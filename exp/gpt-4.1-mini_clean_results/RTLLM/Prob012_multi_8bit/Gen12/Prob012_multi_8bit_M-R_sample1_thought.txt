To refactor the design while preserving the shift-and-add multiplication core idea, I will implement a fully combinational multiplier without using arrays of partial products and a balanced adder tree. Instead, the design will use a simple iterative reduction style expressed with continuous assignments and a loop that accumulates partial sums by shifting and adding the multiplicand based on the bits of the multiplier.

Specifically:
- Use a generate-for block to create partial sums iteratively by checking each bit of B.
- For each bit set in B, add (A shifted by that bit index) to a running sum.
- The additions are done in a cascade via a vector of intermediate sums, with each step adding the shifted A when B[i] is set, or propagating the previous sum otherwise.
- This creates a chain of 8 adders but with a straightforward and easily readable structure.
- This implementation uses only wires and `assign` statements, is fully combinational, and straightforward to synthesize.

This approach differs structurally from the balanced tree by using a linear accumulation of partial sums in a chain, emphasizing simplicity and directness at the cost of slightly longer carry propagation but potentially clearer code for educational or quick synthesis purposes.
