The original design uses a balanced adder tree to sum the partial products generated by shifting the multiplicand. To refactor the code while keeping the core idea, I will implement the multiplier as a fully combinational, bitwise iterative process using a generate-for loop that accumulates partial products using a simple reduction addition.

Instead of precomputing partial products and then summing them in levels, this approach will directly accumulate the shifted multiplicand into a product register, controlled by the multiplier bits, in a single combinational block.

This method preserves the shift-and-add multiplication logic but expresses the summation in a more linear and readable way, using a procedural continuous assignment with a for loop to accumulate the product.

This refactoring emphasizes clarity and compactness without changing functionality or performance much, avoiding multiple intermediate wires and adding signals.

The product is computed by starting from zero and adding (A shifted by i) whenever B[i] is 1, accumulating the final 16-bit product in a combinational always_comb block.
