To improve the PPA of the float_multi module, the main bottleneck is the large 24x24 multiplier in a single cycle, which causes a long critical path and negative WNS.

Improvement strategy:
- Split the multiplication of mantissas into two smaller steps using 12x12 multipliers, combining partial products. This can reduce critical path delay by pipelining or spreading out multiplication work, but adds complexity.
- Alternatively, implement a multi-cycle multiplication (iterative shift-add) for the 24-bit mantissa multiplication, spreading the multiplication over multiple cycles to reduce combinational logic delay in any single cycle.
- Replace the single-cycle full-width multiplication by a sequential multiply using a simple shift-add multiplier controlled by a sub-cycle counter.
- This converts the multiplier to a 5-cycle design:
  * Cycle 0: Extract fields and prepare mantissas.
  * Cycles 1-4: Iteratively perform the 24-bit multiplication.
  * Cycle 5: Normalize, round, and finalize output.

Advantages:
- Significantly reduce the critical path per cycle by removing the 24x24 combinational multiplier.
- Save power by reducing switching in large multipliers.
- Possibly reduce area by using a smaller iterative multiplier block instead of a full combinational multiplier.

Other improvements:
- Remove redundant wide registers by reusing storage for intermediate signals.
- Simplify exponent storage widths by using 10 bits only when needed.
- Use non-blocking assignments consistently in sequential blocks.
- Keep special cases and rounding logic but integrate them in the final cycle.

This approach trades latency (increased from 4 cycles to ~6 cycles) for better timing and power. This tradeoff is often acceptable in floating-point units to meet timing.
