To improve the PPA of the existing 3-stage pipeline float multiplier, the following strategies are applied:

1. **Add an extra pipeline stage to split the long 24x24 mantissa multiplication into a separate stage:**
   - Currently, multiplication occurs entirely in stage 1, increasing critical path delay.
   - By registering inputs before multiplication and outputs immediately after multiplication, we reduce combinational logic per cycle.
   - This yields a 4-stage pipeline:
     - Stage 0: Input capture and special case detection.
     - Stage 1: Mantissa multiplication input register.
     - Stage 2: Mantissa multiplication output register (capturing product), exponent add and sign XOR.
     - Stage 3: Normalization, rounding, special cases, and output.

2. **Simplify special case handling:**
   - Determine special cases only once in stage 0.
   - Pass flags along pipeline to avoid recomputation.
   - Use small bit flags to track NaN, Inf, Zero states efficiently.

3. **Use narrower internal signals for exponent sums:**
   - 10-bit exponent sum is kept, but carefully limited only where needed.
   - Use localparams and smaller-width regs where possible.

4. **Guard rounding logic and sticky bit computation are kept combinational but are pipelined to the last stage.**

5. **Nonblocking assignments used consistently in sequential blocks and all pipeline registers updated every cycle.**

6. **Added reset of pipeline registers on rst for clean startup.**

These changes reduce critical path at each stage and increase max clock frequency. Latency increases by one cycle, acceptable in high throughput designs. Internal signal widths are optimized for area. Special case handling is done once and propagated to reduce repeated logic.

Overall, the 4-stage pipeline approach reduces combinational delays in multiplication and exponent arithmetic and improves timing while preserving functionality and IEEE 754 compliance.
