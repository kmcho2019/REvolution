Refactoring idea:

Instead of using a 3-stage pipeline controlled by a small counter and mixing combinational logic inside the always block, restructure the design into explicit pipeline registers for each stage with separate always blocks for each stage.

Key changes:
- Use separate always blocks triggered by clk and rst to implement stage-to-stage pipeline registers.
- Use continuous assignments (assign) for purely combinational logic that derives signals from registered inputs.
- Clearly separate special case detection as combinational logic before stage 0 registers.
- Use parameterized stage widths for counters to improve readability.
- Replace the counter-based state machine with a simple linear 3-stage pipeline where each stage passes data to the next every clock.
- This structure simplifies the control flow, clarifies timing, and separates combinational from sequential logic more cleanly.

Overall, this refactoring preserves functionality and latency but improves code clarity, ease of modification, and synthesis tool friendliness.

The pipeline stages:
- Stage 0: input capture and special case flags extraction.
- Stage 1: mantissa multiplication, exponent addition, and sign calculation.
- Stage 2: normalization, rounding, overflow/underflow detection, and output generation.

The output valid flag or ready logic is implicit as pipeline always advances each cycle.
