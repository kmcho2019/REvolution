I will implement a synchronous FSM with clearly separated logic for state transitions, counter update, and output signal generation to improve clarity and timing correctness.

The FSM has four states: idle, s1_red, s3_green, and s2_yellow. The idle state initializes the system and immediately transitions to s1_red.

Each traffic light state will have a corresponding fixed duration counter (10 for red, 60 for green, 5 for yellow).

The counter counts down each clock cycle. When it reaches zero, the FSM moves to the next state and loads the corresponding duration.

To handle the pedestrian button (`pass_request`), the logic only applies during the green state (s3_green). If the button is pressed and the remaining green time is greater than 10, the counter is immediately shortened to 10. Otherwise, it remains unchanged.

Outputs (red, yellow, green) are assigned purely combinationally based on the current state to avoid output delays.

The output `clock` represents the current counter value.

Three separate always blocks will be used:
1. State register update (on posedge clk or negedge rst_n).
2. Counter register update (on posedge clk or negedge rst_n).
3. Output assignment (combinational).

This modular approach increases clarity, avoids race conditions, and adheres exactly to the problem's timing and functionality requirements.
