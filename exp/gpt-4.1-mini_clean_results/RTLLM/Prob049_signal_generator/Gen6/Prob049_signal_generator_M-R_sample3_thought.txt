To refactor the triangle wave generator, we can separate the state logic and the wave register update more explicitly using a two-process FSM style: one combinational block to determine the next state and next wave value, and one sequential block to update state and wave registers.

This approach improves clarity by separating combinational next-state and next-wave calculations from sequential updates.

Specifically:
- Define `state` and `wave` as registers.
- Create combinational logic to calculate `next_state` and `next_wave` based on current `state` and `wave`.
- In the synchronous block, update `state` and `wave` on `posedge clk` or reset.
- Maintain the behavior of holding wave at boundaries for one cycle to minimize toggling, consistent with the original approach.

This explicit next-state computation style is a common FSM pattern that improves readability and debuggability, while ensuring the same waveform and timing behavior.
