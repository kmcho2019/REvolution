This alternative asynchronous FIFO design retains the core principles of pointer management with Gray code for safe synchronization, but improves modularity by explicitly dividing the FIFO into five parts per the request: (1) a dual-port RAM submodule for storage, (2) write controller managing write pointer and full detection, (3) read controller managing read pointer and empty detection, (4) a read pointer synchronizer that passes the read pointer into the write clock domain with a two-stage register to avoid metastability, and (5) a write pointer synchronizer that passes the write pointer into the read clock domain similarly.

The pointers (write and read) are each (ADDR_WIDTH+1) bits to represent the FIFO positions and to help full/empty detection logic using Gray codes.

Addressing is done using the lower bits of the binary pointer converted from Gray code.

The full detection condition is carefully implemented as:
- FIFO is full when the next write pointer Gray code matches the read pointer Gray code except the top two bits are inverted and the rest bits are the same.

Empty detection is when both Gray-coded pointers are equal.

The RAM stores data, is clocked asynchronously on write and read clocks, with separate write and read enable signals.

The write controller only increments the write pointer on write request if not full.

The read controller only increments the read pointer on read request if not empty.

Synchronization of pointers crossing clock domains is performed with two-stage flip-flop synchronizers.

This architecture cleanly separates responsibilities, improving readability and facilitating independent debugging and testing of each part.

The solution uses parameterized DEPTH and WIDTH, and calculates ADDR_WIDTH as $clog2(DEPTH).

All modules are in one file for convenience, and the RAM is implemented with inferred dual-port RAM using two separate clocks.
