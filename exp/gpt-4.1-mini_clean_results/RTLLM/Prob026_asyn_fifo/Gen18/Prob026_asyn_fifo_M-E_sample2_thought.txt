I will implement the asynchronous FIFO using classic dual-clock domain design with Gray-coded read and write pointers for safe crossing, but this time synchronizing the Gray-coded pointers directly using two-stage flip-flop synchronizers.

The FIFO depth and width are parameterizable with parameters DEPTH and WIDTH.

The write pointer increments on wclk domain with wrstn asynchronous reset, and read pointer increments on rclk domain with rrstn asynchronous reset.

Gray-coded pointers are used both for addressing (lower bits) and for empty/full detection.

Full condition is detected in write clock domain by comparing the write pointer Gray code with read pointer Gray code synchronized into write domain.

Empty condition is detected in read clock domain by comparing read pointer Gray code with write pointer Gray code synchronized into read domain.

A separate dual-port RAM module instantiated for storage with synchronous write and read enables.

Two-stage synchronizers are used to cross Gray-coded pointers between clock domains, ensuring metastability mitigation.

Write enable is gated by ~wfull and winc; read enable is gated by ~rempty and rinc.

Read data is registered on read clock domain after RAM read enable.

This design uses direct Gray pointer synchronizers, reduces the complexity of pointer synchronization, and conforms well to asynchronous FIFO best practices.

The FIFO address width is $clog2(DEPTH), Gray code pointers are one bit wider for full/empty detection.

Reset signals are asynchronous active low to respective clock domains.

This modular design cleanly separates RAM, pointer logic, synchronization, and control logic, and meets the requirement fully.
