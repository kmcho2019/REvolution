To improve PPA of the original LIFObuffer design while preserving functionality, I will focus on the following optimizations:

1. **Clock Gating at Register Level:**  
   Introduce an internal clock enable signal to minimize unnecessary toggling of SP, stack_mem, and dataOut registers when no valid operation occurs. This reduces dynamic power.

2. **Avoid Variable Indexing in the Same Cycle as SP Update:**  
   The original design uses `stack_mem[SP-1]` indexing immediately after decrementing SP, which can cause timing bottlenecks. To fix this, perform the SP update first, then use the updated SP pointer for the memory access on the next cycle.

   This implies pushing data will occur when SP points to the next free location; so we should store data at `stack_mem[SP-1]` but after SP is updated. To avoid combinational dependency, split the write enable and the address.

3. **Use Separate Read and Write Enables for stack_mem:**  
   This is more hardware-friendly, reduces glitches, and allows easier synthesis of memory inference.

4. **Minimize Reset Workload:**  
   Instead of clearing the entire stack memory on reset, just reset the SP and dataOut. Stack contents are irrelevant when SP = 4 (empty).

5. **Implement Synchronous Reset Only:**  
   Keep reset synchronous to avoid asynchronous glitches.

6. **Use a Separate Pointer Next State Variable:**  
   This clarifies logic and eases static timing analysis.

7. **DataOut Updated Only on Pop:**  
   Hold dataOut stable otherwise to reduce toggling.

8. **EMPTY and FULL as Combinational Signals Derived from SP:**  
   This avoids extra flip-flops.

This approach reduces switching activity, improves timing by removing combinational index calculations dependent on SP in the same cycle, and simplifies reset logic, improving overall power, timing, and area metrics.

Note: These changes introduce a 1-cycle latency between push/pop request and actual update, which is acceptable for this buffer design.
