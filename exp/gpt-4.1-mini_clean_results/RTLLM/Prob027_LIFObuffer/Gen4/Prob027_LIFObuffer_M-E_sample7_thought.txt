Implement the LIFObuffer using a top-down approach with a single always block for both pointer and memory updates to ensure atomic stack operations per clock. The stack pointer (SP) will count the current number of entries (0 to 4), incrementing on push and decrementing on pop, which is the opposite direction of traditional stack pointers but simplifies the empty/full flag logic. On reset, SP is zero (empty), and stack memory is cleared. On a push (RW=0) with space available, the incoming data is stored at the current SP location, and SP increments. On a pop (RW=1) with data available, SP decrements first, then the output data is taken from the decremented SP location. This design avoids negative indexing and ensures the push writes before incrementing SP, while pop decrements SP before reading, making the dataOut always reflect the last pushed item. The EMPTY and FULL flags directly compare SP to zero and maximum capacity, respectively, providing simple combinational logic. This approach ensures simpler control logic, fewer timing dependencies, and a clean synchronous implementation.
