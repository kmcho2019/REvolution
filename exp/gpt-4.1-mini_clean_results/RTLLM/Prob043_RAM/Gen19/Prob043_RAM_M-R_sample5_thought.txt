Refactor the original design by separating the synchronous reset/write operation and the read operation into distinct always blocks for clarity and modularity. 

Instead of a single always block handling both reset and write operations, use one always block for synchronous reset and write to RAM, and a separate always block with combinational logic for read_data, which will latch the read data on read_en.

This approach changes the read data output from purely combinational (direct RAM read) to registered read data, still controlled by read_en. This registers the output, giving stable output data through clocked logic and potentially improving timing.

The memory initialization on reset remains synchronous and initializes RAM contents to zero.

We keep the same parameterization and address width based on DEPTH.

Overall:
- One clocked always block for reset and write RAM.
- One clocked always block to latch read data when read_en is high, clear when low or reset.
- This approach trades zero read latency for stable, registered output which can improve timing and prevent glitches.
