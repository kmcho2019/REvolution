Refactoring Idea:

1. Split the reset and write operations into two always blocks to clarify functionality:
   - Use one always block to handle synchronous reset and write operations on the rising edge of clk.
   - Use a separate asynchronous reset block to initialize read_data to zero to closely follow the original requirement.

2. Use a separate always block for read_data, making it registered rather than combinational. This allows the read output to be stable and synchronous to the clock with an enable signal, as originally specified.

3. Maintain separate read and write address widths based on DEPTH using $clog2 to precisely match addressing.

4. Initialize RAM in the write always block synchronously on reset, as before.

This approach keeps the core synchronous RAM with registered read data, supports simultaneous read/write ports, respects the enable signals, and keeps the design synchronous and clear.
