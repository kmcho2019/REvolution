The original design uses three separate always blocks, each with asynchronous reset and internal counters to toggle the output clocks at the desired division rates. To refactor while keeping the core logic the same but changing the structure, I will unify the counters and outputs into a single always block that manages all counters and toggles clocks accordingly. 

Additionally, instead of toggling the output clocks directly within each always block, I will implement the counters so that the output clocks are derived from the MSB bits of the counters, effectively creating counters that count to the division value and the output clocks are the divided signals (clock divided by 2, 10, 100).

This style uses synchronous reset only and uses counters that count from 0 to max_count-1. The outputs are driven by the MSB of these counters or derived signals toggled when the counter reaches half the count, resulting in frequency division by counting.

This approach reduces code repetition, merges control logic into a single always block, avoids multiple asynchronous resets, and uses synchronous reset consistently for all registers. Also, it avoids manual toggling of output clocks by encoding the output clock states in counters, improving readability and making the code easier to adapt for other division ratios.

The main difference is that output clocks are generated by comparing the counters or using their MSB to naturally produce the toggling output, instead of explicit toggling operations, providing a clean synchronous design.

Overall, this refactoring keeps the functionality, changes the structural approach, and results in a single clocked process with synchronous reset and clean combinational outputs based on counter states.
