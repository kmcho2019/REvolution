The original implementation is clear and correct, but toggling the 50MHz clock on every input clock edge causes the maximum switching activity, which increases dynamic power. To improve power consumption without changing the output frequency or increasing latency, we can generate all clocks from a single synchronous counter that increments on each CLK_in edge. This allows generating all divided clocks in a single always block by checking the count values, minimizing switching toggles and combining logic for better area and timing.

The idea is to use one counter counting from 0 to 99 (for 100MHz input) and toggle outputs accordingly:
- CLK_50 toggles every 1 count (divide by 2): toggle when count reaches 0, 1, 2, etc., i.e., every 1 clock cycle toggling still, but we can derive it from counter bits instead.
- CLK_50 can be derived from counter bit [0], which naturally toggles at half input clock frequency.
- CLK_10 toggles every 5 counts (divide by 10), i.e., toggle output at count 4, 9, 14...
- CLK_1 toggles every 50 counts (divide by 100), i.e., toggle output at count 49, 99.

By implementing a 7-bit counter counting 0 to 99 with synchronous reset, we can generate CLK_1 and CLK_10 by comparing the counter values. CLK_50 can be generated directly from the least significant bit of the counter (count[0]) since it toggles every clock.

This approach reduces switching flip-flops for CLK_50 from a dedicated toggling FF to a direct combinational assignment from the counter bit, improving timing and power. Also, this unifies logic into a single always block, reduces total flip-flop count (no separate toggle flip-flops for CLK_50), and simplifies the design.

Summary of improvements:
- Use a single 7-bit counter counting 0 to 99.
- Generate CLK_50 directly from counter bit 0 (divide by 2).
- Generate CLK_10 and CLK_1 by toggling outputs at specified count values.
- Single always block for synchronous logic with asynchronous reset.
- Reduced FF count and switching for CLK_50 output.
- Clear, maintainable code.

This improves power (less toggling FFs), area (fewer FFs), and can improve timing due to simpler logic paths.

Note: CLK_50 output is driven combinationally from count[0], but to meet output register requirements, it's registered to avoid glitches and ensure timing closure.
