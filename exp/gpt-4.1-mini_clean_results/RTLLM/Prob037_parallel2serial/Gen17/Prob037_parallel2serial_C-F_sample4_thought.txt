To combine the strengths of both examples, we use an internal 4-bit register `data` to hold the parallel input, which aligns with the problem statement's requirement of updating and shifting an internal register. This avoids directly depending on the input `d` during serialization, reducing glitches and timing issues.

Instead of rotating (Example 2) or indexing input bits combinationally (Example 1), we will shift `data` left by 1 bit on each cycle with zero fill (shift-in zero), so bits shift from MSB to LSB correctly. This simplifies the shift logic and reduces toggling compared to a rotate.

We use a 2-bit counter `cnt` to track the bit position from 0 to 3, incrementing every cycle. When `cnt == 3`, we load new parallel data into `data`, output the MSB, set `valid_out` to 1, and reset the counter. On other cycles, we shift left, output the MSB, increment the counter, and deassert `valid_out`.

Registering input `d` at the load cycle ensures stable data during serialization, improving timing and power by decoupling `d` from `dout` during serialization.

`valid_out` is asserted only on the cycle when new data is loaded (when cnt == 3). The output `dout` is always the MSB of `data`, which shifts left every cycle to output bits MSB first.

This design respects the problem description, is robust against glitches, reduces switching activity compared to rotation, and uses a registered data path for better timing and power.

Additionally, reset is active-low as specified, synchronous operations on `clk` with asynchronous reset on `rst_n`.

Summary:
- 4-bit `data` register to hold input data on cnt == 3
- 2-bit counter `cnt` increments each cycle; reset to zero when cnt == 3
- On cnt == 3: load new `d` into `data`, assert `valid_out`
- Else: shift `data` left by 1 bit with zero fill, deassert `valid_out`
- `dout` outputs MSB of `data` each cycle
- Asynchronous active-low reset
