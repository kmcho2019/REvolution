I will implement the frequency divider using a synchronous process with a counter that increments every clock cycle. Instead of toggling `clk_div` inside the always block based on the counter reaching half the division count, I will use the counter to produce a pulse signal when it reaches half the count, and then use a D flip-flop driven by this pulse to toggle `clk_div`. This separates the toggle logic from the counting logic.

Specifically:
- On reset, initialize counter and clk_div to zero.
- Counter increments from 0 to NUM_DIV-1 and then resets.
- When counter reaches NUM_DIV/2 - 1, a toggle enable pulse is generated.
- On the next clock cycle with toggle enable asserted, `clk_div` toggles.
  
This structure makes the code clear and synthesizable. It also avoids multiple toggles per period and uses registered signals to create a clean frequency division.

The counter width is derived from NUM_DIV using $clog2 to accommodate different division values, ensuring a 4-bit minimum if needed.

The module name remains `freq_diveven` as specified.
