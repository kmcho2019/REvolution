To create a stable fractional frequency divider by 3.5 using double-edge clocking without asynchronous domain issues, I propose using a single synchronous counter running at the input clock's rising edge to track the division cycle (7 counts total for 3.5 division as 7/2). 

We generate two non-overlapping pulses representing the divided clock phases within each 7-cycle period:
- One pulse lasts 4 cycles (high),
- The other lasts 3 cycles (high),
alternating each half clock cycle.

Instead of directly using negedge clock domain registers (which can cause asynchronous issues), we generate two signals (clk_intA and clk_intB) in the posedge domain but stagger their updates in time to represent a 0° and 180° phase offset by sampling or delaying one by half clock period (using a flip-flop triggered on negedge clk to create the phase-shifted version).

Specifically:
- Use a single posedge clock counter (0-6).
- Create clk_intA according to counter (high for counts 0..3, low otherwise).
- Create clk_intB similarly (high for counts 0..2, low otherwise).
- To phase shift clk_intB by half clock, we register clk_intB on negedge clk (delayed half clock).
- This negedge registered clk_intB forms the phase-shifted pulse.
- Finally, OR clk_intA and phase-shifted clk_intB to produce the final clk_div signal.

This approach:
- Keeps all counters and pulse generation synchronized in one clock domain,
- Creates a well-defined half clock phase shift via negedge sampling,
- Avoids asynchronous counters running independently,
- Produces a fractional clock with 7 input cycles per output period,
- Alternates pulse widths of 3 and 4 cycles effectively to achieve 3.5 division,
- Improves duty cycle and smoothness due to combining pulses offset by half a clock period.

Reset synchronously initializes all registers.

This design avoids asynchronous counter drift and glitches by centralizing the counter and only phase-shifting the pulse signal via a simple negedge register. The OR-ed output clk_div is glitch-free and stable.
