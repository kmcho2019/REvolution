I will refactor the pulse detection logic to use a simple finite state machine (FSM) with three states: IDLE, HIGH, and LOW_WAIT. The FSM progresses as follows: starting at IDLE when data_in=0, upon detecting a rising edge (data_in=1), it moves to HIGH state, and then waits for data_in to go back to 0 in LOW_WAIT state. When it detects the falling edge completing the 0->1->0 pattern, it asserts data_out for one cycle and returns to IDLE. This FSM explicitly tracks pulse detection states instead of edge flags, and uses a state register with enumerated states, which helps clarity and debuggability. data_in history is kept as a registered signal for edge detection. data_out is asserted synchronously at the last cycle of the pulse, as requested.
