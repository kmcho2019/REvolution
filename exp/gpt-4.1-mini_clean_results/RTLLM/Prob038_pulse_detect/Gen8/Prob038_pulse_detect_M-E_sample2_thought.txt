Instead of using a shift register and pattern matching, I will implement a simple finite state machine (FSM) to detect the "0 -> 1 -> 0" pulse pattern explicitly. The FSM will have four states:

- IDLE: Waiting for data_in to be 0.
- WAIT_ONE: Detected 0, waiting for data_in to become 1.
- WAIT_ZERO: Detected 1 after 0, waiting for data_in to return to 0.
- PULSE_DETECTED: Pulse completed, assert data_out for one cycle, then return to IDLE.

This approach provides clearer state transitions, explicitly encoding the pulse sequence and generating a one-cycle pulse at the end of detection. It also simplifies debugging and scalability for detecting more complex patterns if needed.

The design uses synchronous reset and clocked state transitions with non-blocking assignments. The output is asserted only in the PULSE_DETECTED state, and then the FSM resets for the next pulse detection.
