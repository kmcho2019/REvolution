Use a simple two-stage approach: 
1) On each valid input, latch the 8-bit data into a register called `data_lock`. Use a flag to track whether this is the first or second byte. Initially, the flag is 0 (expecting the first byte).
2) When the first byte arrives (valid_in=1 and flag=0), store it in `data_lock` and set the flag=1.
3) When the second byte arrives (valid_in=1 and flag=1), capture this second byte into another register `second_byte`, clear the flag back to 0, and set a "valid output pending" signal.
4) Then, in a separate clock cycle (the next posedge clk), if "valid output pending" is set, combine the stored first byte (`data_lock`) as upper 8 bits and the current second byte (`second_byte`) as lower 8 bits to form the 16-bit output. At the same time, assert valid_out for one cycle.
5) Clear "valid output pending" after asserting valid_out once.
6) Use synchronous reset to clear all registers.

This architecture avoids complex FSM by using a simple flag and an output-valid pipeline register, ensuring that valid_out and data_out are generated exactly one clock cycle after receiving the second valid input.

This also ensures that when only one input arrives, output waits until the next input arrives to form valid data_out and valid_out signals.

Note: The output data and valid signal generation is explicitly delayed by one clock cycle relative to the second data input arrival, matching the requirement exactly.
