To meet the specification that `valid_out` and `data_out` appear exactly one clock cycle *after* receiving the second valid input, the design needs an explicit two-cycle pipeline for the output data and valid signal:

- On the rising edge of the clock:
  - When the first valid_in arrives, latch and store it (data_lock).
  - When the second valid_in arrives, concatenate stored data_lock and current data_in to form 16-bit data, but do not output immediately.
  - Instead, register this 16-bit concatenation and set a delayed valid flag (`valid_out_reg`) that will be output in the next clock cycle.

- Use separate registers to hold the final output data and valid signals that update on the clock cycle *after* the concatenation happens.

- This means we have:
  1. `data_lock` - storing the first byte.
  2. `data_concat` and `valid_concat` - set during the clock cycle when the second byte arrives.
  3. `data_out` and `valid_out` - registered outputs updated one cycle later from `data_concat` and `valid_concat`.

- Also, implement a simple FSM with two states: IDLE (waiting for first byte), GOT_FIRST (stored first byte).

- This structure guarantees that after two valid inputs, output valid_out and data_out occur exactly one cycle later, meeting timing requirements.

- On reset, all registers are cleared.

- The pipeline avoids combinational feedback and keeps outputs stable and aligned with the specification.
