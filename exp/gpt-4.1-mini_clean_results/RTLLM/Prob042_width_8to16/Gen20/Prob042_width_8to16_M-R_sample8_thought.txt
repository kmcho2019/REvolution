Refactor to clearly separate input data capture, internal storage, and output generation over multiple clock cycles.

Use a simple two-state FSM with a flag to remember if the first byte has arrived:

- When `valid_in` arrives and flag=0: latch first byte into `data_lock`, clear output registers, set flag=1, no output yet.
- When `valid_in` arrives and flag=1: latch second byte, concatenate `{data_lock, data_in}` into `data_out` and assert `valid_out` in the current clock cycle, then clear flag=0.

This ensures `valid_out` and `data_out` update *one clock cycle after* the second input is received, satisfying timing requirements.

Use non-blocking assignments properly, separating input capture and output register updates in a single synchronous always block, without mixing "next" registers updated in the same cycle.

On reset, clear all registers to known states.

This design is clean, easy to understand, and avoids the previous pitfalls.
