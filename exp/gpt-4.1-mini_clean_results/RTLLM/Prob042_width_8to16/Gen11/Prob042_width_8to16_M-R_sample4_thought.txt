Refactor the design by implementing a small finite state machine (FSM) with three states: IDLE, WAIT_SECOND, and OUTPUT.

- IDLE state: Wait for the first valid input. When valid_in=1, store it in `data_lock` and go to WAIT_SECOND.
- WAIT_SECOND state: Wait for the second valid input. When valid_in=1, store it in `data_in_reg` and prepare output in next cycle by moving to OUTPUT.
- OUTPUT state: Assert valid_out and output `{data_lock, data_in_reg}`. Then return to IDLE.

This FSM cleanly separates input capturing and output assertion across clock cycles, explicitly controlling valid_out timing.

Use synchronous logic for state transitions and data registers, and combinational logic for next state.

This approach improves timing clarity, guarantees that output is asserted only in the cycle after the second valid input arrives, and satisfies all problem requirements, including reset behavior and data concatenation order (first input in upper 8 bits).

Additionally, de-assert valid_out in all cycles except OUTPUT to avoid glitches.
