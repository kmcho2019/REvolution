Implement a multiplying accumulator using a fully pipelined architecture with two stages: multiplication stage and accumulation stage.  

1. Stage 1: On each clock, input operands `a` and `b` are registered and multiplied in a combinational manner (using the product of the registered inputs). The product is stored in a pipeline register to decouple the multiplier latency from the accumulator.

2. Stage 2: The multiplication result from the previous cycle is added to the accumulator register. This pipeline staging shortens the critical path by separating the multiplier and adder operations, allowing potentially higher clock frequencies.

3. Reset (`rst`) is synchronous and clears both the pipeline register holding the multiplication result and the accumulator register.

4. The output `c` is directly driven by the accumulator register.

5. Accumulator is 64 bits internally to avoid overflow, but output is truncated to 32 bits since the problem specifies 32-bit output. This design choice assumes overflow wrap-around is acceptable here, contrasting with saturating accumulation.

6. Using pipeline registers improves timing performance at the cost of a one-cycle latency in output.

This architecture improves timing by pipelining multiplier and adder stages, simplifying the critical path, but does not implement saturation or overflow detection. This suits scenarios where wrap-around behavior is acceptable or accumulation width can be extended in future versions.
