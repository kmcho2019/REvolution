Fuse the hierarchical addition pipeline and well-structured enable tracking from Example 1 with the simplified input capturing and clean reset logic from Example 2.

Fusion Strategy:
- Use a 4-stage pipeline:
  Stage 0: Register inputs and input enable when mul_en_in asserted.
  Stage 1-3: Perform partial sums in pipeline registers to reduce combinational delay.
- Track mul_en_in through a 4-bit shift register mul_en_pipe to control register enables and output enable.
- Generate partial products combinationally from registered inputs (mul_a_reg, mul_b_reg).
- Group partial products into smaller, balanced sets for addition:
    - Stage 1 sums partial_products[0..2]
    - Stage 2 sums partial_products[3..5]
    - Stage 3 sums partial_products[6..7]
- Final pipeline stage sums results from stages 1-3 to produce mul_out_reg.
- Registers update only if corresponding enable bits in mul_en_pipe are active, minimizing switching.
- Use non-blocking assignments and synchronous active-low reset.
- Output is valid only when mul_en_pipe MSB is set; otherwise output zero.
- This approach balances performance (multi-cycle pipeline), reduces critical path by splitting the addition tree, and power by gating register updates.
- Input capture and enable logic simplified and robust as in Example 2.
- Partial product generation uses shift operation conditional on multiplier bit as in both examples.
- The output enable and output product signals are registered and synchronized with data validity.
