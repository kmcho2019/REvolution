Fuse the two example designs to achieve a balanced and efficient 3-stage pipeline:

1. Input Stage: Register `mul_a`, `mul_b`, and `mul_en_in` (enabling updates only when `mul_en_in` is high) to reduce switching and ensure synchronous input capture.

2. Partial Product Generation Stage: Generate the 8 partial products combinationally from the registered inputs and multiplier bits.

3. Multi-Stage Pipelined Summation Stage: Instead of summing all partial products in a single combinational step (which hurts timing), split the summation into two pipeline stages to shorten the critical path and improve max clock frequency.

- Stage 2 Pipeline Register: Sum partial products pairwise into 4 sums and register them along with the enable signal propagated through a 3-bit shift register.
- Stage 3 Pipeline Register: Sum the 4 sums into the final product and register it.

4. Output Stage: Drive the output enable and product from the last pipeline stage registers. If output enable is low, output zero.

Advantages of this fusion:

- Improved timing by pipelining the addition tree.
- Reduced power by registering inputs only when enabled and staging the summation to spread switching activity.
- Clear enable signal propagation in a 4-stage shift register (including input capture) matching pipeline stages.
- Final product registered, synchronous reset handled properly.
- Avoids a single large combinational adder to reduce area and improve frequency.
- Maintains clean code style and explicit pipeline stage registers.

This design offers a good tradeoff among pipeline depth (latency = 4 cycles), throughput (one result per cycle after pipeline fill), performance, power, and area.
