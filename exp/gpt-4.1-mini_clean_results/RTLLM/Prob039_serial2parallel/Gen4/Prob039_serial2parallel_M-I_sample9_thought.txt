The original design is mostly correct but has a key issue related to when and how the parallel output is assigned. The shift register update and counter increment happen in the same clock cycle, and trying to assign `dout_parallel` as `{din_serial, shift_reg[7:1]}` duplicates the shift operation rather than using the fully updated `shift_reg`. Because of this, `dout_parallel` does not reflect the correct assembled data, and consequently `dout_valid` never asserts properly.

To fix this:

1. Shift `din_serial` into `shift_reg` on each valid input by shifting left or right so that the first bit received is at MSB (bit 7). The original code shifts to the right with new bit entering MSB, which is valid.

2. Use the counter `cnt` to count from 0 to 7 bits received.

3. When `cnt` is 7 (meaning the 8th bit has just been shifted in), assign the already updated `shift_reg` directly to `dout_parallel` and assert `dout_valid` for exactly one clock cycle.

4. Reset `cnt` after outputting parallel data.

5. Clear `dout_valid` on every other clock cycle.

6. Make sure all registers including `shift_reg`, `cnt`, `dout_parallel`, and `dout_valid` are reset synchronously and asynchronously on `rst_n`.

This avoids reconstructing shifted data and ensures valid is asserted exactly once after 8 bits are received. This also guarantees no indefinite wait or timeout in simulation.

For slight optimization:

- We keep synchronous reset for registers except the asynchronous reset for `rst_n` per spec.

- Use a minimal 4-bit counter.

- Maintain a simple shift register.

This design is clean, easily synthesized, and meets all requirements.
