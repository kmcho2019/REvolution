Instead of using an initial block with a forever loop, implement the clock generator using an always block triggered by a delay using a nonblocking assignment inside an infinite procedural loop. To do this cleanly and uniquely, use an always block with a `#(PERIOD/2)` delay inside a while(1) loop (in simulation) or use an always block sensitive to no event but with a delay statement in the body.

Additionally, add a reset input to asynchronously initialize the clock to 0. This allows more control and deterministic start behavior. The clock toggles on each half period when not in reset. This architecture aligns with conventional RTL design for clock toggling in simulation and testbench, while still simple and elegant. It also improves determinism and can be synthesized in FPGA tools that support delays (though typically for simulation).

Hence, the main novelty:
- Use an input reset signal for initialization.
- Use an always block with a procedural loop and delay.
- Use nonblocking assignments for `clk` to better model sequential logic.

This structure is distinct from the example's single initial block forever loop.
