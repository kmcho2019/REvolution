Instead of using an always block with delay to toggle the clock, implement the clock generation using a cycle counter inside an always block triggered by an internal 1-time-unit period timer.

The idea is to create an internal counter that increments every 1 time unit. When the counter reaches half the PERIOD, toggle the clock and reset the counter.

This removes reliance on delays (#) in always blocks and replaces it with event-driven clock generation using an internal time base.

Advantages:
- Event-driven simulation with no # delays inside always.
- More precise and easy to modify.
- Clear logic for toggling the clock every half-period.

This method is suitable for simulation, keeps the initial clk=0, and matches the desired PERIOD parameter.
