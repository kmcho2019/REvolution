Use a handshake-style synchronizer where data and enable are latched in clk_a domain only when data_en is high, capturing stable data. Then, the data and a pulse generated by data_en's rising edge are synchronized into clk_b domain using two separate two-stage synchronizers. In clk_b domain, when the synchronized pulse asserts (indicating new valid data), the output data register updates with the synchronized data. This approach uses pulse synchronization to indicate new data availability, avoiding direct enable signal synchronization and reducing glitches or metastability risks on enables. It leverages double flip-flop synchronizers for both data validity pulse and data path, and updates output only on new data valid pulse, ensuring stable transfer despite clock domain crossing.
