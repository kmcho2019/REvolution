Refactoring the design to maintain the borrow lookahead subtraction approach, I will implement the comparator logic using vectorized operations and a generate loop for borrow signals to make the code more scalable and compact. Instead of manually writing generate and propagate signals for each bit, I will compute them using vector operations and use a simple combinational always block to calculate borrow chain in a loop. This improves code readability, scalability to wider bit widths, and makes the logic more explicit.

Equality will be computed using a reduction XNOR to check bitwise equality compactly. The borrow chain will be stored in a vector, where borrow[0] is borrow-in (0), and each subsequent borrow[i+1] depends on generate and propagate of bit i and borrow[i]. The final borrow out borrow[4] indicates if A < B.

Outputs are mutually exclusive:
- A_less = borrow out
- A_equal = all bits equal
- A_greater = neither less nor equal

This refactoring does not change the logic but structures it clearly with a for loop and vector signals, making it easier to scale and modify if needed.
