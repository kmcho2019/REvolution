Implement an 8-bit Radix-4 Booth multiplier that follows the user's described style but with a different architectural approach:

- Use two 16-bit registers: multiplicand and multiplier, both sign-extended from 8-bit inputs.
- Use a 17-bit product register initialized to zero.
- Use a 5-bit counter `ctr` counting from 0 to 15 (16 cycles total).
- At reset: multiplicand <= sign-extended a, multiplier <= sign-extended b, product <= 0, ctr <= 0, rdy <= 0.
- On each cycle when ctr < 16:
  - Check the multiplier bit at position ctr.
  - If multiplier[ctr] == 1, add multiplicand shifted left by ctr to product.
  - Shift multiplicand left by 1 for the next cycle.
  - Increment ctr.
- When ctr == 16, set rdy=1 and output the lower 16 bits of product.
  
This is a traditional, simple shift-and-add multiplier controlled by a counter and direct bit inspection of the multiplier. The difference from typical radix-4 Booth multipliers is that here we're interpreting the multiplier bits as a normal multiplication, but since the user requested Radix-4 Booth, we need to adapt this logic for Radix-4:

For Radix-4 Booth:
- Process two bits of the multiplier per cycle (ctr increments by 2).
- Use a 3-bit window (the two bits plus the previous LSB bit) to decide the multiplicand multiple to add/subtract.
- To keep it simple and different from Example 1, the multiplier is left-shifted each cycle (rather than right-shifted), and multiplicand stays fixed.
- The product register accumulates partial sums.
- When 8 cycles complete (processing 16 bits as 8 groups of 2 bits), multiplication completes.
- The ready signal is set high.
  
Implement a small FSM with states IDLE, RUN, DONE.

Inputs a and b are loaded on reset; multiplication starts immediately after reset.
This approach is more state-machine oriented, uses left shifts for the multiplier, and precomputes the Booth multiples combinationally.

The idea is to make the control explicit and implement the multiplier processing 2 bits per cycle in Radix-4 style with a recoding window of 3 bits (2 current multiplier bits + previous bit).

This new architecture contrasts with the shifting multiplier-right approach and the variable shift approach of the example, offering a fresh perspective.
