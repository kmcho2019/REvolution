The original design is clean and minimal, directly implementing the required functionality. To optimize power and potentially area without changing functional behavior:

1. Introduce an enable signal internally, derived from the up_down input, so the counter only updates when counting is needed. This reduces unnecessary toggling on the output register if the input direction doesn't change (though here counting happens every cycle, so actual gating would require an external enable).

2. Synchronize the up_down signal internally (using a flip-flop) to avoid glitches causing extra toggling, which can reduce power.

3. Use an intermediate signal for next count calculation outside the clocked block to separate combinational and sequential logic clearly, potentially aiding synthesis tools in optimizing.

4. Keep the same synchronous reset.

5. Although these changes add a slight overhead, they help in reducing switching noise and may improve PPA with modern tools.

Because no enable signal is specified, we'll treat up_down as stable but synchronize it for glitch prevention.

This approach keeps the arithmetic the same but improves signal integrity and power efficiency with minimal area impact.
