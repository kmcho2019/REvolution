To refactor the design while preserving functionality, I will separate the next-state logic into a combinational always block and then update the register synchronously in a separate always block. 

This two-block structure explicitly distinguishes between the combinational calculation of the next count value and the synchronous state update, improving code readability and maintainability. It also aligns with common RTL style guidelines.

The next state is computed based on the current count and the up_down signal, using the ternary operator. The count register updates on the positive clock edge and resets synchronously.

This approach achieves the same functionality with a slightly different coding style, making the design intent clearer without changing behavior or synthesis results.
