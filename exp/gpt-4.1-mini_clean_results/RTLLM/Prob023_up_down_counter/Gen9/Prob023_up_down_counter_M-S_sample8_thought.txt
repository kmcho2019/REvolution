To simplify the design while maintaining the exact functionality, I will combine the next-state computation and the register update into a single always block triggered on the rising edge of clk.

Inside the clocked process, if reset is asserted, the count resets to zero synchronously. Otherwise, the count increments by 1 if up_down is high, or decrements by 1 if low.

This approach eliminates the separate combinational block, reducing code complexity and slightly improving performance by removing an additional combinational logic stage, without changing the behavior or synthesis results.

The count wraps naturally due to 16-bit arithmetic. The code remains clean, clear, and meets the specifications.
