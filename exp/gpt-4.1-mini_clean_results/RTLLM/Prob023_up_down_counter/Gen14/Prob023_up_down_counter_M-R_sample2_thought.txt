To refactor the up_down_counter while preserving its functionality, I will separate the combinational next-count logic from the sequential register update. Specifically, I will create a combinational logic block (using an always @(*) block) that computes the next counter value based on the current count and the up_down signal. Then, a separate sequential always block (triggered on the clock) will update the counter with this next value or reset it to zero.

This approach enhances code modularity and clarity by isolating combinational logic from sequential state update. It also facilitates easier modifications such as adding enable or saturation features later if desired.

The counter will still naturally wrap around due to 16-bit arithmetic, and the synchronous reset is retained.
