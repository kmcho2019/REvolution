To refactor the design while keeping the same functionality, I will separate the next-state logic into a combinational always block that calculates the next count value based on the current count, reset, and up_down signals. Then, a synchronous always block will update the count register on the clock's rising edge.

This approach clearly distinguishes combinational logic (next state calculation) from sequential logic (state update), improving code readability and making it more suitable for formal verification and certain synthesis tools.

The count will still wrap naturally due to 16-bit arithmetic, and reset will still synchronously initialize the count to zero.
