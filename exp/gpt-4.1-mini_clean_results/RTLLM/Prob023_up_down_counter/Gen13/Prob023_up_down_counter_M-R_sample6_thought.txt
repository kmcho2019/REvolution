To refactor the code while keeping the core functionality intact, I will separate the next-state logic from the sequential logic by introducing a combinational always block to compute the next counter value, and a sequential always block to register the state on the clock edge.

This approach clarifies the design by explicitly showing the next state calculation, which can be beneficial for readability and further extension.

The synchronous reset remains, and the count increments or decrements based on the `up_down` control in the combinational block. The register updates on the rising edge of `clk` accordingly.

This structure also better supports formal verification and easier debugging by making the state transition explicit.
