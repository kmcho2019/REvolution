Instead of using clock gating or a straightforward enable inside the always block, I will implement a Gray code counter that increments only when valid_count is high and wraps from 11 back to 0. Gray code counters reduce switching activity because only one bit changes per increment, which can lead to power savings. Since the output needs to be in binary, I will maintain an internal 4-bit binary counter and generate the Gray code internally for the state transition but output the binary value. The counter increments on each clock cycle when valid_count is asserted. When the count reaches 11, it wraps back to zero. The reset is asynchronous active-low and clears the count to zero. This architecture offers a trade-off: it keeps the binary output as required, reduces switching activity internally for power efficiency, and simplifies the enable logic by using an always block triggered by clk and rst_n, with valid_count controlling increment.
