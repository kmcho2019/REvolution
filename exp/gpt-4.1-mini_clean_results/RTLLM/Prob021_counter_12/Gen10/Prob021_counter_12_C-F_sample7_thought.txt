This retains power benefits by preventing unnecessary counter toggling, while avoiding the pitfalls of gated clocks.

Furthermore, I will use a parameter for the maximum count (11) to improve code scalability and readability. The counter will reset asynchronously when rst_n is low, count only when valid_count is high, and wrap around on reaching the max count. When valid_count is low, the counter value remains stable without redundant register writes, allowing synthesis tools to optimize power.
