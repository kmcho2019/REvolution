Refactor the counter to use a combinational next_state logic separated from the sequential register update. This modularizes the design by clearly defining next value computations outside the always block. The always block then only performs state updating on the clock edge, which improves code readability and makes it easier to analyze and modify next state logic independently. We also use a direct bitwise condition for terminal count detection (out == 11) to optimize critical path delay. The reset remains synchronous and active-low. The counter increments only when valid_count is high; otherwise, it holds its value.
