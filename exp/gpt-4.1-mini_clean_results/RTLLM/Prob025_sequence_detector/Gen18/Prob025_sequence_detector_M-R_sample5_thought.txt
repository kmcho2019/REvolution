To refactor the sequence detector, I will implement a Moore FSM with separate combinational logic for the next state and output signals, using an enumerated type for better readability. The output sequence_detected will be driven combinationally based on the current state only (asserted when in the detection-complete state), removing the need to consider the input in the output logic. This change clarifies the separation of concerns between state transitions and output signals.

Additionally, I will implement asynchronous active-low reset to demonstrate an alternative reset scheme and use blocking assignments in the combinational always block for next state logic as per common FSM style, keeping the sequential state update with non-blocking assignments.

This approach improves readability and modularity while maintaining the same detection functionality for the sequence "1001".
