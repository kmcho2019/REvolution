I will implement the sequence detector using a Moore finite state machine with binary encoded states to minimize the number of flip-flops. The FSM will track the progress of detecting the sequence "1001" by defining states that represent how many bits of the sequence have been matched so far.

To handle overlapping sequences, the state transitions after detecting a '1' will consider the potential start of a new sequence.

The reset signal will be asynchronous and active low (`reset_n`), as specified. This allows immediate reset of the state machine without waiting for a clock edge, which is often desirable for synchronous designs dealing with asynchronous reset signals.

The output `sequence_detected` will be registered (i.e., asserted on the clock cycle after the full sequence is detected), making it a Moore output based solely on the current state.

This approach is efficient in flip-flop usage and timing, uses binary state encoding, supports overlapping sequences, and respects the interface requirements exactly.
