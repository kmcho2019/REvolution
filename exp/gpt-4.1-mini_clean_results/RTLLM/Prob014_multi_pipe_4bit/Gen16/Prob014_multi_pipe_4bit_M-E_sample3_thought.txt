Implement a 4-bit unsigned multiplier using a two-stage pipeline with these key architectural differences:

1. **Partial product generation:**  
   Instead of generating all partial products at once, generate them bit-by-bit using a serial approach over two pipeline stages.

2. **Two-level pipeline:**  
   - **Stage 1:** For each clock cycle, compute partial product for one bit of multiplier `mul_b`.  
     Store intermediate sum in registers after adding shifted multiplicand (if multiplier bit is 1).  
   - **Stage 2:** After all bits are processed (tracked by a counter), output the final accumulated product.

3. **Control flow:**  
   Use a counter to select multiplier bits sequentially and shift/add multiplicand accordingly.  
   This approach makes the pipeline more control-driven but still has two levels of registers: one for partial sum accumulation and one for output register.

4. **Zero extension:**  
   Zero-extend multiplicand as required and shift it according to the current bit index.

5. **Reset behavior:**  
   Reset counter and accumulators to zero asynchronously when `rst_n` is low.

6. **Benefits:**  
   - Registers store intermediate sums for each partial product addition stage.  
   - Two pipeline registers: one for accumulation after each partial product addition, second for final registered output.  
   - Lower combinational logic per stage, potentially higher clock frequency.  
   - Efficient resource usage as multiplication is done bit-by-bit with add-shift steps pipelined over clock cycles.

This design uses a single accumulator to store partial sums and a counter to track progress, fitting the two-stage pipeline requirement with control logic managing flow instead of generating all partial products simultaneously.
