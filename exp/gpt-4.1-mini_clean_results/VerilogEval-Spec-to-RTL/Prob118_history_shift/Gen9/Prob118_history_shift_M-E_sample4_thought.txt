Instead of a single 32-bit shift register updated on each valid prediction or rollback, maintain the global history in a register plus an explicit 32-bit "pending" bit mask and a counter to track how many valid predictions have been made since last rollback. On predict_valid, shift the "pending" bits left and insert the new prediction bit, but do not immediately update the history register. On misprediction rollback, discard the pending bits and restore the history directly from train_history plus train_taken. This design separates the committed history from speculative history, allowing to "commit" the speculative history on the next non-flush cycle if needed (not required here, but design is extensible). For this problem, on misprediction rollback, we restore history, otherwise on prediction, we update speculative history in the pending bits. Finally, on each cycle, predict_history outputs the committed history concatenated with the reversed speculative bits. This approach explicitly tracks speculative bits, simplifies rollback, and can ease future pipeline extensions.

However, as the problem doesn't require speculative commits beyond the current stage, we will simplify and update the committed history register on every clock, but keep speculative bits in a separate register. When a misprediction occurs, we load the history from train_history + train_taken and clear pending bits.

To comply exactly with the problem requirements (predict_history shows the committed state), we always output the committed history register value.

Since output is the committed history, we only update committed history on misprediction rollback or on prediction, by shifting in the relevant bit. So we maintain a single 32-bit register with the logic inverted: on prediction, shift in predict_taken; on rollback, load train_history + train_taken, with rollback having priority.

This approach uses a synchronous load on misprediction, and shift on predict_valid, no async reset on the register directly but using async reset on the flip-flops.

The novelty is to implement the shift register as a parallel load register with an explicit load signal on misprediction, and a shift enable on prediction, rather than conditional combinational logic.

This can allow for more efficient hardware by separating load and shift enables.
