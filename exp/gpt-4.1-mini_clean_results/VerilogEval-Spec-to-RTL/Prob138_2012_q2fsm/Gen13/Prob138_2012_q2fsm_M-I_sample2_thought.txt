To improve the PPA metrics, I will use one-hot state encoding to reduce the complexity of next-state logic and potentially improve timing and power by limiting the switching activity in state bits. The output z is only asserted in states E and F, so one-hot encoding will make the output logic simpler (just OR of those state bits). I'll keep the synchronous active-high reset and use separate always blocks for state registers and next-state logic as required. The one-hot encoding leads to a 6-bit state register instead of 3 bits, increasing area slightly but often improving timing and power due to simpler decoding and logic. This trade-off is beneficial for timing-sensitive designs. The next-state logic will be implemented with a combinational always block using case(1'b1) pattern to select state bits, improving readability in one-hot FSMs.
