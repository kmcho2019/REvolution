Instead of using separate registers for each BCD digit and nested carry logic, I will implement the 4-digit BCD counter as a single 16-bit register representing all digits packed together. Each clock cycle, the counter attempts to add 1 to the ones digit with proper BCD correction.

The increment process will work as follows:
- Add 1 to the ones digit.
- After adding, check if the digit exceeds 9 (i.e., BCD invalid). If so, add 6 to correct it and generate a carry to increment the next digit.
- Repeat this correction for each digit in a sequential combinational process before updating the register on the clock edge.

The ena signals will be generated combinationally, based on whether the carry into each upper digit is active, reflecting that those digits need incrementing.

This "BCD ripple add and correct" approach eliminates nested if-else blocks and enables a more uniform, combinational BCD increment logic before updating the register. It also ensures the carry chain and enables are directly visible from the intermediate carry signals in combinational logic.

The synchronous reset clears the entire 16-bit counter.

This design potentially improves timing since the combinational carry and correction for all digits occur in parallel before register update, and the ena signals naturally derive from these carry signals.
