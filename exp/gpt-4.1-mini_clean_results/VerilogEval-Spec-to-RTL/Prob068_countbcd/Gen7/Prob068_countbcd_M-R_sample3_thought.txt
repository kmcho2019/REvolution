I will refactor the BCD counter by separating the combinational carry detection and the next state calculation from the sequential register update. This means I will create combinational logic to compute the next BCD value based on the current value and carry propagation, then store the next state in a register at the clock edge.

Instead of using nested if-else inside a clocked block, the carry generation and digit increment will be done combinationally with simple if conditions and assigned to next state signals. This approach makes the logic cleaner and may help synthesis tools optimize the combinational paths better.

Enable signals will be generated similarly, based on the current digits to indicate when the next digit should increment.

The synchronous reset will still clear all digits to zero.

This approach cleanly separates combinational next-state logic from sequential updates, improving readability and potentially timing.
