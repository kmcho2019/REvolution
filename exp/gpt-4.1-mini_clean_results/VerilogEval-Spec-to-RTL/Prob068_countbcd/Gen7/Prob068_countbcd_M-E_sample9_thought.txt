Instead of using separate 4-bit registers for each digit and incrementing digits conditionally based on rollovers, I will implement the 4-digit BCD counter as a single 16-bit register representing all four digits combined. On each clock cycle, the counter will increment by one using a combinational process that simulates BCD addition with carry propagation in a pipelined style inside the same clock edge.

The key difference is that the increment operation is done in combinational logic by "ripple carry" through the BCD digits encoded in the 16-bit register: we increment the least significant digit and then propagate the carry to the next digit if needed, and so forth.

The ena signals for the upper three digits will be generated from the carry outputs at each digit increment step. This approach keeps the counter as a single register with combinational logic handling digit incrementing and carry propagation, simplifying state holding.

The synchronous reset clears the full 16-bit BCD register.

This architecture trades off a longer combinational carry chain for simpler state management and a single register, potentially improving area by avoiding multiple registers and function calls. The ena signals directly reflect when a digit increments in the combinational increment logic.

This also centralizes increment logic in one place, which can be easier to optimize or modify. The clock is still positive edge triggered, with synchronous reset.

Overall, this approach offers a clean, unified 16-bit BCD increment implementation with clear generation of digit increment enable signals.
