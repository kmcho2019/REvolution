To improve the original design's PPA (performance, power, area), I will apply these optimizations:

1. **Reduce Carry Chain Critical Path:**
   The original design computes carries sequentially using a function for each digit, then gating next increments on previous carries. This creates a chain of dependent combinational logic, hurting timing.

   I will replace the function approach with a parallel combinational logic style:
   - Compute next digit and carry in a single combinational block that propagates carry through all digits simultaneously using straightforward arithmetic.
   - This minimizes the longest carry path delay by avoiding nested conditional calls.

2. **Optimize Clock Enable Logic:**
   The original design only updates digits if changed, reducing switching. I will keep this as is because it’s effective for power.

3. **Avoid function call overhead:**
   Inlining the increment-with-carry logic will simplify synthesis and timing.

4. **Simplify enable signals:**
   The enable signals indicate when each upper digit increments (carry out from the previous digit). I will keep the existing definition but compute them explicitly from the carry chain.

5. **Use non-blocking assignments consistently.**

This approach reduces the critical path, improves synthesis quality, and maintains clean, readable code with minimal area overhead and lower power due to clock gating on value changes.
