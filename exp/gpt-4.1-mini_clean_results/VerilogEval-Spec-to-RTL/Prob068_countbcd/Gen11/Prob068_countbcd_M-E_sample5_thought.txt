I will implement the 4-digit BCD counter using a single 16-bit register for the entire BCD value to simplify increment logic and reduce combinational complexity. The incrementing will be done sequentially within a single clock cycle, but instead of nested conditional carries, I will perform the increment by checking and updating digits individually using a loop unrolled in a combinational process. 

The key idea is:
- Use a synchronous clocked process to increment the entire 4-digit BCD counter by 1 each clock.
- At each increment, check each digit from ones to thousands:
  - If a digit is 9, reset it to 0 and propagate carry to the next digit.
  - Otherwise, increment that digit and stop carry propagation.
- The enable signals (ena) will be generated based on whether the lower digits have reached 9, indicating the next digit should be incremented on the next clock cycle.
- The whole counter value is kept in a single 16-bit register `q_reg` for compactness.
- This approach avoids cascading function calls and nested ifs by using a simple iterative carry propagation.
- Synchronous reset initializes the entire counter to zero.

This approach reduces combinational complexity in the increment logic and creates a clean, easily synthesizable design with minimal control logic.
