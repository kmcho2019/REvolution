To optimize the original 4-digit BCD counter for better PPA, I will simplify the carry logic by computing carry signals combinationally but updating the digits sequentially on the clock edge to minimize the critical path delay.

Instead of cascading nested if-else blocks inside the sequential always block, I will precompute the carry signals ena combinationally based on each digit's value to indicate when the next digit should increment.

Then, in the sequential logic, I will increment each digit only if its enable signal is asserted, ensuring minimal combinational complexity inside the clocked block.

This splits combinational carry detection from sequential digit increment, reducing the combinational path length at the flip-flop inputs (improving timing).

Additionally, I will replace the bcd_inc function with inline logic for incrementing each digit with wrap-around at 9, which reduces function call overhead and may improve synthesis.

The ena output signals naturally map to the carries from ones to tens, tens to hundreds, and hundreds to thousands digits.

This approach lowers switching activity on higher digits as they only increment when enabled, which reduces power.

Overall, this solution balances timing by decoupling carry detection from digit increment and simplifies the RTL, potentially reducing area and power while maintaining functionality.
