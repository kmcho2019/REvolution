I will refactor the BCD counter by separating the combinational increment logic and the sequential register update more cleanly. Instead of nested if-else inside the sequential block, I will compute the next BCD value in a purely combinational always_comb block, with explicit carry propagation through temporary wires for clarity.

Enables will still be combinational, indicating when each digit is about to roll over to trigger the next digit's increment.

This approach keeps the synchronous register update simple and pushes the combinational complexity outside, potentially enabling synthesis tools to optimize carry logic better and improve timing.

It also enhances code readability by clearly separating the next-state calculation from register updates.
