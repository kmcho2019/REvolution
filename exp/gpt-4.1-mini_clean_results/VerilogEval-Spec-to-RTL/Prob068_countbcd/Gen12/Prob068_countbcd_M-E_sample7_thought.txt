I will implement a ripple enable BCD counter by modeling each digit as a separate 4-bit counter with an explicit enable input. The ones digit always increments every clock cycle (except on reset). The tens digit increments only when the ones digit rolls over from 9 to 0, indicated by a pulse. Similarly, the hundreds digit increments when the tens digit rolls over, and thousands increments when hundreds roll over.

This approach uses dedicated enable signals internally to propagate increments in a ripple fashion, which directly maps to the ena outputs for digits 3:1 as the enable inputs to these counters.

Each digit is a separate always block that increments its value only when its enable input is high. The enable inputs are generated by detecting when the previous digit hits 9 and then rolls over.

Reset is synchronous and active-high, zeroing all digits.

This structure decouples the counters and avoids long combinational chains by using enable signals to sequence increments, reducing critical path and increasing clarity. The ena outputs directly reflect when each upper digit's increment is triggered.

Output q packs the digits as required: ones in bits [3:0], tens [7:4], hundreds [11:8], thousands [15:12].

This modular ripple enable design makes timing easier to meet and logic simpler while fulfilling all spec requirements.
