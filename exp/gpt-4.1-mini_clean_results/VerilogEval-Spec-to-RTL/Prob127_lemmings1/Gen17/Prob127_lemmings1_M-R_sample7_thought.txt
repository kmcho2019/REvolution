I will refactor the FSM by using an explicit state encoding with parameters and replacing the combinational always block for next_state with continuous assign statements to define next_state in terms of the current state and bump inputs. The sequential always block will remain to update the state on clock or asynchronous reset. This will reduce the use of always blocks, favoring continuous assignments for combinational logic, which often leads to simpler and more transparent logic for synthesis tools. This refactoring retains the original functionality and clarity but changes the structural style for potentially easier analysis and verification.
