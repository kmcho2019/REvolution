To improve PPA, simplify the next state logic further by using a clean case-based approach instead of the composite boolean expression. This reduces potential glitches and logic depth in synthesis, potentially improving timing (lower TNS/WNS) and power by reducing transitions in combinational logic.

The next state conditions are:
- If bump_left and bump_right both active, toggle state.
- Else if bump_left active only, set state to 1 (walk_right).
- Else if bump_right active only, set state to 0 (walk_left).
- Else hold current state.

Implementing this with a case or if-else ladder inside a combinational always block for next_state calculation separate from the state register is more readable, can help synthesis tools optimize better, and makes FSM style explicit.

Keep asynchronous positive edge reset for initial state.

Outputs remain simple direct from state (Moore FSM).

This style often leads to cleaner netlists with minimal combinational logic depth, improving performance and power with no area penalty.

Also, by using a next_state signal and separating combinational next state logic from sequential state update, the design becomes modular and easier to optimize.
