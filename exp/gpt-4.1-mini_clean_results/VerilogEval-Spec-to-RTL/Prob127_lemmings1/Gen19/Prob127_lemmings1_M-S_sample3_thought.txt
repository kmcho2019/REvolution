The original design uses a somewhat complex boolean expression for next state logic. We can simplify the logic by explicitly handling all bump cases with clear conditions in the next state logic. Since bump_left causes walking right (state=1), bump_right causes walking left (state=0), and both bumps cause toggling, otherwise hold state, it can be encoded simply using a case or if-else priority style that maps directly to next_state, which improves readability and synthesis efficiency.

We will keep the asynchronous positive edge reset to set the FSM to walk_left (state=0). Then on each clock edge, update the state based on bump inputs:

- if (bump_left && bump_right) next_state = ~state; // toggle state
- else if (bump_left) next_state = 1; // walk right
- else if (bump_right) next_state = 0; // walk left
- else next_state = state; // hold

This is straightforward and minimal, eliminating complex boolean expressions. Outputs directly reflect state as required for a Moore FSM.
