The original solution uses a case statement to handle next state logic, which is already minimal and clear. To optimize for better power and performance, we can replace the case statement with purely combinational boolean logic that directly encodes the next state. This can slightly reduce logic complexity and switching activity by minimizing the number of logic gates inferred.

Specifically, the logic for next state is:
- If bump_left is asserted (1), walk right (state = 1)
- Else if bump_right is asserted (1), walk left (state = 0)
- If both are asserted, invert the current state

This can be expressed using boolean expressions:
- When both bumped: next_state = ~state
- When bump_left only: next_state = 1
- When bump_right only: next_state = 0
- When no bumps: next_state = state

This translates to next_state = (bump_left & ~bump_right) | (bump_left & bump_right & ~state) | (~bump_left & bump_right & 1'b0) | (~bump_left & ~bump_right & state)
Simplify to: 
next_state = (bump_left & ~bump_right) | (bump_left & bump_right & ~state) | (~bump_left & ~bump_right & state)

Further simplification leads to:
next_state = bump_left | (~bump_left & ~bump_right & state) if bump_right=0 or bump_right doesn't set state to 1

But since bump_right forces walk_left (state=0), that means:
If bump_right=1 and bump_left=0: state=0
If bump_left=1 and bump_right=0: state=1
If both=1: state=~state
Else state = state

Hence the Boolean can be written as:
if (bump_left & bump_right)
    next_state = ~state
else if (bump_left)
    next_state = 1
else if (bump_right)
    next_state = 0
else
    next_state = state

Implementing this with a small conditional structure without case reduces logic and can improve PPA slightly.

Also, outputs remain Moore style (derived solely from state).

This approach simplifies combinational logic while keeping FSM behavior identical.

The asynchronous reset and sequential logic remain unchanged.
