To improve PPA further, we focus on reducing toggle rates and simplifying logic while maintaining full functionality.

1. We remove the redundant fall_too_long flag by integrating the splatter condition directly into the fall_timer comparison, avoiding an extra register and OR gate. We simply check if fall_timer > 20 at landing time.

2. We simplify next_fall_timer update by saturating it at 21 (enough to know fall duration exceeded 20). This avoids wrap-around issues and reduces logic.

3. We restructure the FSM logic so that direction changes happen only when in walk mode and bumped, and bumps are ignored in other modes per spec, ensuring minimal direction toggles.

4. We assign default values carefully to prevent unintentional switching.

5. The asynchronous reset remains as is for clear reset behavior.

6. The fall_timer is set to 0 except when falling, where it increments and saturates at 21.

These changes reduce register count, eliminate one signal, and reduce combinational complexity, improving timing and power slightly without changing the FSM behavior or readability.
