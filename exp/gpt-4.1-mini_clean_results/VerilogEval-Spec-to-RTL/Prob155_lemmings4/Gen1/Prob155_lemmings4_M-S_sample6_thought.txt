Simplify the FSM by focusing on direction (left/right) and action (walking, falling, digging, splattered).

- Maintain direction bit: 0=left, 1=right.
- Maintain action state: WALK, FALL, DIG, SPLATTERED.
- On reset, direction=left, action=WALK.
- On each clock, asynchronously reset to WALK_LEFT.

Transitions with precedence: FALL > DIG > TURN.

- When walking:
  - If no ground, start falling in current direction.
  - Else if dig=1 and ground=1, start digging in current direction.
  - Else if bump_left or bump_right:
    - If bumped left, direction=right.
    - If bumped right, direction=left.
    - If bumped both sides, flip direction.
- When digging:
  - If ground=0, start falling in current direction.
  - Else continue digging.
- When falling:
  - Increment fall_count.
  - If ground=1:
    - If fall_count > 20, splatter.
    - Else go to walking in current direction.
    - Reset fall_count.
  - Ignore bumps and dig while falling.
- When splattered:
  - Stay splattered until reset.

Outputs are all 0 in SPLATTERED.

This approach uses simple direction and action state registers and clearly prioritizes events, ignoring bumps while falling/digging and handling all cases cleanly.

Fall count resets when leaving falling state.

All inputs sampled synchronously except async reset.

This design simplifies logic by using direction and action separately and avoiding large enums.
