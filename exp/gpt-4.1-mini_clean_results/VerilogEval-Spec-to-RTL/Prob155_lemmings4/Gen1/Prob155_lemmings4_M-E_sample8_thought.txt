Implement the Lemming controller as a Moore FSM with two orthogonal pieces of state: a direction bit (0=left, 1=right) and a mode state (walking, falling, digging, splattered). Separate these two state dimensions for clarity.

- The FSM state is a combination of mode and direction.
- On async reset, set mode=walking and direction=left.
- Outputs are driven by mode and direction only.
- On walking mode:
  - If ground==0, transition to falling mode, start fall counter at 1.
  - Else if dig==1, transition to digging mode.
  - Else if bumped left or right, toggle direction.
- On digging mode:
  - If ground==0, transition to falling mode, start fall counter at 1.
  - Else remain digging.
- On falling mode:
  - If ground==0, increment fall counter.
  - If ground==1:
    - If fall_count>20, transition to splattered mode.
    - Else transition to walking mode (keep direction).
  - Else remain falling.
- On splattered mode: stay forever.
  
The fall counter saturates at a max value >20 to avoid overflow toggling.

Using two separate registers (mode and direction) simplifies the logic and makes precedence and direction tracking explicit.

Moore outputs directly reflect mode and direction. Async reset sets mode=walking, direction=left, fall_count=0.

This approach clearly separates concerns, simplifies conditional logic, and matches the spec.
