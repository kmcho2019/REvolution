Use a Mealy-style approach internally but present a Moore interface by registering outputs.  
Model direction, mode (walking, falling, digging, splattered), and a fall timer separately as registers.  
Direction: 0 = left, 1 = right  
Mode encoded as enumeration: WALK=0, FALL=1, DIG=2, SPLAT=3  
On async reset: direction=left, mode=WALK, fall_timer=0  

FSM logic on posedge clk (with async reset):  
- If splattered: remain splattered forever until reset  
- Else if falling:  
  - increment fall_timer  
  - if ground reappears: if fall_timer > 20 -> splatter; else mode=WALK, fall_timer=0 (keep direction)  
- Else if walking:  
  - if ground==0 start falling with fall_timer=1  
  - else if dig==1 start digging  
  - else if bump_left or bump_right (bump on any side) switch direction  
- Else if digging:  
  - if ground==0 start falling (fall_timer=1) keep direction  
  - else continue digging (ignore bumps and dig input)  

Outputs computed purely from current mode and direction (Moore):  
walk_left=1 if mode==WALK and direction==0  
walk_right=1 if mode==WALK and direction==1  
aaah=1 if mode==FALL  
digging=1 if mode==DIG  
All zero if SPLAT  

This approach avoids a large FSM with combined states.  
Direction and mode are separate state variables; fall_timer handles timing.  
The precedence fall > dig > bump is respected by order of conditions in always_ff sequential logic.  
Asynchronous reset clears all registers.  
Outputs are synchronous Moore style from registered mode and direction.
