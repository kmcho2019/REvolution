I will implement the Lemming FSM using one-hot state encoding for clarity and potentially improved synthesis performance. Instead of a multi-bit state, each state will be represented as a one-hot bit, simplifying next state logic. I will encode direction separately as a 1-bit register and separate the falling timer counter logic using an enable signal active only when falling, which minimizes counter toggling and saves power. The FSM outputs will be generated as pure combinational outputs from the current state and direction registers (Moore outputs). I will also use a priority-encoded always_comb block to clearly express the priority order: falling > digging > direction switching. Direction switching will only occur when walking on ground and not digging or falling. The splat state disables all outputs and halts operation until reset. Asynchronous reset initializes the FSM to walking left. This design aims for clear, modular, and readable logic with separate next-state, direction, and timer calculations, emphasizing power savings on the fall timer and straightforward state transitions.
