Refactor the FSM into a single always_ff block handling state updates with asynchronous reset, and use combinational functions to separately compute next mode, direction, fall timer, and fall_too_long. The next-state logic is implemented as functions returning next values to cleanly separate combinational logic from state updates, making the code modular and easier to read and test. Outputs remain Moore, assigned from current state. This functional approach avoids the large always_comb with many variables and leverages clear functional decomposition of the next-state logic while maintaining the same behavior and priorities.
