We implement a Moore FSM with states representing walking left, walking right, falling, digging, and splattered. Walking states are distinguished by direction. The state transitions are as follows:

- On reset, state = WALK_LEFT.
- If in walking (left or right):
  - If ground==0, go to FALLING, start fall counter.
  - Else if dig==1, go to DIGGING.
  - Else if bump_left==1 or bump_right==1 (or both), switch walking direction.
- If in digging:
  - If ground==0, go to FALLING, start fall counter.
  - Else remain digging.
- If in falling:
  - Increment fall counter.
  - If ground==1, check fall duration:
    - If fall_count > 20, go to SPLATTERED.
    - Else return to walking in original direction before falling.
- If splattered:
  - Stay in splattered forever until reset.

Outputs are derived from the current state:
- walk_left=1 if walking left.
- walk_right=1 if walking right.
- aaah=1 if falling.
- digging=1 if digging.
- All outputs zero in splattered state.

We need to record walking direction before falling to restore after falling. Bumps have no effect while falling or digging.

The fall counter increments only while falling, resets on other states and reset.

areset asynchronously resets state to WALK_LEFT.

We define states as an enumerated type for clarity:
0 = WALK_LEFT
1 = WALK_RIGHT
2 = FALLING
3 = DIGGING
4 = SPLATTERED

We implement synchronous state transitions and output logic, with asynchronous reset.
