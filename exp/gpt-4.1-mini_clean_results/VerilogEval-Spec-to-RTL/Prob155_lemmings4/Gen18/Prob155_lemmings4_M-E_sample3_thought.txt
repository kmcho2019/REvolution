I will implement the Lemming FSM using explicit named states encoded as localparams for clarity, and separate a direction register from the state logic. The FSM will have four states: WALK, DIG, FALL, SPLAT. The direction will be stored independently as a single bit: 0 for left, 1 for right.

To simplify bump logic, I will create a combined bump signal as bump_any = bump_left | bump_right and use it only when walking and not digging or falling. If bumped on left, direction is forced right; if bumped on right, direction is forced left. When bumped on both sides, I will flip direction.

During FALL, a 5-bit timer counts up each clock cycle until hitting 21 (which means >20 cycles). When ground is regained, if the timer indicates a long fall, Lemming splats.

The priority order in next state logic is fall > dig > bump direction switch. Bump signals are ignored if not walking on ground.

I will implement asynchronous reset to WALK left. Outputs are Moore-type: only dependent on current state and direction.

This approach uses clear explicit state and direction handling, clean separation of timer logic, and simplifies bump logic via combined signals. The code is fully synchronous except asynchronous reset, and the outputs follow the requirements exactly.
