Instead of using a flat mux or evenly chunked sub-muxes, I will implement a tree-based hierarchical 2:1 mux for the 100-bit inputs. This approach breaks down the 100-bit mux selection into multiple stages of smaller muxes (for example, 2-bit muxes), organized in a balanced binary tree structure. At each stage, pairs of bits are selected based on sel, and the outputs are fed into the next stage of muxes, eventually resulting in a single combined output.

Advantages of this tree approach:
- Reduced fan-in per mux and shorter mux paths per bit compared to a flat 100-bit mux.
- Enables balanced load and potentially better timing and power characteristics by localizing switching and allowing parallel evaluation.
- Modular and scalable to arbitrary widths by adjusting tree depth.
- Demonstrates a different architectural approach compared to simple chunking or flat muxing.

Implementation details:
- Base level muxes select between each bit from a and b based on sel.
- Then recursively pair-wise combine outputs until full 100-bit vector is resolved.
- Since sel is the same for all bits, this hierarchy logically replicates the same select, but structures mux logic in a tree.

This provides a novel architectural solution different from flat or chunked muxing, showcasing hierarchical decomposition in hardware.
