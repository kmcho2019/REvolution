Implement a streaming, bit-serial approach to process the 512-cell Rule 110 automaton using a shift register and a three-stage pipeline for neighbor context. Instead of fully parallel combinational logic, the design:

1. Stores the 512-bit state in a register (`q`).
2. On each clock, if `load` is asserted, it loads the new 512-bit data.
3. Otherwise, it iterates sequentially through the 512 cells over 512 clock cycles using a bit index counter (`idx`).
4. A 3-bit sliding window is built serially by shifting in bits from `q` (the current state).
5. The Rule 110 logic is applied on this 3-bit window to compute the next state for each bit, which is stored in a separate shift register (`next_q`).
6. After processing all 512 bits, the new state (`next_q`) replaces `q`.
7. Boundary conditions are handled by assuming zero for bits outside the array (when the window includes indexes < 0 or >= 512).
8. This approach trades off latency (512 cycles per generation step) for reduced combinational logic and simpler datapath, making timing easier and potentially saving power and area.

The output `q` is always the current generation state, updated every 512 cycles. The module includes control logic to manage the load, processing, and update of the state in a serialized fashion.
