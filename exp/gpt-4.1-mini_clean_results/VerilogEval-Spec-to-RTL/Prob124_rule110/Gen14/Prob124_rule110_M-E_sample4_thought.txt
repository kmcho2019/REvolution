Implement Rule 110 as a two-stage pipeline to reduce combinational delay in each clock cycle:

1. Store the current state `q` in a 512-bit register.
2. In the first pipeline stage (next_state_stage), compute the left, center, and right neighbors for each cell and hold them in three separate 512-bit registers (`left_reg`, `center_reg`, `right_reg`).
   - Boundary cells assume zero neighbors.
3. In the second pipeline stage, use these neighbor vectors to compute the next state `next_q` using bitwise operations in parallel (vectorized computation) according to Rule 110 logic applied per bit.
4. The computed `next_q` is registered and becomes `q` for the next cycle.
5. On asserting `load`, directly load `q` with input data immediately, clearing the pipeline.
   
This approach splits the neighbor extraction and the next-state logic into two cycles, halving the combinational logic per cycle, improving timing.

Also, boundary bits are handled by shifting with zero padding using vector concatenation and slicing, avoiding per-bit logic in neighbor extraction.

The logic is fully combinational between pipeline registers, with latency of two cycles to produce the next state. The interface remains the same with synchronous load.

This novel two-stage pipeline balances the critical path better, leverages vector operations to keep code compact and efficient, and clarifies the neighbor extraction and rule application steps.
