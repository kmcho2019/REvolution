The original design uses a continuous assignment with the OR operator directly on inputs a, b, and c. To refactor without changing functionality, I will implement the logic inside an always_comb block using non-blocking assignment. This approach expresses the same combinational logic in a procedural style rather than a continuous assignment. The output is assigned based on the OR of the inputs inside the always block, which is synthesizable and functionally identical.

This refactoring changes the coding style from declarative (continuous assignment) to behavioral (procedural always block), which might be preferred in certain design flows or coding standards. It maintains minimal hardware since synthesis will infer the same OR gate structure, so PPA remains optimal.

Hence, the refactor demonstrates an alternate, procedural coding style while preserving minimal hardware and optimal synthesis results.
