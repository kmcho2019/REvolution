Use a three-state FSM to track the message reception: IDLE (waiting for a start byte), BYTE2 (waiting for the second byte), and BYTE3 (waiting for the third byte). On reset, return to IDLE. When in IDLE, only transition to BYTE2 if the input byte has in[3]=1 (start of a message). In BYTE2 and BYTE3, accept any byte as part of the message. When the third byte is received (BYTE3 state), assert done for one cycle and transition back to IDLE. This approach clearly models the protocol states and makes the state transitions explicit, improving code clarity and extensibility.
