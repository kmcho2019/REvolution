Refactor the FSM by explicitly defining three states: IDLE, BYTE1, BYTE2. Use a state machine encoded as a 2-bit register to track the message progress. On reset, state goes to IDLE. When in IDLE, wait for a byte with in[3]=1 to start message (go to BYTE1). Then sequentially move through BYTE1 and BYTE2 states on each byte received. When transitioning from BYTE2 back to IDLE, assert done for one cycle. This approach replaces the counter with an explicit state machine, making the design clearer and easier to modify or extend.
