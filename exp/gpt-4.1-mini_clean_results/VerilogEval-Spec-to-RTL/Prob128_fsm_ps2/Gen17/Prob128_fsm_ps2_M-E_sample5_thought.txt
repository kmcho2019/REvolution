Instead of using a counter to track the number of bytes received, I will implement a simple three-state FSM with explicit states IDLE, BYTE1, BYTE2, and BYTE3 representing how many bytes of the current message have been received. 

- In IDLE, the FSM waits for a byte with in[3]=1 (start byte). 
- Upon detection, it moves to BYTE1, signifying the first byte received. 
- Next cycle with any byte input, it transitions to BYTE2, then BYTE3. 
- When BYTE3 byte is received, the FSM asserts done for one cycle and returns to IDLE to look for the next start byte.

This approach simplifies the logic by explicitly enumerating message reception stages, easing verification and potentially reducing glitches by avoiding counters and enable logic. 

The synchronous reset clears the state machine to IDLE and done=0. The done signal is asserted only in the cycle after the third byte has arrived, indicating message receipt.

This FSM directly models the three-byte message process, making the design clear and robust.
