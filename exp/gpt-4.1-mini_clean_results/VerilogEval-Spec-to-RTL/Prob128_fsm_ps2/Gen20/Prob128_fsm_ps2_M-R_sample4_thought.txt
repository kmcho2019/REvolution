Refactor the FSM by explicitly defining states using a one-hot style encoding with three states representing the byte count (WAIT_START, BYTE2, BYTE3). Use a combinational always block for next state logic and a sequential always block for state updating and done generation. This approach separates state transition and output logic, making it clearer and more maintainable. The done output is asserted immediately after receiving the third byte (BYTE3 state), and reset remains synchronous active-high. The main logic relies on the input bit in[3] to detect the start of a message, and states transition accordingly.
