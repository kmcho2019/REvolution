Fusion strategy:
- Use a single always block with synchronous active-high reset.
- Default done to 0 every cycle to avoid glitches.
- Use a small 2-bit counter to track bytes in the message: 0 means waiting for start byte, 1 and 2 mean bytes 2 and 3.
- Start counting when in[3] = 1 at count=0.
- Increment count only when inside a message.
- Assert done for one cycle immediately after receiving third byte (when count=2).
- Reset count to zero on done or reset.
- Introduce an enable signal that is active only when inside a message or detecting a start byte, gating counter updates and done generation to reduce unnecessary toggling, improving power.
- Retain straightforward non-blocking assignments and minimal combinational logic for performance and area efficiency.
- Keep the done pulse single-cycle with no extra latency.
This combined approach optimizes performance, power, and area (PPA) by minimal logic, controlled toggling, and a simple, predictable FSM.
