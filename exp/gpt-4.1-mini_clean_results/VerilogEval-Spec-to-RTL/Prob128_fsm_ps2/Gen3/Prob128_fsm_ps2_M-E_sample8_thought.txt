Instead of using an explicit multi-state FSM, use a 2-bit counter to track received bytes of the current message. The counter resets to 0 on reset or when a byte with in[3]=1 is seen (indicating start of a new message). When counter is 0 and in[3]=1, we start a new message by setting counter to 1. On subsequent clocks, increment the counter if counter > 0, and when it reaches 3, assert done for one cycle and reset counter back to 0. This approach naturally handles continuous streams and message boundaries with minimal control logic and keeps done a one-cycle pulse.
