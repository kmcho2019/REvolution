Refactor the FSM by using an explicit combinational always @(*) block for next-state and output logic with case statements instead of continuous assignments. This approach improves code readability and synthesis tool friendliness by clearly separating combinational and sequential logic while retaining synchronous reset and non-blocking assignments in the sequential block. The output z is registered (not purely combinational) to demonstrate a different FSM style, capturing output as a registered signal updated alongside the state.
