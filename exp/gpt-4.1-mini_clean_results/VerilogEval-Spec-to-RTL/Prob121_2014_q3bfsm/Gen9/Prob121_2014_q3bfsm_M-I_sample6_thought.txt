To improve PPA (timing, power, and area), I will switch the FSM encoding from binary to one-hot, since only 5 states exist and 3 flip-flops used currently encode 8 states, wasting area. One-hot encoding uses 5 flip-flops but reduces combinational logic in next state and output decoding, which can improve timing and reduce glitching power. The output z depends directly on the state, so registering the output z on the clock edge will reduce glitches and dynamic power on the output line. The synchronous reset remains active high. Next state logic and output logic are simplified to direct assignments using one-hot signals, reducing complex case statements and improving timing. This tradeoff favors better timing and power by simplifying combinational paths at slight area cost (5 FFs vs 3 FFs), which is acceptable for the small FSM.
