To optimize the FSM for better PPA (performance, power, area), I will focus on reducing combinational logic depth and switching activity:

1. **State encoding**: Use one-hot encoding for the 5 states. One-hot encoding simplifies next-state logic since only one bit is set for a state, leading to simpler combinational logic, improving speed and potentially reducing area and power.

2. **Output logic**: Because the output z is solely determined by the current state (Moore output), it can be registered together with the state flip-flops to reduce glitching and switching on the output net, thereby potentially reducing power consumption.

3. **Reset**: Keep the synchronous active-high reset as required.

4. **Next state logic**: Implement next state logic by explicit combinational logic equations derived from the one-hot state encoding and input x, to minimize logic depth.

By employing one-hot encoding, the next state logic can be implemented with fewer logic gates. Registering the output z reduces glitches and switching activity on output pins. These optimizations help improve timing (lower critical path delay), reduce power, and keep area low.

I will also keep separate combinational always blocks for next state and output logic for clarity and extensibility.
