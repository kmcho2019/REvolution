A novel approach is to implement the thermostat control logic using a small finite state machine (FSM) that explicitly tracks whether the system is currently heating, cooling, or idle. This FSM approach, although slightly more complex, provides a clear stateful framework that can be easily extended for hysteresis or delayed transitions in the future.

The FSM has three states:
- IDLE: neither heating nor cooling active.
- HEATING: heater on.
- COOLING: air conditioner on.

Transitions depend on the mode and temperature inputs. The fan output depends on whether heating or cooling is active or if the user forces the fan on (fan_on).

This stateful design separates control decisions from outputs, making the design modular and more maintainable, and showcases a different architectural style than purely combinational logic.

This is implemented with synchronous logic for state updates triggered by inputs (for simplicity, we'll assume synchronous updates using a clock input internally generated by a combinational trigger, or treated combinationally in this example). For clarity, here we'll model the FSM as combinational outputs derived from the present inputs and current state signals (mode, too_cold, too_hot).

Since no clock is specified, we will model it as combinational logic with explicit states stored in internal registers updated combinationally—emulating a Mealy machine style.

This design can be easily adapted to a clocked FSM if a clock is later added.
