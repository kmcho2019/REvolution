To improve the PPA metrics (timing slack, power, area) for this FSM, we target:

- Timing: The current 2-bit binary encoding is minimal in flip-flops but involves combinational priority checks on input `r[2:0]` every cycle in the next-state logic, potentially creating critical paths. To reduce logic depth and improve timing, use one-hot encoding for states A, B, C, D. This trades a few more flip-flops (4 vs 2) but greatly simplifies the next state logic and output decoding.

- Power: One-hot encoding may increase flip-flop count but reduces combinational logic toggling and complexity, potentially lowering switching power on combinational nets. Since grants activate only one bit at a time, outputs are directly connected to state bits, so toggling is minimal. Also, enable synchronous reset gating to avoid glitches on reset assertion.

- Area: One-hot encoding uses more FFs but less combinational logic; depending on the technology, simpler combinational logic might reduce total area or improve timing. Since the area in the previous design is small (35 um²), the slight increase from more FFs is acceptable for timing gain.

Implementation details:

- State bits: 4 bits, each corresponds to a state: A=4'b0001, B=4'b0010, C=4'b0100, D=4'b1000.
- Next state logic: Directly encode next states with simple AND/OR gates reflecting priorities without complex priority encoding.
- Outputs g: directly assigned from state bits B, C, D: g[0]=B, g[1]=C, g[2]=D.
- Synchronous active-low reset sets state to A.
- Separate always blocks for state update and next-state combinational logic.
- Keep logic minimal and combinational paths shallow.

This will improve WNS and TNS by reducing combinational critical path, potentially reduce power by less complex logic toggling, and slightly increase area due to more FFs but still compact.

Overall, this tradeoff optimizes PPA by prioritizing timing and power improvements while maintaining clarity and correctness.
