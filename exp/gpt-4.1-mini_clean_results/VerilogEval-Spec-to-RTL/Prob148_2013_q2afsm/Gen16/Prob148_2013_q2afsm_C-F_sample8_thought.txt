Fuse the best ideas from both examples to create a minimal, power- and area-efficient FSM:

- Use a 2-bit binary state encoding (4 states: A=00, B=01, C=10, D=11) to minimize flip-flop count and switching activity. This reduces area and dynamic power compared to one-hot (3 flip-flops).

- Map states explicitly: 
  - 2'b00: idle (A)
  - 2'b01: grant device 0 (B)
  - 2'b10: grant device 1 (C)
  - 2'b11: grant device 2 (D)

- Implement synchronous active-low reset to state A.

- Next state logic follows priority:
  - From idle (A), check requests in priority order and move to corresponding grant state.
  - From a grant state, stay if request persists, else return to idle.

- Outputs (g[2:0]) are combinationally derived from state to grant the corresponding device:
  - g[0] = 1 if in B (state == 2'b01)
  - g[1] = 1 if in C (state == 2'b10)
  - g[2] = 1 if in D (state == 2'b11)
  - Otherwise, all grants are 0.

- Use blocking assignments in combinational always block and non-blocking in sequential.

- This approach minimizes flip-flops (2 vs 3 or 4), reduces switching, and yields simpler combinational next state logic than the binary encoded FSM with outputs decoded from state, which is power/area efficient and likely improves timing.

- The combinational output logic is straightforward and avoids direct mapping from one-hot states, reducing glitches and unnecessary toggling.

- This fusion thus improves PPA by combining the minimal flip-flop count from binary encoding with clean next-state and output decoding logic inspired by one-hot simplicity.
