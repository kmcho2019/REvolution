The existing FSM uses a 3-bit one-hot encoding with 4 states (A, B, C, D) but encodes idle state A as 3'b000 (no flip-flop set), which is unconventional for one-hot encoding. This causes the outputs (g) to directly mirror the state register bits, but in idle no grants are given, which fits. 

To improve PPA, especially area and power, we can move from one-hot encoding to binary encoding using only 2 bits for the 4 states. This reduces flip-flops from 3 to 2, thus saving area and power. Binary encoding reduces switching as fewer flip-flops change state each clock cycle.

We will assign:
- 2'b00 = A (idle)
- 2'b01 = B (grant device 0)
- 2'b10 = C (grant device 1)
- 2'b11 = D (grant device 2)

The next-state logic will encode the same priority logic:

- In idle (A), if r[0] is high, go to B
- else if r[1] is high, go to C
- else if r[2] is high, go to D
- else stay in A

In grant states B, C, D, stay if the granted device's request persists, else return to A.

The output g[2:0] will be decoded combinationally from the state. The grant bit matching the device granted is 1, others 0. This reduces output toggling compared to directly mirroring state bits.

Reset remains synchronous active-low reset to state A (2'b00).

This approach reduces flip-flops from 3 to 2, simplifies state registers, reduces switching activity, and should improve area and power without impacting performance significantly.

We will use blocking assignments in the combinational block and non-blocking in sequential, following best practices.

Overall, this binary FSM encoding with combinational output decoding will provide a better PPA tradeoff for this small 4-state FSM.
