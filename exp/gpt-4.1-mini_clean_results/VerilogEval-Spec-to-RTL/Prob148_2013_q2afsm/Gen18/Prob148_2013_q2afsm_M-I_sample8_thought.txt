The original one-hot encoding solution is clean and functionally correct but uses 3 flip-flops for 4 states, which is more than the minimal 2 bits needed. To improve area and power, and potentially timing, we will switch to a binary-encoded FSM with 2 bits representing the states:

- 2'b00: State A (Idle)
- 2'b01: State B (grant device 0)
- 2'b10: State C (grant device 1)
- 2'b11: State D (grant device 2)

The grant outputs g[2:0] will be derived combinationally from the current state. This reduces flip-flop count, simplifies the state register, and should reduce power and area.

The priority logic remains the same: from idle, grant the highest priority request device; from a grant state, remain in that state if the corresponding request remains asserted, else return to idle.

We keep synchronous active-low reset, clocked on the positive edge.

This binary FSM reduces state bits by 1 and should improve all PPA metrics while preserving the specified FSM behavior.
