Refactor the design to use a simple two-state FSM: IDLE and ENABLE.

- In the IDLE state, shift_ena is low and the module waits for either reset or pattern detection signal to start the 4-cycle enable.

- When reset is asserted synchronously high, or pattern is detected, the FSM transitions to the ENABLE state.

- In ENABLE, shift_ena is asserted high and a 3-bit counter counts from 4 down to 0 on each clock cycle.

- After the counter reaches 0, FSM returns to IDLE and shift_ena is deasserted.

- Pattern detection is represented by an input signal (e.g., pattern_detected) that triggers the FSM to start enabling shift_ena for 4 cycles whenever asserted.

This structure separates control logic and counting, uses an explicit FSM, and uses synchronous reset and pattern detection inputs to control shift_ena.

To keep the same interface as requested, we'll add an input `pattern_detected`. If not allowed, the pattern_detected input could be simulated internally or hardwired.

For this refactoring, the counter and FSM state register are updated synchronously on clk. shift_ena is driven combinationally from the state.

This solution meets the requirement: shift_ena asserted for exactly 4 cycles after reset, and for 4 cycles whenever pattern_detected is asserted.
