To implement the FSM with minimal states and correct timing, use three states:

- State A: initial/reset state, waiting for s=1 to start monitoring w.
- State B: sampling state, where w is sampled for exactly three consecutive clock cycles and the count of w=1's is accumulated.
- State C: output state, where z is asserted for one cycle if exactly two out of three sampled w's were 1, otherwise z=0.

This approach clearly separates:

- waiting for trigger (s=1) in state A,
- sampling phase in state B with a 2-bit counter (0 to 2),
- output phase in state C with 1-cycle duration.

On reset, go to state A, clear counters and output.

In state B, on each clock, accumulate w count and increment sample counter.

When sample counter hits 3, transition to state C in the next clock.

In state C, output z depending on count_w == 2, then transition immediately back to B to start next 3-cycle sampling window.

This creates a clean repeating cycle: A -> B(3 samples) -> C(output z) -> B -> C -> ...

This avoids off-by-one errors and keeps code straightforward.

All signals updated on positive clock edge with synchronous reset.

No overlapping sampling and output cycles.

The s input is ignored except in state A.

This approach uses 3 states but is very clear and easy to maintain correctness.

Because the problem demands minimal states but clarity and correctness are prioritized, three states are acceptable.

All counters and outputs are registered synchronously.

This design directly matches problem requirements with exact timing for output z and input sampling windows.
