I will refactor the FSM to use a Moore FSM style with a state register and separate output logic combinational block. Instead of embedding all logic in one always block, I will separate:

- A state register always block for synchronous state transitions and counters.
- A combinational block for next state and next counters logic.
- A separate combinational block for output z logic based on the state and counters.

I will use three states: A (waiting for s=1), B0, B1, B2 representing the 0th, 1st, and 2nd sampling cycles in the 3-cycle window, rotating through B0->B1->B2->B0, to explicitly track the cycle count within states instead of a separate counter. This reduces the need for a separate counter register.

I will accumulate the count of w=1 samples in a 2-bit register. After reaching B2, z is asserted on the next cycle based on whether the count equals 2.

This refactoring provides clearer separation of FSM logic and output, making the code easier to verify, potentially improving synthesis optimization, and illustrating a standard FSM style with explicit states rather than embedded counters.

Reset synchronously sets the FSM back to A and clears counters and outputs.

All sequential logic remains on the posedge clk with synchronous active-high reset.
