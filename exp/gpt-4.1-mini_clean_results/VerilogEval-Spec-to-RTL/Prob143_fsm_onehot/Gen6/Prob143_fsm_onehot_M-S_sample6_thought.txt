To simplify the design, I will avoid the for-loop and directly compute next_state bits as combinational ORs of all possible transitions from current states based on input 'in'. This removes the loop and case statements, reducing complexity and making the code more concise and readable.

Since states can be multi-hot, I will explicitly enumerate for each next_state bit the sources from which it can be reached in one step, combining them with OR operations.

For outputs, I will keep the bitmask approach with one assignment per output for clarity and efficiency.

This approach trades some redundancy for simplicity, maintaining full functionality and combinational correctness while making the code easier to follow and synthesize.
