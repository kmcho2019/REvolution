To fuse the best ideas from both examples, we keep the clarity and maintainability of the for-loop iteration from Example 2 while adopting the explicit, direct combinational OR logic structure from Example 1 to reduce unnecessary sequential if checks and enhance logic synthesis optimization. Instead of updating outputs inside the loop and risk multiple assignments (which can confuse tools or increase toggling), we accumulate outputs using bitwise OR over all active states after computing next_state. This also cleanly separates next_state computation from output logic.

Moreover, we explicitly list the transitions in a flat manner, which gives synthesis tools better ability to optimize and share common terms, such as many states transitioning to S0 on input 0. For outputs, instead of setting registers multiple times inside the loop, we OR all states with known outputs with the input state vector to produce combinational output signals.

This structure yields:
- Clean, readable code using a for-loop and case to cover all states.
- Reduced combinational logic depth by consolidating transitions directly.
- Outputs computed separately by OR’ing the current states with known output bits to reduce logic toggling and improve synthesis.
- Ensures correct handling when multiple current states are simultaneously active.

Overall, this balances explicitness and synthesis friendliness, yielding a design with better clarity, maintainability, and potential PPA improvements.
