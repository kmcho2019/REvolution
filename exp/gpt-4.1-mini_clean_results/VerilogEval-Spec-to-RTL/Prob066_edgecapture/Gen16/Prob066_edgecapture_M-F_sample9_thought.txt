The main issue is likely the initial value of `prev_in` after reset. Setting it to zero means that the first valid input with bits high will be interpreted as a falling edge on those bits going from 1 to 0, which is incorrect. To avoid this, initialize `prev_in` to the current input on reset so that the first comparison is meaningful, thus preventing false falling edges immediately after reset. This ensures that only real falling edges detected after reset are captured. The rest of the logic remains unchanged.
