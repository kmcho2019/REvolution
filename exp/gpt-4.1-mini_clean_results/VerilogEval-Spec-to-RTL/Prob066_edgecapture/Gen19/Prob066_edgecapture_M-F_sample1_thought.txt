The key issue is that initializing `prev_in` to all ones on reset can cause false falling edge detections if the actual input bits start at zero, since a 1->0 transition is wrongly inferred immediately after reset. To fix this, initialize `prev_in` synchronously to the current input value `in` on reset. This ensures no false edges are detected on the first active cycle after reset because `prev_in` matches `in` exactly, so only genuine 1->0 transitions afterwards are captured. The rest of the design logic remains unchanged, still detecting falling edges via `prev_in & ~in` and latching the outputs accordingly.
