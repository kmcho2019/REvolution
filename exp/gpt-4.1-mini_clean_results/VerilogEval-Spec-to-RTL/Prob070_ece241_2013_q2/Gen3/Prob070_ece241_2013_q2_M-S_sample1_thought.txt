We need to generate outputs that are logic 1 when inputs correspond to decimal 2, 7, or 15, and logic 0 for 0,1,4,5,6,9,10,13,14. Inputs 3,8,11,12 never occur.

Given the input bits a,b,c,d as a 4-bit number with 'a' as MSB and 'd' as LSB, decimal values correspond as: value = a*8 + b*4 + c*2 + d*1.

Since only three input values output 1, the minimal sum-of-products (SOP) is just the OR of their minterms:
- 2 = 0010 = ~a & ~b & c & ~d
- 7 = 0111 = ~a & b & c & d
- 15=1111 = a & b & c & d

For minimal product-of-sums (POS), it's simpler to use the complement of out_sop and apply DeMorgan to get POS:
- out_pos = ~out_sop = 1 only when output is 0, matches the specified zero values and don't cares.

This avoids manually complex POS minimization and ensures correctness.

Hence:
- out_sop = OR of minterms for 2,7,15
- out_pos = NOT of out_sop (minimal and accurate)

This approach is minimal, clean, and logically consistent.

Note: Since 3,8,11,12 never occur, the output value for those combinations is don't-care and won't affect correctness.
