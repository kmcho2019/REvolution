Instead of building the function using two separate AND gates followed by an OR gate, I will implement the logic with a 2-to-1 multiplexer structure controlled by x3.

From the truth table, when x3=0, f = x2; when x3=1, f = x1 OR x2 (since for x3=1, f=1 if x1=1 or when x2=0,x1=1). However, checking carefully, f is 1 at x3=1,x1=1 or x3=0,x2=1.

Another observation is that f = (x2 & ~x3) | (x3 & x1). But to be different, I will implement a 2:1 multiplexer module that outputs x2 when x3=0, and x1 when x3=1, exactly the function f.

I will create a Mux2to1 module and instantiate it inside TopModule to select the correct input according to x3.

This approach uses a modular multiplexer structure to implement the function directly and avoids multiple AND and OR gates explicitly. It also generalizes easily if input width increases.

This design is novel compared to the previous AND-OR gate approach.
