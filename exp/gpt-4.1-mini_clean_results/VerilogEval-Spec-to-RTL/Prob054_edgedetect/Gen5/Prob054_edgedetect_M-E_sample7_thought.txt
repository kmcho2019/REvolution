Instead of directly registering the previous input and computing the rising edges in the same clock cycle, I will introduce a two-stage pipeline. The first stage registers the input vector; the second stage compares the registered input from the first stage to the current input in the second stage to detect the 0-to-1 transitions. The output pedge is registered in the second stage, effectively delaying the pulse detection by one clock cycle after the transition. This pipelining breaks the critical path into smaller stages, allowing potentially higher clock frequencies in timing-sensitive designs. The trade-off is an additional register stage (area and latency), but it may improve performance due to reduced combinational logic depth per stage. This approach cleanly separates input sampling and edge detection, enhancing timing clarity and pipeline-based design methodology.
