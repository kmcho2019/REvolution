Instead of separately deriving next-state signals as separate one-hot bits, we can define each next-state as a direct wire from the current state and inputs, following the one-hot encoding, but encoded in a priority encoder style.

To do this, we will create explicit expressions for each next state, using the current state's one-hot signals and inputs. We combine inputs and current states in AND terms, then OR these for the next state signals.

Moreover, to avoid complex expressions, we will separate the state transitions into two categories: those driven by input d (the early states), and the fixed linear sequence through the B states, then counting, then wait.

For outputs, since it is a Moore machine, outputs depend only on the current state. We derive done, counting, shift_ena directly from current states.

Additionally, we generate next-state indicators signals (e.g., B3_next) by directly computing the logical expressions of the next state.

This approach makes next state and output logic explicit and modular.

This design will have the same functionality but a different structural style, emphasizing readability and explicit next state formulas.

Note: For the fixed "always go to next cycle" states (B0->B1->B2->B3->Count), the next state is simply the next bit in the one-hot chain.

For the states S, S1, S11, S110 and Wait, Count, transitions depend on inputs (d, done_counting, ack).

We will create explicit one-hot next-state expressions for all states, then assign output signals and next-state indicators accordingly.

This differs from the prior design by explicit direct one-hot next-state signal assignments instead of using an intermediate vector.
