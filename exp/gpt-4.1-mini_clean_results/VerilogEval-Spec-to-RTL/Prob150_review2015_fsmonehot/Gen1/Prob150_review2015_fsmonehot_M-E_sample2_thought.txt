Instead of directly encoding next-state bits by explicit enumeration per state, we can leverage the one-hot encoding to create a next-state vector by combining a set of intermediate signals for each state's possible next states.

We create intermediate signals representing possible next states derived from the current state bits and inputs using boolean logic. Then, we combine these to form the next-state signals.

This approach uses one-hot nature by defining next-state signals as combinations of current state bits and inputs, but with less reliance on sequential `if-else` and more on compact boolean expressions for clarity.

Outputs are driven directly from the current state bits as per Moore machine definition.

This modular logic approach helps keep combinational logic succinct and easy to verify.

The next-state logic derived:

- S_next = (S & ~d) | (S1 & ~d) | (S110 & ~d) | (Wait & ack)
- S1_next = S & d
- S11_next = S1 & d | S11 & d (not required as output signals)
- S110_next = S11 & ~d (not required as output signals)
- B0_next = S110 & d (also not output)
- B1_next = B0 (not output)
- B2_next = B1 (not output)
- B3_next = B2 (output signal)
- Count_next = B3 | (Count & ~done_counting)
- Wait_next = (Count & done_counting) | (Wait & ~ack)

Outputs:

- shift_ena = B0 | B1 | B2 | B3
- counting = Count
- done = Wait

We only expose signals B3_next, S_next, S1_next, Count_next, Wait_next, done, counting, shift_ena.

This logic fully encodes transitions and outputs, leveraging the one-hot property clearly.
