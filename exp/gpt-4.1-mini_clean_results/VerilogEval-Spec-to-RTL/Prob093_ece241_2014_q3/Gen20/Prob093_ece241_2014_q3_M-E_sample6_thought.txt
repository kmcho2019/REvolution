We have a 4-to-1 mux with inputs mux_in[3:0], selected by {a,b}, and the output should implement the K-map given over variables {a,b,c,d}.

The 4-to-1 mux selects one of mux_in[0], mux_in[1], mux_in[2], mux_in[3] based on {a,b}:
- ab=00 selects mux_in[0]
- ab=01 selects mux_in[1]
- ab=11 selects mux_in[2]
- ab=10 selects mux_in[3]

Each mux_in[i] is a function of c and d only and represents a column in the K-map:

The K-map with rows as cd and columns as ab is:

      ab
  cd  00  01  11  10
  00 | 0 | 0 | 0 | 1 |
  01 | 1 | 0 | 0 | 0 |
  11 | 1 | 0 | 1 | 1 |
  10 | 1 | 0 | 0 | 1 |

For each mux_in[i], list the outputs for cd=00,01,11,10 (rows):

- mux_in[0] (ab=00): 0,1,1,1
- mux_in[1] (ab=01): 0,0,0,0
- mux_in[2] (ab=11): 0,0,1,0
- mux_in[3] (ab=10): 1,0,1,1

The requirement is to implement these four functions of c and d using only 2-to-1 multiplexers and constants, no other gates.

Novel architectural idea: build each mux_in[i] using a hierarchy of 2-to-1 multiplexers controlled by either c or d, where each 2-to-1 mux is a primitive.

We define a simple 2-to-1 mux module, then use these muxes to build the functions.

Observe that the inputs for mux_in[i] differ at different cd values. We can select first on c or on d to minimize mux levels.

For example:

- mux_in[0]:

  For cd=00(c=0,d=0):0
  cd=01(c=0,d=1):1
  cd=11(c=1,d=1):1
  cd=10(c=1,d=0):1

  When c=0: output = d (0 or 1)
  When c=1: output = 1

  Implement as mux controlled by c: if c=0 output=d else 1

- mux_in[1]: always 0

- mux_in[2]:

  cd=00:0
  cd=01:0
  cd=11:1
  cd=10:0

  When c=0: 0
  When c=1: output = d (actually d=1 for cd=11, d=0 for cd=10)

  So mux controlled by c: 0 or d

- mux_in[3]:

  cd=00:1
  cd=01:0
  cd=11:1
  cd=10:1

  When c=0: output = ~d (since d=0->1, d=1->0)
  When c=1: 1

Use mux on c to select between ~d and 1.

Use only 2-to-1 muxes (not operators) to build these functions.

Implementation plan:

1) Define a 2-to-1 mux module "mux2" with inputs sel, in0, in1, output y.

2) Build the four functions using mux2 and constant wires (0 or 1).

3) In TopModule, instantiate mux2 modules as needed to build each mux_in[i].

This modular approach uses a single small mux2 primitive and builds the entire input vector mux_in.

This matches the problem requirement: use one 4-to-1 mux (outside our module) and build the inputs with 2-to-1 muxes only, no other logic gates.

Since only c,d inputs and constants are used, the total number of mux2 instances will be minimal.

Note: We will not implement the external 4-to-1 mux; we only build mux_in[3:0] as required.
