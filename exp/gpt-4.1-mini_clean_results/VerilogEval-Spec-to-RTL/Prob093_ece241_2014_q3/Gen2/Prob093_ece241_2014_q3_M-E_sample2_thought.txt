Use the inputs c and d to generate the four 1-bit inputs mux_in[3:0] needed for the 4-to-1 mux controlled by a,b, so that the overall function implements the K-map.

Since only multiplexers (1 4-to-1 and any number of 2-to-1 muxes) are allowed, no direct logic gates, we will build each mux_in bit only using 2-to-1 muxes with inputs c or d as selectors.

We create a parameterized 2-to-1 mux function inline (using a function or ternary operator).

Plan for each mux_in bit:

- mux_in[0] = values for ab=00 from K-map: c d -> out
  00:0, 01:1, 11:1, 10:1
  Logic: out = d OR c (since all except 00 are 1)
  Using muxes:
    mux1 = mux(d, 0,1) => d (since d=0->0,1->1)
    mux0 = mux(c, mux1, 1) => if c=0 then mux1 else 1
  So out = c ? 1 : d

- mux_in[1] = ab=01: all 0, so assign 0 directly.

- mux_in[2] = ab=11: c d -> out
  00:0,01:0,11:1,10:0
  Logic: out = c & d
  Using muxes:
    mux = mux(d, 0, c) => if d=0 then 0 else c

- mux_in[3] = ab=10: c d -> out
  00:1, 01:0, 11:1, 10:1
  Let's derive a mux-only expression.

From truth table:

c d | out
0 0 | 1
0 1 | 0
1 0 | 1
1 1 | 1

Try to write out in mux form:

- When c=0:
  out = ~d  (since out=1 when d=0, out=0 when d=1)
- When c=1:
  out=1

So implement out = c ? 1 : ~d

Implement ~d using mux(d,1,0).

No direct NOT allowed, so use mux with d as selector:
  ~d = mux(d,1,0)

So,

mux_in[3] = c ? 1 : ~d

Overall, this approach uses no direct gates, only muxes with inputs c or d as selectors, and constants 0 or 1.
