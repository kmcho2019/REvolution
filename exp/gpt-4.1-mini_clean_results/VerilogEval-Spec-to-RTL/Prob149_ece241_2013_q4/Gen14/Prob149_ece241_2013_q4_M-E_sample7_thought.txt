Implement a level-based FSM that explicitly encodes water levels as a 2-bit state: BELOW (0), LOW (1), MID (2), ABOVE (3) corresponding to water below lowest sensor, between lowest and middle, between middle and highest, and above highest sensor respectively.

Determine level transitions strictly on clock edges by comparing the current sensor readings decoded into levels to the stored current level. On any level change, update previous level to the current level before changing current level.

Use a combinational function to decode the sensor input `s` into one of the four discrete levels by counting how many sensors are asserted from bottom up (e.g., sensors are arranged s[2] highest, s[1] middle, s[0] lowest). The water level is given by how many sensors are asserted starting from the bottom sensor upwards (e.g., 0 sensors asserted = BELOW, 1 sensor asserted = LOW, 2 sensors asserted = MID, 3 sensors asserted = ABOVE). This method naturally covers all sensor input patterns consistently.

Derive nominal flow rates from the current level by a combinational lookup table, which enables flow valves accordingly.

Detect water level rising transitions by comparing current and previous levels; if current level is greater than previous, assert the supplemental flow valve `dfr`.

On synchronous reset, initialize the state to BELOW level and all outputs asserted (flow valves and supplemental valve on), simulating a long low water level condition.

Outputs (fr2, fr1, fr0, dfr) are registered synchronously and updated every clock cycle, reflecting the current logic.

This approach ensures all sensor input combinations yield a deterministic water level, avoids ambiguous patterns, and cleanly implements flow control logic and supplemental flow control on rising water levels.
