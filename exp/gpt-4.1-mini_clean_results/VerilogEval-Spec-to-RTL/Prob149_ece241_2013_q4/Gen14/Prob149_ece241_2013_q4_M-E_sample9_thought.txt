Use a clean enumeration of the water level as 0 to 4 representing the number of sensors asserted (0: no sensors asserted, i.e., below lowest; 3: all sensors asserted, i.e., above highest). The sensors s[2:0] indicate which sensors are wet (1 = sensor covered by water). Since sensors are placed vertically, the water level can be interpreted as the count of consecutive asserted sensors starting from the bottom s[0]:

- Level 0: no sensors asserted (below s[0])
- Level 1: only s[0] asserted (between s[1] and s[0])
- Level 2: s[0] and s[1] asserted (between s[2] and s[1])
- Level 3: all s[0], s[1], s[2] asserted (above s[2])

Ignore any invalid or non-consecutive sensor patterns by determining the level as the highest consecutive chain from the bottom. For example, if s = 3'b010 (only s[1] asserted), treat as level 0 for safety (below lowest).

Keep a register of previous level and current level, updated synchronously each clock cycle.

Determine nominal flow outputs fr2, fr1, fr0 from current level:

- Level 3 (above s[2]): all flows off (fr2=0, fr1=0, fr0=0)
- Level 2 (between s[2] and s[1]): fr0=1 only
- Level 1 (between s[1] and s[0]): fr0=1, fr1=1
- Level 0 (below s[0]): fr0=1, fr1=1, fr2=1

For supplemental flow valve (dfr): assert it whenever water level rises compared to previous level. This means: dfr = 1 if current level > previous level; else 0.

Use a synchronous active-high reset to set previous and current level to 0 (below lowest) and all flows including dfr to 1, representing maximum flow at low water level as if low for a long time.

All outputs are registered synchronous outputs.

This approach simplifies sensor decoding by counting consecutive asserted sensors from bottom, handles partial or invalid sensor states safely as below level 0, and makes flow decisions accordingly.
