The design will track the current water level based on the 3-bit sensor input `s` (each bit representing a sensor) and the previous water level to detect changes. The water level categories are:

- Above s[2]: all sensors asserted (s[2]=1)
- Between s[2] and s[1]: s[2]=0, s[1]=1 (s[0] can be either 0 or 1)
- Between s[1] and s[0]: s[1]=0, s[0]=1
- Below s[0]: no sensors asserted

We can encode these as states:

- STATE_ABOVE = 3 (s[2]=1)
- STATE_BETWEEN_21 = 2 (s[1]=1, s[2]=0)
- STATE_BETWEEN_10 = 1 (s[0]=1, s[1]=0)
- STATE_BELOW = 0 (no sensors)

On each clock, sample the sensor input and determine the current state. Compare with the previous state. If the state increased (e.g. from BELOW=0 to BETWEEN_10=1), it means the water level rose, so supplemental flow valve (dfr) opens. Otherwise, dfr=0.

Set flow valves according to nominal flow table:

- Above s[2]: fr0=fr1=fr2=dfr=0
- Between s[2] and s[1]: fr0=1, fr1=fr2=0
- Between s[1] and s[0]: fr0=fr1=1, fr2=0
- Below s[0]: fr0=fr1=fr2=1

Reset sets the outputs to the BELOW state with supplemental valve open (fr0=fr1=fr2=dfr=1).

All outputs updated synchronously on rising edge of clk.

Note: We define state encoding as integer for comparison ease.
