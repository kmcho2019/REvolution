A clean solution is to store the previous water level explicitly as a state register, updated only on a sensor change. On each clock cycle:

- We compare the current sensor input `s` with the previous sensor input stored in `prev_s`.
- If the sensors have changed, we update `prev_level` to the level decoded from `prev_s` (the sensor state before the change).
- Then update `prev_s` to the new sensor input `s`.

This ensures `prev_level` always holds the level before the last sensor change.

The outputs `fr0`, `fr1`, and `fr2` are generated combinationally from the current input `s` decoded level, and `dfr` is asserted if the current level is strictly higher than `prev_level` indicating the water level has risen.

On reset, we initialize `prev_s` and `prev_level` to the lowest level (no sensors asserted), and assert all outputs (`fr0`, `fr1`, `fr2`, `dfr`) to 1, corresponding to the maximum flow valve state.

This simple sequential update with a single previous sensor register avoids any handshake complexity and ensures correct "previous level" tracking and flow rate outputs.

Additionally, any unexpected sensor patterns (other than `000`, `001`, `011`, `111`) will be treated as the lowest level (0) for safety.
