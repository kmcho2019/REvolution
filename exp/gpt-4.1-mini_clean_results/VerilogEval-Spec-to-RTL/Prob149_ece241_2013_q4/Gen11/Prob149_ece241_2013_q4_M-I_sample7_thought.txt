To correctly implement dfr according to the spec, we must explicitly detect water level changes only when the decoded sensor input changes to a new stable water level. We will track the previous stable level before this change and compare it with the new stable level. Only on a genuine water level change event will we update dfr, setting it to 1 if the water level rose (new_level > old_level), else 0. Between changes, dfr holds its previous value. This eliminates spurious toggling of dfr on stable inputs or transient inputs.

The approach involves:
1. Decode the water level from sensors.
2. Maintain a register for the last stable water level (`stable_level`).
3. On each clock, compare the new decoded level with `stable_level`.
4. If changed, update `prev_level` to the old `stable_level`, update `stable_level` to the new level, and update dfr accordingly.
5. If not changed, hold all registers and outputs steady.
6. Generate nominal flow rate outputs combinationally from `stable_level`.

This meets the spec of using the level previous to the last sensor change for dfr and ensures dfr changes only on level transitions. The reset initializes the system to BELOW_S0 with all outputs asserted, consistent with the problem statement.

This more explicit stateful tracking removes glitches and race conditions in dfr and ensures clean timing behavior.
