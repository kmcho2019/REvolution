Instead of computing all 256 cells' neighbors combinationally in one big nested loop, implement a shift-register based line buffer approach to process the grid one row at a time per clock cycle. Maintain three 16-bit rows as registers representing the "previous", "current", and "next" rows of the toroidal grid. For each clock cycle, compute the next state of one row using these three rows, shifting through columns serially within the cycle.

This approach serializes the computation: at each clock edge, compute and store one updated row in a temporary buffer, advancing the row pointers in a cyclic manner every 16 cycles. After 16 cycles, the entire 16x16 grid is updated and stored back in a 256-bit register. If `load` is asserted, the full 256-bit input is loaded immediately.

Because 16x16 = 256 cells and computation is now done over 16 cycles (one row per cycle) using simple logic for neighbor count of 8-bit cells, this reduces combinational logic complexity per clock cycle, improving timing and reducing power.

Edge wrap-around is handled by rotating the row indices modulo 16 and the column neighbors by rotating bits in the 16-bit row registers.

This method trades latency (16 clock cycles per generation) for better PPA and a simpler, smaller logic footprint. The output `q` updates once every 16 cycles, except immediately on load. The module signals ready state every 16 cycles for possible synchronization (optional).

This design is a classic line-buffer streaming approach to Conway's Game of Life in hardware.
