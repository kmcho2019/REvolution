Implement a pipelined architecture to improve timing and reduce combinational complexity. Instead of computing all 256 cells' next states combinationally in a single cycle, split the computation across multiple cycles by processing one row per clock cycle.

Maintain an internal 16x16 register array representing the grid state. On load, synchronously load the entire 256-bit data into the register array.

Then, each clock cycle (when not loading), update one row of the grid according to the rules by computing its next state using the currently stored rows: the previous row, current row, and next row (with wrap-around), enabling correct neighbor calculation with wrapping on rows. For each cell in the row, sum the eight neighbors using modular indexing on columns with bit masking (since width=16). This restricts complex combinational logic to just one row (16 cells) per cycle, greatly reducing combinational depth and improving max frequency.

Over 16 cycles, all rows update once, completing a full step of the game. The output q is continuously updated by concatenating the internal 2D register array. This trades throughput (16 clock cycles per full update) for improved performance and power efficiency by limiting combinational logic per cycle.

This approach also allows simplified indexing, reduces power from toggling all cells combinationally every cycle, and decreases area by reusing the same combinational logic for each row sequentially.

An additional row counter register manages the current row being updated. The design is fully synchronous and easily synthesizable.
