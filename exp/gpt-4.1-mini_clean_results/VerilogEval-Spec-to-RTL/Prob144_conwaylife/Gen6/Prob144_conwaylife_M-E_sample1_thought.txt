Implement a pipelined update engine that processes the grid row-by-row each clock cycle instead of all at once. Use a small internal 16-bit register to hold one row of the grid and buffer the rows above and below it to calculate neighbors with wrap-around. At each clock cycle:

- If load is high, synchronously load the entire 256-bit data into internal memory.
- Otherwise, update only one row of the grid per clock cycle by computing the next state of that row based on the previous, current, and next rows (with wrap-around).
- Store the entire grid as a 16-word memory array (each 16 bits representing a row).
- Maintain a row index that increments each clock cycle modulo 16 to process the entire grid in 16 cycles (one row per cycle).
- Output the entire 256-bit grid by concatenating all rows.
  
This approach spreads the combinational logic over multiple cycles, drastically reducing the combinational path length per cycle, improving timing and area. Since we update only one row per clock, power is also reduced.

Wrap-around neighbors are handled by reading row indices modulo 16. Neighbor count is computed by bitwise shifts and adds on 16-bit row data for previous, current, and next rows.

This method pipelines the Game of Life update across rows, trading throughput latency (16 cycles per generation) for improved PPA and a clean synchronous interface.
