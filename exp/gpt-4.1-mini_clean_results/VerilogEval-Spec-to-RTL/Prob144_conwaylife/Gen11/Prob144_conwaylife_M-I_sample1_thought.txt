To improve PPA (performance, power, area), the main bottleneck is the large combinational logic that calculates the neighbor sums with nested loops and a function call for wrapping indices, creating a long critical path and large fan-in.

Optimization strategy:
- Replace the function call wrap_index with explicit modular arithmetic using bitwise AND with MASK (15) for fast wrap-around, which synthesis tools handle more efficiently.
- Precompute all row indices wrapped using masks once per iteration to reduce repeated calculations.
- Use an array of partial sums to accumulate neighbors for each cell, performing addition via explicit summation instead of increments inside nested loops, thus reducing the synthesis fan-in.
- Flatten the neighbor addition to sum the eight neighbors by directly indexing cells without nested loops to reduce complexity and improve synthesis.
- Avoid recomputing repeated indices.
- Maintain a fully combinational next_q to avoid registers for intermediate values, enabling a single clocked register update stage.
This will reduce the combinational path delay (better timing), reduce switching (improves power slightly), and produce simpler logic (smaller area).

The functionality remains unchanged; only indexing and summation methods are refactored for better synthesis and PPA.
