Implement the 16x16 toroidal Conway-like game using a pipelined approach that updates one row of the grid per clock cycle instead of the entire 256-bit grid simultaneously. This reduces combinational logic complexity and critical path delay. The module holds the entire 16x16 state internally and uses a row counter to track which row is being updated each cycle.

At each clock cycle:
- If load is asserted, load the entire 256-bit data into the internal grid state and reset the row counter.
- Otherwise, compute the next state for a single row based on the current entire grid state, and update only that row in the internal state.
- Increment the row counter modulo 16.
- Output the complete updated grid state.

The neighbor counting for a single row is combinational and only involves 16 cells, reducing logic depth per cycle by serializing updates over 16 cycles per generation step. This pipelining trades latency for improved timing and area.

Wrapping indices use bit masking for modulo 16 operations (`& 4'hF`).

This design supports continuous game evolution every 16 clock cycles, with synchronous load overriding the current state.

Advantages:
- Much shorter critical path since only one row is computed per clock.
- Smaller combinational logic reduces power and area.
- Output q always reflects current full state.

Disadvantages:
- One full update step of the whole grid takes 16 cycles.
- Latency between loading and first full update is up to 16 cycles.

This approach is novel compared to fully combinational next state calculations for the entire grid each clock cycle.
