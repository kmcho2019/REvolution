To improve PPA, split the combinational neighbor counting into a two-stage pipeline:

- Stage 1 (clock cycle N): For each cell, compute the number of alive neighbors (neighbor count only, store as 4-bit value).
- Stage 2 (clock cycle N+1): Apply the Game of Life rules using the neighbor count and current cell state to compute the next state.

This reduces the combinational path delay each cycle since the neighbor counting is done independently before rule application.

Implementation details:

- Add a pipeline register neighbor_count (16*16*4 bits) to store counts.
- At each clock edge:
  - If load is high, load data directly into q and clear neighbor_count.
  - Else if pipeline stage 1: compute neighbor counts from q (previous state) and store in neighbor_count.
  - Else if pipeline stage 2: use neighbor_count and q to compute next_q and update q.

- Use a 1-bit state flip-flop to track pipeline stage (neighbor counting or state update).
- This trades 2-cycle latency for halving combinational path each cycle.
- The load signal resets pipeline to stage 1.
- Index wrapping still done by masking.
- Neighbor counting is simpler combinationally; next state computation only uses neighbor_count and q bits.

This pipelined approach greatly improves timing by splitting complex logic into stages, reducing critical path and allowing higher clock frequency.

Code uses nonblocking assignments in sequential always block and blocking in combinational to adhere to good style.

All other interface and behavior remain the same.
