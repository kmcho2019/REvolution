To optimize PPA, I will slightly refactor the FSM encoding by separating walking direction and mode (walking/falling) into distinct registers, rather than packing them in one 2-bit register. This allows for simpler control logic with fewer bitwise operations and clearer combinational logic, potentially improving timing.

I will also remove the unnecessary double-check of both bump signals when both are asserted by simply inverting the direction if any bump occurs. This logic is simpler and equivalent since specification says bump on either side or both causes direction flip.

Digging state remains a separate flag. The next-state logic is flattened with clear priority:

1. If not ground -> fall (mode=fall), digging cleared

2. Else if falling and ground return -> walk, digging cleared

3. Else if walking and dig asserted -> start digging

4. Else if walking and bumped -> flip direction

5. Else retain state

This clearer prioritization reduces logic depth. Using separate reg for direction and mode simplifies decoding and output logic. The outputs are assigned directly from mode, direction, and digging.

This should improve the critical path and reduce toggling, improving timing and power, while area remains minimal.

Asynchronous reset remains active high, initializing to walking left, not digging.

This refactoring maintains identical functionality and output behavior.
