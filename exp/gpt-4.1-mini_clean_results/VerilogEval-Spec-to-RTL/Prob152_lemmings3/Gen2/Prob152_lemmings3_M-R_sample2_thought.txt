Refactor the FSM by separating the state and direction registers to simplify logic, while still implementing a Moore FSM. Use an enumerated walking/falling/digging state for the main FSM and hold direction in a separate registered variable. This cleanly separates state and direction updates, making transitions more explicit and easier to verify.

- Use a 2-bit state variable encoding only the activity: WALK, FALL, DIG.
- Use a 1-bit reg for direction: 0=left, 1=right.
- Outputs are generated from both state and direction registers.
- On reset, set direction to left and state to WALK.
- Next state and next direction are computed in combinational logic, prioritizing fall > dig > bump as before.
- Direction updates only on bump signals during walking state.
- State updates on clock edge from next state.
- Direction updates on clock edge from next direction.
- This separation clarifies and isolates direction updates from state updates, potentially reducing glitches or mismatches.

This structure still implements a Moore FSM since outputs depend only on registered state and direction. It also retains all problem requirements but uses cleaner modular logic that is easier to debug.
