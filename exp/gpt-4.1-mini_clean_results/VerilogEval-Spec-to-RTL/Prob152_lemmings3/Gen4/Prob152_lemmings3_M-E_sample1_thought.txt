Implement the TopModule FSM using a single 2-bit state register encoding both activity (walking, falling, digging) and direction (left/right) combined, avoiding separate direction registers. This simplifies state handling.

Define states explicitly as follows:
- WALK_LEFT (walking left)
- WALK_RIGHT (walking right)
- DIG_LEFT (digging left)
- DIG_RIGHT (digging right)
- FALL_LEFT (falling left)
- FALL_RIGHT (falling right)

On asynchronous reset, state = WALK_LEFT.

In each clock cycle (posedge clk or areset):
- If areset asserted, reset state.
- Else update state based on next_state computed combinationally.

In combinational logic for next_state:
- Priority order:
  1. If ground is lost (ground == 0) while walking or digging, transition to FALL with direction preserved.
  2. If falling and ground appears (ground == 1), transition to WALK with previous direction.
  3. If walking and dig==1 and ground==1, start digging in current direction.
  4. If walking and bump(s) occur (bump_left or bump_right), switch walking direction.
- While falling or digging, bumps do not affect direction.
- Direction is implicit in state, so switching is changing state to walking of opposite direction.
- Being told to dig while falling or falling while digging or bumps during fall or dig do nothing except falling has priority.

This method makes transitions and outputs straightforward: each state directly implies outputs (walk_left, walk_right, aaah, digging). No separate direction signals needed. Edge detection is avoided by directly sampling ground signal synchronously and using the current and previous state to deduce falling/landing conditions, which avoids complexity and ensures correct reaction timing without delay pipelines.

This architecture reduces risks of mismatched timing between ground changes and bump inputs, and integrates direction and activity into a single FSM encoding, simplifying logic and ensuring glitch-free outputs.
