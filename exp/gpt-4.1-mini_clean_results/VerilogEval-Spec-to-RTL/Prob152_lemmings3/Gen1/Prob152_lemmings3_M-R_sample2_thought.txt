Refactor the FSM by separating state and walking direction explicitly, with distinct signals for state (FALLING or WALKING) and direction (left/right). Maintain a digging flag separate from state, making outputs a direct function of these signals.

- Use an enumerated `state` for FALLING or WALKING.
- Use a 1-bit `dir` to track walking direction (0=left, 1=right).
- Use a 1-bit `digging` to track if currently digging.
- Use a 1-bit register `saved_dir` to remember walking direction before falling.
- On reset, state= WALKING, dir=left, digging=0.
- On each clock:
  - If reset, initialize.
  - Else:
    - If currently FALLING:
      - If ground=1, transition to WALKING, dir = saved_dir, digging=0.
      - Else remain FALLING.
    - Else (WALKING):
      - If ground=0, transition to FALLING, save current dir, digging=0.
      - Else if digging:
        - If ground=1, continue digging.
        - Else ground=0, start FALLING, digging=0.
      - Else if dig=1 and ground=1 and not digging, start digging.
      - Else if bumped (left or right), flip walking direction.
      - Else stay same.

Outputs:
- walk_left = WALKING and dir=0 and not digging.
- walk_right= WALKING and dir=1 and not digging.
- digging = WALKING and digging=1.
- aaah = FALLING.

This clear separation simplifies logic, avoids mixing walking direction inside state encoding, and separates digging as a flag. The saved_dir is updated only when transitioning to FALLING and used to restore walking direction after falling.

This also avoids confusion about next state encoding and separate digging flag. Logic is easier to read, outputs cleanly correspond to state variables, and FSM is easy to extend.
