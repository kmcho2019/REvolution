Simplify the FSM by encoding only the direction and mode (walking or falling), and use a single reg to represent the direction (0=left,1=right). Add a digging flag that is only set or cleared when walking on ground.

Use one state register encoding direction and mode:
- When ground is lost, switch to falling mode but keep saved direction.
- When ground returns, return to walking with saved direction.
- Direction changes only occur when walking and bumped.
- Digging starts only when walking on ground and dig=1, continues until ground disappears.
- Bumps and dig commands are ignored while falling or digging.
- The outputs are directly derived from the mode and direction.

This approach avoids a separate FSM state register and saved_dir, instead using one state reg with bits encoding direction and mode, reducing complexity and making saved direction inherent in state. The asynchronous reset sets to walking left, not digging, not falling.

This solution respects the priority: fall > dig > bump.

Outputs are one-hot (walk_left/walk_right/digging/aaah) from the state and digging flag.

Overall, this simplifies logic and state management, making it more concise while preserving functionality.
