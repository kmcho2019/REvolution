To improve the existing solution's PPA metrics, especially power and area, I propose the following optimizations:

1. **Simplify stable_ground detection**:  
   Instead of storing the previous ground value every cycle (which toggles even if ground is stable), use a simple synchronizer flip-flop only clocked when ground=1, minimizing unnecessary toggling. This reduces toggle rate on `prev_ground` and saves power.

2. **Simplify bump logic**:  
   Replace the multiple conditions for bump direction updates with a concise priority logic that directly computes the next direction without redundant checks, keeping it minimal combinational logic.

3. **Use synchronous reset**:  
   Replace the asynchronous reset with a synchronous reset to potentially improve timing closure, as it avoids asynchronous reset handling in state and direction registers.

4. **Optimize state encoding to one-hot**:  
   The current 2-bit encoding is area efficient but can have slightly slower decode paths. Switching to one-hot encoding (3 bits, one hot per state) can reduce combinational decoding, possibly improving timing with a minor area tradeoff (acceptable given small state count).

5. **Combine state and direction updates cleanly**:  
   Perform updates in a single always_ff block, with next-state and next-direction clearly computed combinationally.

6. **Clean code style**:  
   Minor style improvements for readability and clarity, including explicit default states and consistent naming.

These changes are expected to yield slightly better timing (by simplifying decoding and reset), reduced power (by gating toggling registers), and modestly better area/toggle reduction for the prev_ground state. Since this FSM is small, one-hot state encoding's area increase is negligible.

The functionality remains unchanged.
