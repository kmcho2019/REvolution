Refactor the design to clearly separate combinational and sequential logic. Make the prediction outputs purely combinational using the speculative GHR and PHT before update, so that the outputs immediately reflect the current state when `predict_valid` is high. Use synchronous always blocks only to update the PHT and GHR registers on the clock edge. Maintain two separate 7-bit GHR registers: `arch_ghr` for committed history and `spec_ghr` for speculative history. On each clock:

- If training is valid and mispredicted, update the PHT entry, restore both `arch_ghr` and `spec_ghr` to the `train_history` input (rollback).

- Else if training is valid (not mispredicted), update the PHT and update `arch_ghr` by shifting in the actual branch outcome (`train_taken`), and synchronize `spec_ghr` to this updated `arch_ghr` (commit).

- Else if only prediction is valid, update `spec_ghr` by shifting in the predicted bit (speculative update).

Outputs `predict_taken` and `predict_history` are driven combinationally from the current speculative state and PHT contents indexed by the XOR of `predict_pc` and `spec_ghr`. This matches the problem's requirement that outputs reflect the state before speculative update. On reset, initialize all states and PHT entries properly.

This refactoring clarifies timing: outputs reflect current state combinationally, updates to PHT and histories occur synchronously. Priority is given to training updates over prediction updates in updating `spec_ghr` and `arch_ghr` on the clock edge.
