To fix the timing and output update issues, we must ensure that all outputs (predict_taken and predict_history) are registered and updated synchronously on the clock edge. The prediction outputs must correspond to the PHT and GHR state of the *current* cycle when predict_valid was asserted.

Because the PHT is asynchronously read combinationally using the current GHR and pc (pc XOR GHR), we can generate the prediction *combinationally* each cycle, but must *register* the outputs on the clock edge when predict_valid is asserted. This aligns the output timing with the clock domain and removes timing mismatches.

In detail:

- Keep PHT as a reg array asynchronously indexed by pc XOR GHR.
- Create combinational wires for current prediction (taken bit from PHT entry).
- At the rising clock edge, if predict_valid is high, register the predicted taken and current GHR into outputs.
- The GHR updates synchronously at clock edge: priority to training misprediction recovery (restore GHR to train_history), else if predict_valid, shift in the predicted taken bit.
- Training updates PHT synchronously on clock edge.
- On async reset, initialize GHR, outputs, and PHT entries to default states.

This approach ensures:

- Outputs update only on clock edges synchronized with predict_valid, matching testbench expectations.
- Outputs reflect the prediction made with the GHR and PHT state before updating GHR.
- No combinational latches for outputs.
- Priority given correctly for GHR update on training mispredict.
- Training updates PHT without affecting prediction output in same cycle.

This aligns precisely with the problem specification and fixes the functional mismatches.
