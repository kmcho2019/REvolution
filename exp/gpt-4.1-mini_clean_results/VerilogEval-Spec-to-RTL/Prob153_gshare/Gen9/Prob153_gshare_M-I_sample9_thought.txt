The issue is that the `predict_history` output must reflect the global history register state *used* to make the prediction in the current cycle, which is the global history value *before* updating the speculative history (`ghr_spec`) at the clock edge. Currently, `predict_history` is directly driven by `ghr_spec`, which changes at the clock edge and therefore does not represent the history value at prediction time.

To fix this, we introduce a separate register `ghr_reg` that holds the committed global history, and a combinational wire `ghr_pred` which is the value used to index the PHT and output for prediction. We update `ghr_spec` on clock edge as before, but *prediction* logic uses the current `ghr_reg` (which is stable during the cycle) for indexing and outputting `predict_history`. At clock edge, `ghr_reg` captures the updated speculative history `ghr_spec`.

This separation ensures:
- Prediction always uses the stable committed history (`ghr_reg`) and sees PHT state before training updates.
- `predict_history` output matches the history used to compute the prediction.
- Global history updates properly reflect either recovery (on training misprediction) or speculative update (on prediction).

The pipeline stage calling prediction expects stable prediction outputs during the cycle; using `ghr_reg` guarantees this stability.

All other logic remains mostly unchanged, preserving training priority and correct saturating counter update.

This approach fully resolves the mismatch on `predict_history` and aligns prediction timing with the spec.

Also, reset initial PHT entries to weakly not taken (01) to avoid bias.
