To fix the main issues and match the spec precisely, we redesign the gshare predictor as follows:

1. **PHT Memory Read/Write:**
   Implement the PHT as a synchronous RAM with one read and one write port per cycle. Prediction and training can happen concurrently but for possibly different addresses. 

   We implement:
   - **Prediction port:** combinational read from PHT at index (predict_pc XOR global_history). Since PHT updates only on posedge clk, the prediction reads the *current* contents of PHT before training writes take effect (matching the spec timing).
   - **Training port:** synchronous write at posedge clk, updating PHT at (train_pc XOR train_history) if train_valid.

   Because there is only one PHT, and training and prediction can happen on different addresses, the prediction and training port addresses may differ. We use two separate read and write ports by modeling PHT as a dual-port memory (one combinational read port for prediction, one synchronous write port for training).

2. **Global History Register (GHR) Update:**
   - On each posedge clk:
     - If `train_valid` and `train_mispredicted`: restore GHR to `train_history` (flush the pipeline history to the known state after misprediction).
     - Else if `train_valid` and not mispredicted: update GHR by shifting in the predicted bit from the prediction that *would have been* made during the fetch (this must be the predicted bit for the instruction being trained). Since `predict_valid` might be 0, we conservatively update only if prediction valid. The predicted bit for training updates is obtained by re-reading PHT entry at (train_pc XOR train_history) *before* the training update, simulating the timing that training uses old PHT state.
     - Else if no training, but `predict_valid`: update GHR by shifting in the predicted bit from the prediction (from the predict port).
     - Else keep GHR unchanged.

   This priority order ensures training updates override prediction updates for GHR.

3. **Prediction Output:**
   - Prediction reads PHT combinationally using current global_history.
   - Output predict_taken as MSB of PHT counter.
   - Output predict_history as current GHR.

4. **Initialization:**
   - Asynchronous reset sets GHR to 0 and all PHT entries to weakly taken (2'b10).

5. **Saturating Counter Update Function:**
   - On training writes, update PHT entry saturating counter accordingly.

6. **Handling Simultaneous Predict and Train to Same Entry:**
   - Prediction reads before training writes (due to synchronous write), so predict_taken corresponds to state before training update, as spec demands.

Overall, this approach strictly follows the spec timing, resolves the issue of combinational PHT reads from a synchronous RAM, and correctly prioritizes GHR updates with clear, consistent timing.
