Refactor the design by separating combinational prediction logic and synchronous state updates more explicitly. Use a combinational block to compute the prediction outputs directly from the current speculative global history and the PHT contents, ensuring the prediction outputs represent the predictor state before any updates in the current cycle.

Implement the PHT as a synchronous RAM-like register array updated only on training events, while prediction accesses are purely combinational reads from the stored PHT entries indexed by pc xor speculative history.

Maintain two distinct global history registers:

- `ghr_commit`: updated synchronously with actual branch results (non-mispredicted trains).

- `ghr_spec`: the speculative history used to predict branches and updated synchronously on prediction or restored on misprediction recovery.

On the positive clock edge:

- If `areset` asserted, reset all registers.

- If `train_valid` and `train_mispredicted`, restore speculative history (`ghr_spec`) to `train_history`.

- Else if `predict_valid` (and no misprediction train), update speculative history by shifting in predicted taken bit.

- Also, if `train_valid` and not mispredicted, update committed history with actual branch outcome.

- Update PHT entry synchronously on training with saturating counter update.

This approach separates combinational prediction and synchronous state updates cleanly, explicitly ensures prediction output is stable and correct before updates, and carefully arbitrates history updates with training misprediction recovery prioritized. 

Additionally, drive `predict_taken` and `predict_history` combinationally without gating on `predict_valid`; this ensures stable outputs and aligns with typical predictor output behavior, avoiding potential simulation mismatches on deasserted `predict_valid`.

The saturating counter update function uses a non-blocking implementation to ensure proper PHT update semantics.

This structure improves clarity, avoids combinational reads of synchronous write ports inside clocked blocks, and matches timing requirements precisely.
