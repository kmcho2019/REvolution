The main problem with the original code is the order of updates for `train_ghr` and the recovery of `fetch_ghr` on a misprediction flush. Currently, `fetch_ghr` is assigned the old `train_ghr` value before `train_ghr` is updated to the flush history (`train_history`), causing `fetch_ghr` to recover incorrectly.

To fix this, I will first compute the *next* value for `train_ghr` in a temporary reg, then update both `train_ghr` and `fetch_ghr` from those computed values sequentially in the same always block. This guarantees that when flush happens, `fetch_ghr` is restored from the correct `train_history` state.

Also, I will reorder the logic to:

1. Compute the next `train_ghr` based on training inputs.
2. Update `pht` entry synchronously on training valid.
3. Update `fetch_ghr`:
   - If flush (`train_valid` & `train_mispredicted`), recover to the flush history (new `train_ghr`).
   - Else if prediction valid, update with predicted taken bit.
   - Else hold.

This clean sequencing ensures flush recovery uses fresh `train_ghr` value.

Additionally, minor improvements:
- Use nonblocking assignments carefully.
- Initialize PHT to weakly taken (2'b01) on reset as before.
- Keep prediction combinational reads outside always block for clarity.

This change fixes the timing bug around flush recovery and ensures correct prediction history and taken outputs after mispredictions, thus correcting the previous mismatch errors.
