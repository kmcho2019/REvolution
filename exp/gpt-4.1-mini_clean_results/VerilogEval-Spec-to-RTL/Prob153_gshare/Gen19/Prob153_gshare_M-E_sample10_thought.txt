I will implement a gshare branch predictor with a single global history register (ghr) and a pattern history table (PHT) of 128 two-bit saturating counters indexed by XOR of 7-bit PC and 7-bit global history. The key difference is to explicitly separate prediction read and training update stages with a two-stage pipeline:

- In the first stage (combinational), prediction inputs produce the predicted taken and current ghr (predict_history).

- Prediction results and prediction PC are registered for use in the next cycle to update ghr on clock edge.

- On the clock edge, if training is valid and mispredicted, ghr is restored to the train_history value (flush/recovery), overriding any predicted update.

- Otherwise, if prediction was valid in the previous cycle, update ghr by shifting in the prediction bit made in previous cycle.

- PHT updates happen synchronously on clock edge only if training is valid, updating the entry indexed by train_pc XOR train_history. The update uses saturating counter increment/decrement depending on train_taken.

This pipeline design explicitly delays the ghr update for predictions by one cycle (storing predicted taken bit), thus faithfully implementing the timing requirement that prediction updates ghr "at the next positive clock edge" and avoiding race conditions between train and predict updates on ghr.

Outputs predict_taken and predict_history are driven combinationally from current ghr and pht, reflecting the predictor state before updates at clock edge.

This method cleanly handles simultaneous train and predict requests. If train and mispredict coincide, ghr recovery overwrites prediction update at clock edge.

This approach provides a clear, deterministic update order, avoids combinational feedback loops, and complies exactly with the timing diagram described in the problem.

Additionally, initialize PHT counters to weakly taken (2'b10) on reset.

This new architecture decouples prediction generation from ghr update using pipeline registers, ensuring consistent, stable outputs and correct update precedence.
