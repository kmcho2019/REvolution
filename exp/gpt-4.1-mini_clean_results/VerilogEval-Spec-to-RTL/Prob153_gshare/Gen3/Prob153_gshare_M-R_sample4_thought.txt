Refactor the gshare predictor to separate the prediction-combinational logic from sequential updates more clearly by splitting the logic into two always blocks:
- Use a combinational block to compute prediction outputs based on the current GHR.
- Use a sequential block (on posedge clk or posedge areset) to update the GHR and PHT entries according to training and prediction inputs, prioritizing training misprediction recovery.

Key improvements:
- Use the combinational prediction result (`predict_taken_comb`) directly to update the GHR next cycle when no training misprediction occurs.
- Capture the prediction history output (`predict_history`) as the GHR before the prediction update, making sure it reflects the state *used* to make the prediction.
- Use non-blocking assignments in the sequential block to prevent update ordering issues.
- Keep PHT updates synchronized to the clock using sequential logic.
- For output signals, register prediction outputs on the clock edge so outputs are stable and aligned with pipeline timing.
- On reset, initialize GHR to zero and PHT entries to weakly not taken (01).

This separation improves clarity, functional correctness, and timing semantics, ensuring prediction uses correct GHR, GHR updates use current prediction results, and training updates the PHT and GHR appropriately.
