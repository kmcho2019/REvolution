Implement the gshare predictor with a separate "shadow" global history register (GHR) that tracks the actual committed branch outcomes updated during training, and a "speculative" GHR used for prediction. The key idea:

- Maintain two 7-bit GHR registers:
  - `ghr_shadow`: reflects the committed global branch history updated during training and misprediction recovery.
  - `ghr_spec`: speculative history updated only on predictions (predict_valid).
  
- The PHT is a 128-entry 2-bit saturating counter table indexed by PC XORed with the GHR used for that operation.

- Prediction:
  - For a prediction, use `ghr_spec` to compute the PHT index (predict_pc XOR ghr_spec).
  - Output prediction based on current PHT entry (combinational).
  - Output the current speculative GHR (`ghr_spec`) as `predict_history`.
  - On the next clock edge, if predict_valid and no misprediction training update that cycle, update `ghr_spec` by shifting in the predicted direction.

- Training:
  - Use train_history XOR train_pc to find the PHT entry and update it based on train_taken.
  - If train_mispredicted is asserted, restore `ghr_spec` to the supplied `train_history`, reflecting recovery of speculative state to correct history.
  - Independently, update `ghr_shadow` to track committed branch outcomes only during training (non-mispredicted).
  
- Priority:
  - On clock edge, if training misprediction occurs, restore `ghr_spec` to `train_history` (recover speculative history).
  - Else if prediction valid, update `ghr_spec` by shifting in predicted direction.
  - Always update PHT when train_valid is asserted.
  - Update `ghr_shadow` only when train_valid and no misprediction, shifting in train_taken.

- This decouples committed history (ghr_shadow) from speculative history (ghr_spec), improving clarity and correctness.

- Prediction outputs (`predict_taken`, `predict_history`) are purely combinational with respect to `ghr_spec` and PHT entries at the start of cycle, avoiding pipeline register complications.

- Initialize all counters to weakly not taken (01), and both GHRs to zero on async reset.

This architecture cleanly handles simultaneous training and prediction requests, provides correct priority handling, and outputs stable predictions and histories aligned with the predictor state at prediction time.
