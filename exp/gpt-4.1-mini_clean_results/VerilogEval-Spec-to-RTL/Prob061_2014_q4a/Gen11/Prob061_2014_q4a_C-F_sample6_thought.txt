The best aspects of both examples can be combined by using an explicit clock enable signal (clk_en = L | E) to reduce unnecessary register toggling and thus dynamic power while keeping the sequential logic clean with a single always @(posedge clk) block. Unlike example 1, this approach avoids gating the clock net directly by using a register enable (clk_en), which synthesis tools generally handle more efficiently. The next state logic (next_Q) is computed combinationally for clarity and to separate concerns, as in example 2. By doing so, we keep the register from updating when not needed (reducing power), maintain a clean separation of combinational and sequential logic, and provide clear priority (load over shift) in next_Q calculation. This fusion achieves improved timing, power, and area trade-offs by combining explicit enable control without complicated gated clocks and by clear, maintainable code structure.
