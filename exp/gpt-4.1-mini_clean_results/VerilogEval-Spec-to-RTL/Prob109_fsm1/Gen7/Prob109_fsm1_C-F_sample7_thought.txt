To fuse the best ideas from both examples, I will adopt the clear separation of next-state combinational logic from the sequential block as in Example 1, since this enhances readability and facilitates formal verification and potential optimization. I will keep asynchronous reset handling integrated with the state register update for proper hardware behavior.

From Example 2, the direct case statement for next-state logic is very readable and easy to modify, so I will encode the next-state logic combinationally with a case statement instead of nested ternary operators.

The output remains a continuous assignment purely reflecting the state, maintaining the Moore machine property.

Overall fusion strategy:
- Use reg for state and wire for next_state.
- Use a combinational always_comb block with a case statement for next_state.
- Use asynchronous reset and state update in an always @(posedge clk or posedge areset) block.
- Assign out directly from state.
- Use localparam for state encoding.

This balances clarity, modularity, and simplicity while preserving clean asynchronous reset logic and concise output encoding.
