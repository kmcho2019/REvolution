I will implement the Moore FSM using a separate combinational next_state logic block and a clocked process for state update with asynchronous reset. Instead of encoding states as parameters, I will use an enumerated type for improved readability. The output will be generated from the state in a separate always_comb block. This separates concerns clearly: combinational next state logic, sequential state update, and output logic, which can improve clarity and maintainability. The asynchronous reset will still be handled in the clocked process with posedge areset.
