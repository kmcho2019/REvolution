The original solution uses separate next_state logic and a Moore FSM output registered together with the state. Since there are only two states and the output depends directly on state and input, we can simplify by combining state and output updates in one always block without a separate next_state signal. We just keep a single state register and update it synchronously (with asynchronous reset). The output can be computed combinationally from state and input, then registered synchronously. This avoids separate next_state logic, making the code shorter and simpler while maintaining the Moore FSM behavior.
