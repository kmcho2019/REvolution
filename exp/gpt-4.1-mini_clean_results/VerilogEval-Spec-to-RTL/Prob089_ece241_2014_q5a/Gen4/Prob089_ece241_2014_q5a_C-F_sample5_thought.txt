Fuse the advantages of both examples by implementing a Moore FSM that registers the input bit each clock cycle and uses purely synchronous logic for state and output, ensuring glitch-free, stable output strictly dependent on registered signals and state.

From Example 1: Registering input (x_reg) stabilizes the input sampling and removes combinational dependency on asynchronous input, making output depend only on registered inputs and FSM state, meeting Moore FSM definition cleanly.

From Example 2: The output is also synchronous, registered on clock edge, with async reset. Using a typedef enum improves readability and makes state transitions explicit.

Fusion strategy:

- Use typedef enum for state clarity.
- Register input bit (x_reg) on every clock cycle with async reset.
- Use two states: WAIT_FOR_FIRST_ONE and INVERT_BITS.
- Update state synchronously at posedge clk or async reset.
- Derive next state from registered input x_reg, avoiding glitches.
- Output (z) is a registered Moore output, updated on clock or reset.
- On reset, state goes to WAIT_FOR_FIRST_ONE, x_reg and z cleared to zero.
- In WAIT_FOR_FIRST_ONE, output z = x_reg.
- In INVERT_BITS, output z = ~x_reg.

This fusion preserves Moore FSM purity, input registration for stability, and clean asynchronous reset handling, resulting in minimal, glitch-free logic with improved timing and power characteristics.
