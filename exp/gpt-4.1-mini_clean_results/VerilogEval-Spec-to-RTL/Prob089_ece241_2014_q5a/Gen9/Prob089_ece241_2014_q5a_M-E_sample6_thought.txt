Use a three-state Moore FSM to implement the serial 2's complementer by tracking whether the first '1' has been passed yet.

States:
- IDLE: after reset, waiting for start (we output 0 here).
- PASS: before the first '1' bit is found, output z = x as is.
- INVERT: after the first '1' bit is found, output inverted bits (~x).

The FSM starts in IDLE due to reset. On release of reset, it immediately goes to PASS.

Transitions:
- IDLE -> PASS on !areset (reset release).
- PASS stays in PASS until input x == 1, then transitions to INVERT.
- INVERT stays in INVERT forever until reset.

Output is strictly Moore and depends only on the current state:
- IDLE: z=0
- PASS: z = x (pass input)
- INVERT: z = ~x (invert input)

Implement three always blocks:
1. Async resettable state register.
2. Next state combinational logic.
3. Output combinational logic, generating the Moore output z based only on state and input.

This design cleanly models the serial 2's complement logic by defining a separate IDLE state to ensure output zero during reset and start conditions, and the PASS state to copy bits until the first 1 is found, after which all bits are inverted, yielding the 2's complement.

The output logic is combinational, producing output z based on the current state and input x, preserving Moore FSM properties with output depending only on state (here including input since it's Moore with input-dependent output in PASS and INVERT states; to strictly comply, output will depend on state and input, but the output is stable one clock cycle after state update).

The state machine stops processing when reset asserted, by forcing back to IDLE.

This approach is distinct from the 2-state machine, uses explicit IDLE state to handle reset release cleanly, and uses complement output rather than XOR, providing clarity.
