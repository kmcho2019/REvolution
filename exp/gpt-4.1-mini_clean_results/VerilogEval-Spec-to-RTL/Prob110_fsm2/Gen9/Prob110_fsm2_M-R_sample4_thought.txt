I will refactor the FSM implementation by using a one always block for both next-state and state update with a blocking assignment for next_state. The output will be registered along with the state, converting the output to a registered Moore output inside the sequential block, rather than a combinational assign. This way, the output changes synchronously with the state, reducing glitch possibility on output at the cost of one-cycle output latency. I will also use a case statement for next-state logic, illustrating a different structural style. The asynchronous reset remains the same.
