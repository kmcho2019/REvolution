To optimize the PPA metrics, I will simplify the design by making the output purely combinational, driven directly by the registered state. This reduces the number of flip-flops, decreasing area and power by avoiding unnecessary output register toggling.

Keeping the asynchronous reset on the state register preserves functionality. This change shortens the critical path because output logic no longer depends on next_state calculation or a registered output; instead, output updates immediately on state changes.

This approach maintains the Moore FSM structure (output depends only on current state), improves timing by reducing sequential stages on output path, lowers power by eliminating an output flip-flop, and reduces area slightly.

Hence, the improved design:
- Registers only the FSM state with async reset
- Computes next state combinationally from current state and inputs
- Computes output combinationally from current state
- Uses non-blocking assignments in sequential always block
