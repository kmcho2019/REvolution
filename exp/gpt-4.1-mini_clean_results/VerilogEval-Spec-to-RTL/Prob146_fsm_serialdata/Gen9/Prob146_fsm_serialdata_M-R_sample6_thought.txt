I will refactor the FSM to separate the state register update and the output logic clearly, and implement the FSM next-state and output signals using purely combinational always blocks with registered state and outputs updated synchronously. 

The main differences:
- Use an explicit next_state register and a separate output logic block instead of mixing output updates inside the sequential block.
- Keep done and out_byte registered outputs assigned in a separate always block driven by the clock, driven by combinational signals that represent done_next and out_byte_next.
- Shift data bits only when in RECEIVE state, using an explicit enable signal.
- Simplify done to be asserted for one cycle only when the stop bit is correctly detected.
- This clean separation improves code readability and makes FSM behavior more transparent.

Functionally, it is equivalent but with a clearer structure that distinguishes state transitions, output generation, and data shifting.
