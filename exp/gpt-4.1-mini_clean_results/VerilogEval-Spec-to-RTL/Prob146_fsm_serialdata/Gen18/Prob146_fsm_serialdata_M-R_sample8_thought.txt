I will refactor the FSM to use a one-hot style state encoding with three states to simplify next-state logic and make the state transitions more explicit. I will combine the data shift register and bit counting logic into a single sequential always block with clear control signals.

The done pulse will be generated combinationally based on the current and next state transition detecting a valid stop bit, and out_byte will be registered on the same clock edge for synchronous outputs.

Also, instead of using typedef enums, I will use `localparam` for state encoding with one-hot values for clarity and potentially easier synthesis.

The FSM states will be:

- IDLE: waiting for start bit (in==0)
- RECEIVING: shifting in 8 data bits, counting bits
- STOP_BIT_CHECK: check stop bit correctness, assert done if correct, otherwise wait until stop bit is valid.

If the stop bit is wrong, stay in STOP_BIT_CHECK until in==1 (stop bit correct).

This structure keeps the FSM behavior identical but clarifies states and separates combinational next-state and outputs from sequential registers cleanly.

The reset remains synchronous active high.

All sequential logic is triggered on the positive clock edge.
