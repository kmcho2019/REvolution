I will simplify the FSM by merging the STOP and WAIT_STOP states into one STOP state that checks the stop bit and waits for a valid stop bit before accepting the next start bit. This reduces state complexity from four to three states: IDLE, RECEIVE, and STOP. 

The FSM works as follows:
- IDLE: line idle at 1, wait for start bit (0).
- RECEIVE: shift in 8 data bits (LSB first).
- STOP: check stop bit; if valid (1), output byte and assert done, then return to IDLE; if invalid (0), stay in STOP until line returns to 1.

This approach retains full functionality but simplifies state transitions and code. All logic remains synchronous with reset, done is asserted one cycle on valid stop bit, and `out_byte` outputs correctly received byte.

We keep the 3-bit bit counter and an 8-bit shift register as before. Register updates happen only as needed to minimize toggling. The simpler FSM eases understanding and reduces hardware.

This minimal FSM suffices for the protocol without explicit WAIT_STOP state, as STOP state both verifies stop bit and waits for line to return idle before next byte.
