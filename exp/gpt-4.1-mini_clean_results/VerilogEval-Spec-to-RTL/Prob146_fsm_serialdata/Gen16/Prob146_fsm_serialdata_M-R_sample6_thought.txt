I will refactor the FSM by separating the state and output logic more explicitly and using a Moore FSM style where outputs depend solely on the current state. Instead of using a combinational always block for next_state and done_next, I will use one always block for next_state combinational logic and a separate always_ff block for state updates, and register done only when moving to IDLE after a correct stop bit. The data_shift register will be updated using an enable signal derived from the state machine. I will implement the bit counter with an explicit enable and clear signal. This modular approach improves clarity, makes control signals explicit, and simplifies reasoning about the FSM behavior while keeping the same functionality.
