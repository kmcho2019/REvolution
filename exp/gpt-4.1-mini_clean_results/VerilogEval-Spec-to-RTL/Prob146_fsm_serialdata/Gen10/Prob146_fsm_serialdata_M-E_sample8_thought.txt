I will implement a Moore FSM with five states: IDLE (waiting for the start bit), START_WAIT (validating the start bit timing), RECEIVE (shifting in 8 data bits LSB first), STOP_CHECK (validating the stop bit), and RECOVER (waiting for line idle if stop bit invalid). 

Instead of shifting bits into a register each cycle, I will use a parallel load technique by counting bits and assembling the byte by shifting the incoming bits at the correct count. This reduces logic toggling by controlling updates more precisely.

To detect the start bit, the FSM waits in IDLE while line is high. Upon detecting a 0 (start bit), it moves to START_WAIT, sampling the bit again to confirm it’s a valid start bit (helps filtering glitches). Then it moves to RECEIVE.

During RECEIVE, the module shifts in bits on each clock tick, counting 8 bits. After that, it moves to STOP_CHECK state, where it checks if the stop bit is 1.

If stop bit is valid, output byte and assert done one clock cycle. If not, enter RECOVER state and stay there until line is idle again (stop bit or line is 1).

A synchronous reset will clear all registers and return FSM to IDLE.

This design clearly separates bit counting and FSM states, limits shift register updates to when receiving bits, and adds start bit confirmation, improving robustness.
