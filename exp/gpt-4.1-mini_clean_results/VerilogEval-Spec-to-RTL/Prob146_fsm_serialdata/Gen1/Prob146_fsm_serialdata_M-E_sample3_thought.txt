Instead of an explicit FSM with multiple states, implement a shift-register-based serial receiver with a bit counter and a small control logic that implicitly tracks the frame phases:

- When idle (line is high), wait for start bit (in == 0).
- Once start bit is detected, start counting bits received (including data bits and stop bit).
- Shift data bits into a shift register on each clock after start bit.
- After 8 data bits are received, check the next bit for stop bit.
- If stop bit is correct (1), output data and assert done for one cycle.
- If stop bit is incorrect (0), discard current byte and keep sampling input until stop bit (1) is detected, then go idle again.
- Use a simple "state" flag (idle vs receiving) and counters, avoiding a traditional FSM enum.
- The synchronous reset initializes everything.
- done pulse is one clock cycle at successful reception.
This approach is simpler and uses a small bit counter with minimal states, inherently robust for this protocol.
