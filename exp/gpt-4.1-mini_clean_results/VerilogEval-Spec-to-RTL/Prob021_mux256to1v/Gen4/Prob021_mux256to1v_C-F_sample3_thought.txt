Fuse the clarity and modularity of hierarchical multiplexing from Example 2 with the simplicity and efficiency of a direct indexed part-select from Example 1. 

Specifically:
- Avoid unpacking the entire 1024-bit input vector into an intermediate 256-element array to save area and routing.
- Use two levels of hierarchical selection based on sel[7:4] and sel[3:0] to express the mux logically but implement these selections with calculated bit slicing to minimize case statements.
- Perform the first 16-to-1 selection by directly slicing the input vector using the lower 4 bits of sel, calculating the index offset for each group (16 inputs per group, each input is 4 bits), with the group selected by the upper 4 bits of sel.
- Then select the final 4-bit output from the 16 intermediate groups based on sel[7:4].
- Implement this with a generate block for the first stage to avoid large explicit case statements and use an always_comb (or always @(*) ) block for the final selection.
- This approach leverages arithmetic indexing and partial unpacking only for 16 intermediate wires, drastically reducing logic complexity, power, and area compared to fully unpacked or fully case-based implementations.
- The design remains fully combinational and synthesizable with minimal mux depth, improving timing and power efficiency compared to the large flat case approach.

This fusion combines modular clarity and strong PPA benefits, making the code scalable and efficient.
