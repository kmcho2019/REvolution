I will refactor the design by implementing the timer using a single register to store the counter and a procedural block for both loading and decrementing, but this time explicitly use an `if-else` statement inside the sequential `always` block to handle the load and decrement operations. Instead of computing `next_counter` combinationally, the logic for loading and decrementing will be directly embedded in the sequential process. The terminal count output (`tc`) will still be combinationally derived from the register value. This structure keeps the single-register constraint but changes the style from a combinational next-state approach to a straightforward sequential conditional update, improving code clarity and better matching a typical FSM style.
