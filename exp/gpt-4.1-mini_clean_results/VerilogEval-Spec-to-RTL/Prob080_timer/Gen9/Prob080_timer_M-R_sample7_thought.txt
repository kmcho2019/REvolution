Refactor the timer by implementing the counter as a register updated inside an always block that explicitly checks for the load condition first, then counts down if not zero, otherwise remains at zero. Instead of using a combinational wire for next_counter, integrate the logic directly in the sequential always block. The terminal count (tc) is still driven by combinational logic checking if the counter is zero.

This approach maintains a single register but expresses the behavior as a straightforward procedural state update, making the control flow clear and potentially easier to adapt for additional states or logic. It also clearly avoids unnecessary decrement operations when the counter is zero by explicitly checking it before decrementing.

This style is common and can be more intuitive to some designers, trading off a slight increase in verbosity for clarity in control structure and direct state update inside the clocked block.
