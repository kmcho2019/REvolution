Instead of continuously shifting bits into a pattern register to detect the start pattern 1101, use a small dedicated shift register updated every clock cycle, and compare its content against the pattern. When matched, enter a state to load exactly four bits sequentially as the delay value, reading MSB first by shifting in each bit on the MSB side.

Once the delay is loaded, implement the timer using two counters:

1. A "segment" counter initialized to delay + 1, representing how many 1000-cycle segments remain.

2. A 10-bit "cycle" counter counting from 999 down to 0 per segment.

On each clock cycle during counting, decrement the cycle counter; when it reaches zero, decrement the segment counter. When the segment counter reaches zero and cycle counter zero, counting is done.

Outputs:

- `count` reflects the current segment count - 1 (0-based) as delay countdown, matching problem spec: output shows delay for 1000 cycles, delay-1 for 1000 cycles, ..., down to 0 for 1000 cycles.

- `counting` is asserted during counting.

- `done` asserted when counting finishes, until acknowledged.

FSM states:

- IDLE (searching for start pattern)

- LOAD_DELAY (loading 4 bits into delay reg)

- COUNT (counting down segments and cycles)

- WAIT_ACK (done asserted, waiting for ack)

Using two counters avoids costly division, and cleanly models the timer in discrete steps. The delay loading and pattern detection are done with separate registers to avoid confusion.

All logic is synchronous with positive clock edge and synchronous reset.

This clear separation and counting approach provides a robust, easy-to-debug timer, with outputs changing only at clock edges.
