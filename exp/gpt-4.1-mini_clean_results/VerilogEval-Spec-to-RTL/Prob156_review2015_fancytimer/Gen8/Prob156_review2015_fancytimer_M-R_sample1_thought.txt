Refactor approach:

1. Use a more modular and clearer FSM design with one always block for state and sequential updates and separate combinational always block for next-state and output logic.

2. Use a shift register for pattern detection that shifts bits into MSB first (shift right, new bit into MSB) to match the "1101" pattern detection MSB first.

3. Similarly, for delay loading, shift delay bits MSB first (shift right, new bit into MSB) per spec.

4. Pattern detection only active in the IDLE state; delay loading only in DELAY_LOAD; data ignored in COUNTING and DONE states.

5. Make the counting mechanism clearer:
   - Use a 10-bit cycle counter counting 0 to 999 for cycles per block.
   - Use a 4-bit block counter counting down from (delay+1) to 0, decrement only on cycle_counter rollover.
   - Only decrement block_counter if it is not zero.
   - Transition to DONE state only after block_counter reaches 0 and cycle_counter finishes its 1000 cycles (cycle_counter=999).

6. Keep outputs as registered signals driven by state and counters.

7. Remove conflicting multiple writes to block_counter in different always blocks by consolidating them in the main sequential always block.

8. Synchronous reset clears all registers and puts the FSM in IDLE.

This approach provides clear and correct sequencing of detection, loading, counting, and done/ack handling, while following the timing and shift directions requested.
