Implement a two-phase approach using a clearly staged FSM with explicit signal separation:

1. Use a 4-bit shift register that continuously shifts in input data bits only when searching for the start pattern 1101. This keeps detecting the pattern reliably.

2. When the pattern 1101 is detected, transition to a "LOAD_DELAY" state where we shift in the next 4 bits MSB-first into a delay register.

3. To shift MSB-first correctly, start loading bits into delay_reg[3] down to delay_reg[0]. We'll use a 3-bit counter from 3 down to 0 to track which bit to load.

4. Once all 4 bits are loaded, move to the COUNT state:

   - The total delay cycles = (delay + 1) * 1000 cycles.

   - Use two counters: 
     - segment_counter (4-bit) initialized to delay + 1 (the number of 1000-cycle segments remaining)
     - cycle_counter (10-bit) counts from 0 to 999 cycles within each segment.

5. The output 'count' always shows the current remaining segments minus 1, i.e. segment_counter - 1 (since the problem wants delay value, then delay-1, ... to 0). 

   So when segment_counter is N, count = N - 1.

6. Each time cycle_counter reaches 999, decrement segment_counter.

7. When segment_counter reaches zero (finished counting), transition to DONE state.

8. In DONE state, assert done signal and wait for ack input from user.

9. On ack, return to SEARCH state, reset all counters, and resume scanning for the pattern.

This architecture clearly separates pattern detection, delay loading, counting, and done/waiting states with simple counters. It ensures MSB-first loading, exact delay+1 segments counting, proper output timing, and no ambiguity in outputs during states.

Also, use synchronous reset active high, state transitions on posedge clk.

All signals and registers will be named clearly to avoid confusion.
