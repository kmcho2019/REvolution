I will implement a four-state FSM that processes the serial input as follows:

1. IDLE: continuously shift in data bits into a 4-bit shift register for pattern detection. When the pattern 1101 is detected, transition to LOAD_DELAY.

2. LOAD_DELAY: shift in 4 bits MSB first over 4 clock cycles to form a delay value. Once complete, initialize a 10-bit cycle counter (counts 0 to 999) and a 4-bit remaining delay counter set to delay value, then move to COUNT.

3. COUNT: count clock cycles up to 1000 per delay step. After each 1000 cycles, decrement the remaining delay counter. The counting lasts exactly (delay+1)*1000 cycles, so counting continues while the remaining delay counter is >= 0. Output the current remaining delay on count output and assert counting=1. Once counting completes (remaining delay counter < 0), de-assert counting and assert done, then wait for ack to reset.

4. DONE: assert done=1 and wait for ack=1 input. Once ack is detected, go back to IDLE to search for the next pattern.

Key points:

- The pattern shift register holds last 4 bits for pattern detection, shifting in each clock when in IDLE.

- Delay is loaded MSB first into a 4-bit register during LOAD_DELAY.

- The count output reflects the current remaining delay step, held steady during each 1000-cycle interval.

- The cycle counter counts from 0 to 999 for each 1000-cycle segment.

- Synchronous reset resets FSM and all registers.

This approach cleanly separates pattern detection, delay load, counting, and done acknowledgment phases and precisely controls the timer duration as (delay+1)*1000 cycles.
