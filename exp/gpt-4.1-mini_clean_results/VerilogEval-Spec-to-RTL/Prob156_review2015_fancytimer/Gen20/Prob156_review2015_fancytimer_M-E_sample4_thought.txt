This solution implements the required timer using a Moore-style finite state machine with five states:

1. **PATTERN_DETECT**: Continuously shift in the serial `data` bit into a 4-bit shift register each clock cycle. When the pattern `1101` is detected, move to the DELAY_LOAD state.

2. **DELAY_LOAD**: Shift in 4 bits (MSB first) that specify the delay value. A 3-bit counter tracks how many delay bits have been loaded. Once 4 bits are collected, transition to COUNT.

3. **COUNT**: Use two counters:
   - A cycle counter counts down from 999 to 0 to define 1000 clock cycles per delay unit.
   - A segment counter counts down from `(delay + 1)` to 0 to define how many 1000-cycle segments remain.
   
   At each clock:
   - decrement the cycle counter;
   - when cycle counter reaches zero, decrement the segment counter and reload cycle counter to 999.
   
   Output `count` equals the current segment counter minus one (remaining delay count in 1000-cycle units).
   
   Assert `counting` during this state.

4. **DONE_WAIT_ACK**: When counting is complete (both counters zero), assert `done` and wait for user `ack` to be asserted.

5. **RESET_TO_PATTERN**: After `ack` is received, reset the state machine back to PATTERN_DETECT for the next timer run.

This design cleanly separates the pattern detection from delay loading and counting phases. It freezes pattern detection during delay loading and counting. It uses synchronous reset and all registers update on clock rising edge.

Outputs:
- `count`: valid only during COUNT state; otherwise zero.
- `counting`: high during COUNT.
- `done`: high during DONE_WAIT_ACK.

This approach emphasizes clear state separation and precise counting intervals, avoids off-by-one errors, and ensures the timer waits for user acknowledgment before restarting.
