I will implement a modular FSM that cleanly separates concerns:

1. Pattern detection will be done with a 4-bit shift register that continuously shifts in the `data` input each clock cycle in the SEARCH state.

2. Upon detecting the pattern `1101`, the FSM transitions to LOAD_DELAY state, where it will shift in exactly 4 bits of delay, MSB first, using a 3-bit counter (counts 0 to 3).

3. Once delay is fully loaded, the FSM will move to COUNTING state, where the timer runs for `(delay + 1) * 1000` clock cycles. To efficiently track this, the module uses two counters:
   - a 10-bit sub-counter to count from 0 to 999 (to count 1000 cycles blocks)
   - a 4-bit remaining counter initialized to delay + 1, decremented each time the sub-counter reaches 999

4. Output the remaining time as the number of 1000-cycle blocks still to count minus 1 (since it counts down to zero). For each 1000-cycle block, the count output remains stable. When not counting, count output is don't-care (will set to 0).

5. Once counting completes (remaining counter is zero and sub-counter reached 999), output done=1 and wait for ack=1 to return to SEARCH.

6. Use synchronous reset to start in SEARCH with all registers cleared.

This approach cleanly defines states and counters, avoids complicated combinational logic between multiple always blocks by consolidating state and counters into a single always @(posedge clk) block. It initializes the remaining_ticks to delay + 1 at LOAD_DELAY end, ensuring exact timing. All outputs are synchronous and stable.

The outputs:
- counting: asserted only in COUNTING
- done: asserted only in DONE_WAIT
- count: outputs remaining_ticks - 1 during counting, else zero

This design follows the problem requirements, is fully synthesizable, and easy to verify.
