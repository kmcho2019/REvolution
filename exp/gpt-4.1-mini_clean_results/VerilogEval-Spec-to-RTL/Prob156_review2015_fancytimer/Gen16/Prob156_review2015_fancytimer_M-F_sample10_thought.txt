To fix the functional issues, the following key points are addressed:

1. **Pattern Detection Alignment:**  
   Since the serial input is MSB-first, the leftmost bit received is the most significant. To detect the pattern `1101` correctly, the shift register must insert the new bit at MSB and shift right, or keep shifting left and insert at MSB with the new bit at MSB.  
   The easiest is to shift left and insert the new bit at LSB, but then the pattern to compare is reversed. Alternatively, shift right and insert at MSB so the bits accumulate in order.  
   We will shift the pattern register right, insert new bit at MSB (since data arrives MSB-first), so the pattern forms left to right as bits arrive, then compare with `4'b1101`. This ensures correct pattern detection.

2. **Delay Loading Consistency:**  
   Similarly, delay bits are shifted in MSB-first order. Use the same shift direction as for the pattern: shift right, insert new bit at MSB. This ensures `delay_reg` holds the delay value correctly.

3. **Counting Logic with Precise Cycle Duration:**  
   Use two counters:  
   - `cycle_counter` counts from 0 to 999 (inclusive), representing each 1000 cycles per tick.  
   - `tick_counter` counts the remaining ticks (delay + 1).  
   On the last cycle of each tick (`cycle_counter == 999`), decrement `tick_counter`. When `tick_counter` reaches 0 after decrement, counting is done.  
   The `count` output shows the current remaining tick count minus one, stable for all 1000 cycles of that tick (i.e., count = tick_counter - 1 when tick_counter > 0, else 0).  
   This removes off-by-one errors by updating `tick_counter` and `count` synchronously and cleanly.

   Use a combinational FSM for next state and synchronous updates, as before. Initialize `tick_counter` and `count` at the DELAY_LOAD->COUNT transition properly.

5. **Reset and Output Signal Initialization:**
