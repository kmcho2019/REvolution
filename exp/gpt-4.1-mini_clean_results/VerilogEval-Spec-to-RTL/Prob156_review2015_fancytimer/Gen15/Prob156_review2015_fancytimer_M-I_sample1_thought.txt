To fix the functional issues:

1. **Correct Pattern Detection Shift Direction:**  
   The problem states bits come in MSB-first order for both pattern and delay. For pattern detection, shift left (<<) and insert the new data bit at LSB. After four bits, pattern_shift[3:0] will hold the pattern in order with MSB first in bit 3 and LSB first in bit 0. Then compare pattern_shift to 4'b1101.

2. **Correct Delay Loading Shift Direction:**  
   Similarly, for delay bits, shift left and insert the new bit at LSB to build delay_reg MSB-first correctly.

3. **Simplify Counting Logic with Accurate Initialization and Updates:**  
   - Initialize tick_counter to delay + 1 at start of COUNT state.  
   - Maintain cycle_counter counting 0 to 999 each clock.  
   - Each time cycle_counter reaches 999 (end of 1000-cycle tick), decrement tick_counter if >0 and update count output to tick_counter-1 (count down delays from delay to 0).  
   - When tick_counter reaches 0 and cycle_counter completes 999, counting is done.

4. **Simplify FSM and Signal Assignments:**  
   - Reset all registers properly on reset and on entering SEARCH state (clear pattern_shift).  
   - count output is only valid during COUNT; otherwise don't care (zero).  
   - Assert done only in WAIT_ACK state and wait for ack.

5. **Use consistent style with one synchronous block and one combinational block for FSM.**

This approach ensures correct pattern detection, correct delay loading, exact timer duration, stable count output during each 1000-cycle interval, and proper handshake via done/ack signals. It fixes all off-by-one and shifting bugs from the original design.
