The main issue in the original design is the use of division and multiplication with 1000, which is not synthesizable or leads to timing inaccuracies. To fix this:

1. Replace the single total_cycle_count and division-based approach with two counters:
   - A `tick_count` counter counting down from `delay` to 0 (4 bits).
   - A `cycle_count` counter counting from 0 to 999 for each tick interval of 1000 clock cycles.

2. This way, each tick lasts exactly 1000 clock cycles, with `count` output stable and equal to the current tick number (counting down from delay to 0).

3. The counting phase proceeds as:
   - cycle_count increments each clock.
   - When cycle_count reaches 999, reset cycle_count to 0 and decrement tick_count.
   - When tick_count reaches 0 and cycle_count finishes its 1000 cycles, counting ends.

4. The state machine stays off data input during counting and done wait states.

5. Inputs and outputs are updated synchronously and cleanly.

6. Pattern detection and delay loading remain MSB-first shift registers.

This approach eliminates division/multiplication, ensures correct and exact timing for counting, and aligns output count transitions with the problem specification.

The reset remains synchronous active-high and all sequential logic on positive clock edge.
