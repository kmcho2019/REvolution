Fix the following main issues:

1. **Delay bit loading direction:**  
   The problem requires MSB-first loading. The first bit shifted in after the pattern should be the most significant bit of delay_reg. Instead of shifting new bits into LSB, shift in from the MSB side by left-shifting delay_reg and inserting data at LSB:  
   `delay_reg <= {delay_reg[2:0], data};` is LSB-first (incorrect).  
   Correct is: shift right inserting at MSB:  
   `delay_reg <= {data, delay_reg[3:1]};` or better store bits from MSB downward.

   To make this clear, use a bit counter (load_bits_cnt from 0 to 3) and assign `delay_reg[3 - load_bits_cnt] <= data;` each cycle.

2. **Counting and remaining_ticks update:**  
   Avoid using `%` modulus in sequential logic. Instead, maintain a cycle counter from 0 up to total_count-1. Every clock increment the cycle_counter. Whenever `(cycle_counter % 1000) == 999` (i.e., on the last cycle of each 1000-block), decrement remaining_ticks.

   To avoid `%` altogether, keep a smaller sub-counter counting from 0 to 999. When it wraps, decrement remaining_ticks.

3. **Counting cycle length and off-by-one fixes:**  
   Counting should last exactly `(delay + 1) * 1000` cycles. Initialize remaining_ticks = delay. The count output should output the current remaining_ticks value stable during each 1000-cycle block.

   When remaining_ticks reaches 0 and the 1000-cycle block completes, counting ends and transition to DONE_WAIT.

4. **Synchronous reset and FSM transitions:**  
   On reset, clear all registers to initial state SEARCH.

5. **Outputs:**  
   - `counting` high only in COUNTING state.  
   - `done` high only in DONE_WAIT.  
   - `count` is valid only during COUNTING as current remaining_ticks.  
   - count is don't-care (set to zero) elsewhere.

Implement a Moore FSM with these states: SEARCH, LOAD_DELAY, COUNTING, DONE_WAIT.

Implement two counters in COUNTING:  
- `cycle_subcount` (0 to 999) to count cycles inside a 1000-cycle block.  
- `remaining_ticks` (initialized to delay) counting down each block.

When remaining_ticks reaches 0 and the 1000-cycle block ends, counting finishes.

This approach fixes all previously identified problems, precisely meets spec, and avoids non-synthesizable logic.
