Refactor to a clearly separated Moore FSM with explicit states and outputs, minimizing combinational next-state logic by using only synchronous state updates and registered outputs for better timing.

Key improvements:

1. Use a 5-bit shift register to detect the pattern "1101" in a rolling manner, updated every clock cycle regardless of state until pattern found. This avoids missing the start sequence timing.

2. Implement a separate shift register and bit counter to serially capture the 4-bit delay once the pattern is detected. The delay bits are shifted in MSB first by shifting left and appending data LSB (so first bit shifted in ends as MSB). This matches the spec clearly.

3. Separate timer logic:
   - Use a cycle_counter to count from 0 to 999.
   - Use a tick_counter to count down the remaining (delay+1) timer ticks.
   - At each 1000 cycles, decrement tick_counter.
   - When tick_counter reaches 0 after completing the last 1000 cycle count, transition to DONE.

4. Output logic:
   - `counting` asserted only in COUNTING state.
   - `done` asserted only in DONE state.
   - `count` outputs the current tick_counter - 1 when counting (remaining full 1000-cycle chunks), and zero during done.
   - When not counting or done, count is zero (don't care as per spec).

5. Wait in DONE state for ack to return to searching for start pattern.

6. Synchronous active-high reset initializes all registers.

This structured approach aligns with the timing requirements and state transitions, fixing off-by-one errors and ensuring the start pattern detection is always updated. Outputs are generated as stable signals per FSM state. This also cleans the code by using enumerated states and removes combinational next_state logic by moving it inside the synchronous block for clarity.

This clear, well-defined FSM with continuous pattern detection and ordered delay loading matches the spec and should pass functional tests.
