I will refactor the design into a Moore-style FSM with clearer state separation and more precise timing control:

- Use a 2-bit pattern detector shifting in bits only when searching, with no shifting during counting or done states to avoid false detections.
- During delay loading, shift delay bits MSB first with a bit counter, all synchronized to clock edges.
- Use a large 24-bit main counter counting down from `(delay + 1)*1000 - 1` to zero, so we count exactly `(delay+1)*1000` cycles. This removes nested counters and off-by-one errors.
- Derive the 4-bit `count` output directly from the high nibble of the main counter divided by 1000 by integer division, effectively `count = remaining_ticks - 1 - (elapsed_ticks / 1000)`, which avoids complex decrements and glitches.
- Ensure outputs `counting` and `done` are only asserted in respective states.
- Use synchronous reset to set initial state to SEARCH.
- Transition from DONE to SEARCH only after `ack` is asserted.
- In the SEARCH state, shift in new bits on each clock, and when pattern detected, move to LOAD_DELAY.
- In LOAD_DELAY, shift in 4 delay bits MSB first over 4 clocks, then transition to COUNT.
- In COUNT, decrement main counter each clock; when reaches zero, move to DONE.
- Freeze inputs during counting and done states.

This design simplifies counters, aligns outputs precisely with states, avoids glitches and off-by-one errors, and clearly separates functionality. It uses a single large down-counter rather than nested counters, facilitating easier verification and clarity.
