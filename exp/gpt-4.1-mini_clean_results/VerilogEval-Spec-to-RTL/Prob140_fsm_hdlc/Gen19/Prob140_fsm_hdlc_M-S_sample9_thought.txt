To simplify the design, I will merge the next state calculation and output logic into a single always block to reduce code size and remove the separate next-state logic. Since the FSM only needs to track the count of consecutive ones, a simple counter with saturation at 7 is enough. Outputs are Moore-type and depend on the current count and input, so they can be computed from the updated count within the same clock cycle.

This reduces the code from two always blocks to one, making it straightforward while preserving functionality, synchronous reset, and one-cycle output assertion delay. The design remains clear and minimal.
