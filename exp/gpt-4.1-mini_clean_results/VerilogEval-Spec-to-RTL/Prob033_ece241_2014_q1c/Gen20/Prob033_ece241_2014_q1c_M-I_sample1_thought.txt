To improve PPA (power, performance, area), I will refactor the ripple carry adder code by using a generate loop instead of manually instantiating each bit's logic. This reduces code verbosity and enables the synthesis tool to better optimize resource sharing and routing, potentially reducing area and power.

Additionally, I'll use assign statements inside a generate block for carries and sums. For overflow detection, the classic method using XOR of carry into and carry out of the MSB remains the simplest and fastest.

This approach keeps the ripple carry adder architecture (still area and power friendly for 8 bits) while making the code cleaner, easier to maintain, and likely more efficient after synthesis optimizations. 

If timing becomes a bigger concern, one could switch to a carry lookahead or carry skip architecture, but for this 8-bit size, the ripple carry with generate is a good tradeoff.

Hence the improvement strategy focuses on code clarity, maintainability, and small synthesis improvements that help area and power metrics.
