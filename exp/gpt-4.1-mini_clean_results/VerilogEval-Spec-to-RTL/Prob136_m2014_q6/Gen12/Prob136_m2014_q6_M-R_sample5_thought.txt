I will implement the FSM using an `always @(*)` combinational block for the next state and output logic using a `case` statement, separating the next state logic from the sequential state register update. This makes the design clearer and easier to extend or modify. The output `z` will be registered inside the clocked block for synchronized outputs, and the reset logic will initialize the FSM to state A. This structure contrasts with continuous assignment for next state by using a more traditional FSM style with a single always block for combinational next state and output and another for the sequential update.
