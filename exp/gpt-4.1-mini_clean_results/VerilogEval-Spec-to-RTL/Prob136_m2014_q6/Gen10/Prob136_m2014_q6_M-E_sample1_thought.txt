I will use a Moore FSM implemented with a case statement in a synchronous always block to define both next state and output z together. The output z will be registered alongside the state for glitch-free behavior. To simplify the logic and minimize combinational logic depth, I will store z as a state attribute in the state encoding by defining an enumeration of states with their output values embedded. This way, the output logic is trivial (just assign z based on the current state), and the next state logic is handled in a single case statement inside the clocked always block. Reset will asynchronously set the FSM to state A with z=0.
