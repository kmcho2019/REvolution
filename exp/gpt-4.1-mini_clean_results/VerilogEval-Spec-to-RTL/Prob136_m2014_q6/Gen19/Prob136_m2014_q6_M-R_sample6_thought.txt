I will refactor the design by implementing the next state logic using a combinational `case` statement instead of nested if-else chains. This change provides clearer state-transition logic and potentially allows synthesis tools to optimize the critical path better due to the mutually exclusive nature of case items. Also, I will explicitly reset `next_state` to a default value at the start of the combinational block to avoid inferred latches. The output `z` will be generated inside an always_comb block instead of continuous assignment to keep all combinational logic in one place, increasing clarity for some designers and tools. The synchronous reset and state register remain unchanged to keep stable and predictable state transitions. State encoding and overall functionality remain the same to keep behavior identical.
