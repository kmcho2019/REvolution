I will refactor the FSM by using an explicit enumerated type (using `typedef enum`) for states to improve code readability and maintainability. The next-state and output logic will be described with combinational `always @(*)` blocks using a `case` statement for clearer state transitions, which synthesis tools generally handle well. The output `z` will be assigned combinationally using an assign statement instead of an always block. The synchronous state update remains on the positive clock edge with synchronous reset. This approach keeps the functionality identical but improves clarity and structure.
