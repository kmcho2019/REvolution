I will refactor the FSM by using one always block for both state transitions and output logic, consolidating the next-state and output computations. Also, I will use a `case` statement instead of if-else chains for better readability and synthesis friendliness. To eliminate the explicit `next_state` signal, I will compute the next state combinationally within the always block and update the state register synchronously. The output `z` will be declared as a reg and assigned inside the same always block based on the current state, making the output logic synchronous with the state transitions, which can simplify timing and logic. This approach yields a clean, easily extensible FSM structure.
