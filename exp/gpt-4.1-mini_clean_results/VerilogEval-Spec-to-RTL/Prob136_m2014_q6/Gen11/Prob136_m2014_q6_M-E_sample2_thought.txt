I will implement the FSM using a `case` statement in a combinational always block to compute the next state and output `z` simultaneously. The state encoding will be binary with 3 bits, but instead of nested ternaries, the `case` statement will improve readability and can help synthesis tools optimize logic. The output `z` depends on the current state, so I will assign it inside the combinational block as well, making it registered (state-dependent) but combinationally derived from current state. The state register update is synchronous with reset handled asynchronously. This approach centralizes the FSM logic and outputs in one place, improving clarity and allowing for easy future expansion or modification.
