Instead of a bitwise ripple-carry or explicit full adder chain, I will implement the adder-subtractor using a high-level arithmetic expression combined with a two's complement subtraction approach internally, but verify and set the zero flag via a separate always block that explicitly checks if the output is zero without relying on reductions in the same always block. This avoids potential latch inference or improper zero flag updates.

Specifically:
- Use a combinational always block with non-blocking assignments for outputs to improve simulation behavior and clearer synthesis intent.
- Implement subtraction as addition of a plus the two's complement of b when do_sub is asserted: out = a + (~b) + 1 for subtraction.
- Use a separate always block or explicit combinational logic to set the zero flag by comparing out to zero (`out == 8'd0`) to prevent any ambiguous zero detection.
- This modularizes zero detection and calculation cleanly.
- Use non-blocking assignments in combinational logic, a safe practice in modern Verilog for purely combinational always blocks.
- This approach ensures clarity, no inferred latches, and reliable zero flag setting.
- Additionally, no explicit carry chain logic is used here, allowing synthesis tools to pick optimal adder implementations.

This method leverages arithmetic expressions and proper always block structure for clean, bug-free design.
