Instead of directly expressing next_y1 as a single Boolean expression, I will implement a small combinational ROM (lookup table) using a case statement indexed by the current state y and input w. This approach explicitly enumerates all possible transitions, making the design very clear and easy to verify. It leverages a combinational block that outputs the next value of y[1] based on all state transitions. The output Y1 will be the current y[1], as required.

This approach can be considered architectural diversification compared to a pure Boolean expression, enabling straightforward FSM modifications and easier debugging. The downside is a slightly larger logic for the decoder, but with only 3-bit state and 1-bit input, this is minimal.

Since only next_y1 is required, we output only that bit from the case table.

This approach is useful for FSM next-state signals extraction or when the designer wants explicit control over transitions.
