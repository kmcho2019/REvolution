Implement the saturating counter using simple arithmetic with saturation boundaries, avoiding a case statement. Compute the next state as the current state plus one or minus one based on train_taken when train_valid is asserted, saturating at 0 and 3. Use an enable signal to update the state only when train_valid is high and the next state differs from the current state, which reduces unnecessary toggling and hence saves power. The asynchronous reset sets the state to 2'b01 as specified. This approach is concise, low-latency, and efficient in hardware.
