Refactor the design by removing the explicit next_state register and instead using a pure combinational continuous assignment (`assign`) to calculate the next state. The always block will only handle the synchronous state update with asynchronous reset. This reduces the number of variables and clearly separates combinational next-state logic from the sequential state update. Also, express the next state transitions using arithmetic with saturation clamps instead of a case statement, which achieves the same behavior with simpler combinational logic and may improve readability and synthesis results.
