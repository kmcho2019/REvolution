Refactor the design by separating the combinational next-state logic into a dedicated always_comb block and use a single always_ff block for the state update with asynchronous reset. This makes the design more modular and clearer by distinguishing combinational and sequential logic explicitly. Instead of using an enable condition inside the sequential block, implement the enable by gating the state update using a conditional next_state assignment in the combinational logic: if train_valid is low, next_state equals current state, else it increments/decrements saturating as before. This removes the need for a conditional update in the always_ff block. The asynchronous reset is preserved. This approach improves readability by separating combinational and sequential domains, while keeping functionality and performance unchanged.
