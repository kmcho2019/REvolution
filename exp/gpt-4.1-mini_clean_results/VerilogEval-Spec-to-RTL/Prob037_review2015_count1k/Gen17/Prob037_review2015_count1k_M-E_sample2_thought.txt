Implement a binary-coded decimal (BCD)-style counter with two separate parts: a 4-bit digit counting 0-9 and a 6-bit digit counting 0-99 (actually 0-99 is 7 bits, but we can manage with two separate counters). Here, the lower 4 bits count from 0 to 9, and upon rolling over from 9 to 0, the upper 6 bits increment. Since 999 in decimal is represented as three decimal digits (9-9-9), we can count the decimal digits in binary-coded decimal fashion, which naturally fits the decimal counting.

Specifically:
- Use three counters: digit_ones (4 bits), digit_tens (4 bits), digit_hundreds (4 bits).
- On each clock cycle, increment digit_ones.
- When digit_ones reaches 9, reset it to 0 and increment digit_tens.
- When digit_tens reaches 9, reset to 0 and increment digit_hundreds.
- When digit_hundreds reaches 9 and digit_tens and digit_ones are 9, reset all to zero.
- Combine all three digits into a 10-bit output (3 bits for hundreds, 4 bits for tens, 4 bits for ones), giving a total of 11 bits, so the hundreds digit uses only 3 bits (since max digit is 9 which fits 4 bits, so let's use 4 bits for each digit, resulting in 12 bits; to fit into 10 bits output, we can encode decimal count into pure binary).
  
However, since the output is required to be a 10-bit count representing values 0 to 999 in binary, the internal BCD counters are only for counting logic; finally, output q is a binary representation of the decimal count.

This architecture trades some logic in comparator and addition for simpler increment and reset logic that mimics decimal counting, potentially reducing comparator complexity and improving readability. The output q is constructed by converting the decimal digits into binary value using a combinational multiply-and-add approach (q = hundreds*100 + tens*10 + ones).

The reset is synchronous and active high. Counting occurs on posedge clk.

This design is novel because it does not count binary directly but instead counts decimal digits separately and combines them combinationally, which can be beneficial in some scenarios for power or timing by reducing wide adder complexity in counting path.
