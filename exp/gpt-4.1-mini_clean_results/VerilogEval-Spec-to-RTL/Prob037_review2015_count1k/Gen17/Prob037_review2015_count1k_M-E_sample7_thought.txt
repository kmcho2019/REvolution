Instead, for novelty, split the counter into two stages:

- A 10-bit binary counter counts from 0 to 999;
- Implement the synchronous reset inside the sequential block;
- Use an integer variable for the next count, computed sequentially inside an always @(posedge clk) block to reduce combinational logic complexity.

This method means the counter logic is fully sequential with minimal combinational next-state logic, reducing critical path by removing combinational next-state logic outside the sequential block.

This differs from the previous design by pushing next count logic inside sequential always block without an explicit combinational next state, trading a small increase in flip-flop input complexity for reduced combinational logic.

Additionally, implement the counter using a simple comparison (q == MAX_COUNT) for reset condition, and implement reset inline with synchronous reset logic.
