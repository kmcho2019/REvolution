Implement the 10-bit counter using a binary-coded decimal (BCD)-style counting approach by dividing the counter into two parts: a 4-bit digit for the hundreds place and a 6-bit digit for the units and tens combined, counting from 0 to 999. 

Specifically, the lower 6 bits count from 0 to 63, but we will reset the counter early to implement decimal counting:

- Use a 4-bit digit for hundreds (0 to 9).
- Use a 4-bit digit for tens (0 to 9).
- Use a 4-bit digit for units (0 to 9).

Since 10×10×10 = 1000 counts, each digit counts 0 to 9 and then rolls over.

This approach:

- Splits the 10-bit counter into three BCD digits of 4 bits each.
- On each clock, increment the units digit.
- If units digit reaches 9, reset units to 0 and increment tens.
- If tens digit reaches 9, reset tens to 0 and increment hundreds.
- When hundreds digit reaches 9 and units and tens are 9, reset all to 0.
- Use synchronous active-high reset as specified.

This approach simplifies the rollover logic and explicitly models a decimal counter rather than a binary one, which can be useful if the count is to be displayed or decoded later. It is also a structurally different approach from a simple binary counter.

Finally, concatenate the three BCD digits to form the 10-bit output, padding the units and tens to 4 bits each, which sums to 12 bits, but since only 10 bits are available for q, we'll pack them efficiently:

- Use 4 bits for hundreds (q[9:6])
- Use 3 bits for tens (q[5:3]) — store 0 to 9 in 4 bits but only output 3 bits (this sacrifices one bit, but can be acceptable because tens never exceed 9)
- Use 3 bits for units (q[2:0])

However, 3 bits can only encode 0-7, which is insufficient for decimal digits (0-9). So to keep it simple and correct, we will store all three digits internally as 4-bit registers but output the concatenation of these digits as q[9:0] with units on the rightmost 4 bits (q[3:0]), tens next 4 bits (q[7:4]), and hundreds in q[9:8] plus two zeros to pad. This packs the 12-bit internal representation to 10 bits by truncating or overlapping bits, which is not precise.

Therefore, to strictly meet 10 bits output, instead of storing BCD digits, store the count as a 10-bit binary number internally but implement counting by incrementing units, tens, and hundreds separately and then encoding that into the binary output.

- Implement the counter as a 10-bit register.
- On each clock, add 1 to the count.
- When the count reaches 1000 (decimal), it wraps to 0.
- To detect when to wrap, check if q == 999; this can be done by adding 1 and checking the carry out of the addition (q + 1 == 1000).
- Using the carry-out of the increment operation, reset q to 0.

This effectively uses the carry-out bit from addition as the terminal count detector, a novel approach different from checking equality or partial bit matches.
