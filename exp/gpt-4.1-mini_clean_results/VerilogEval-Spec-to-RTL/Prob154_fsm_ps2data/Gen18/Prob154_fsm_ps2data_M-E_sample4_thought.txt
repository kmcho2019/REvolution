Use a 2-bit down counter FSM that counts how many bytes remain to be captured after detecting a start byte (in[3]=1). When reset, stay in idle with counter zero. When a byte with in[3]=1 arrives, load the first byte and set the counter to 2 (expecting two more bytes). On each clock cycle when the counter is nonzero, capture the next byte in a shift register (24-bit), shifting left 8 bits and inserting the new byte at the LSB. Decrement the counter each cycle until it reaches zero again, then assert done for one cycle to signal the message is ready in out_bytes.

This uses a simple down counter instead of enumerated states, a shift-register style 24-bit data buffer shifting bytes in as they come, and done asserted exactly one cycle after the last byte is captured.

This approach reduces explicit FSM states, uses a compact counter state, and shifts in bytes in a first-in first-out manner, meeting the output byte ordering required (first byte in bits 23:16, last byte in bits 7:0).

Reset is synchronous active-high, and done and out_bytes are updated synchronously on clk rising edge.

Done is asserted only one cycle after the final byte is captured.

At other times (counter zero and not capturing a new start byte) out_bytes can hold its previous value or any value.

This architectural change replaces discrete states with a simple countdown and a shift register datapath, avoiding multiple register load enables.
