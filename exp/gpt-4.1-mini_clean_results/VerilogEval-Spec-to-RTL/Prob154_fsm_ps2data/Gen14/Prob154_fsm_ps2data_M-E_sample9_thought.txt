Use a Moore FSM with four states: IDLE, BYTE1, BYTE2, BYTE3, and DONE. The FSM stays in IDLE discarding bytes until it sees a byte with in[3]=1. Then it transitions to BYTE1 and captures the first byte. Next cycles, it goes to BYTE2 and BYTE3 capturing subsequent bytes. After the third byte is captured, the FSM goes to DONE state where it asserts done and outputs the assembled 24-bit message as out_bytes (concatenated as first, second, third). On the next clock cycle, it returns to IDLE to search for the next message. Using a separate DONE state ensures the done signal is stable and asserted for exactly one clock cycle, and the output is valid at done assertion. Synchronous reset returns to IDLE and clears outputs.

The datapath stores the three bytes in three separate registers (byte1, byte2, byte3), concatenated into out_bytes on done. This modularizes storage and avoids partial register updates. The done signal pulses high for one clock cycle in the DONE state, which makes timing clear and the FSM easy to test.

This approach simplifies logic by separating data capture and done signaling in distinct states, making the FSM easy to analyze and minimizing glitches on outputs.
