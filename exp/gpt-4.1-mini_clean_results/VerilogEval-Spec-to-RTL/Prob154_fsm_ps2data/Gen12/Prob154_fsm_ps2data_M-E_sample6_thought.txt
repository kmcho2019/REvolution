I will implement the FSM using one-hot encoding for clarity and simplicity, where each state is represented by a separate flip-flop. This might slightly increase area but simplifies state decoding logic.

The FSM will have four states: IDLE (waiting for a byte with in[3] = 1), BYTE1 (first byte matched), BYTE2 (second byte received), BYTE3 (third byte received and output done next cycle).

I will use a shift register approach to store incoming bytes: on detecting the first byte (in[3] = 1), store it in the highest byte of out_bytes; then shift in the next two bytes to lower bytes, so out_bytes always holds the 3-byte message as {byte1, byte2, byte3}.

The done signal will be asserted for one clock cycle immediately after receiving the third byte, i.e., when the FSM transitions from BYTE3 back to IDLE.

Reset will synchronously clear all registers.

This approach outputs the 24-bit message in the done cycle with minimal intermediate registers and an easy-to-understand FSM.
