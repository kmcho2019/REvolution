Refactor the FSM by explicitly defining states using an enumerated type with `localparam` and a single state register, instead of using a count variable. Use a combinational always block to determine next state and outputs, and a sequential always block for state update and registers. This separates state transition logic from state register updates, improving code readability and clarity of FSM behavior. Also, use a shift register style to store bytes by shifting in the newest byte when accepted. The done signal and out_bytes are asserted together in the output state. The synchronous reset behavior remains unchanged.
