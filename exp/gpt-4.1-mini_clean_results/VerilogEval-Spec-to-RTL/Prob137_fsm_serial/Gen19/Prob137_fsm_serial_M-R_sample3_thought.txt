I will refactor the FSM by separating the combinational next-state logic and output logic from the sequential state and data registers. This two-process approach improves code clarity and synthesis friendliness. I'll use one always_ff block for state and data register updates on the clock edge with synchronous reset, and a separate always_comb block for next state and outputs. The done signal will be generated as a pulse in the combinational logic based on the current and next states to minimize toggling. I will also gate updates to the shift register and bit counter only during the DATA state to reduce unnecessary switching, improving power efficiency. The FSM encoding remains binary for area efficiency.
