The primary fix is to remove the combinational assignment to 'done' and have 'done' driven only in the synchronous always block, ensuring a single driver and no conflicts or glitches.

Also, to properly capture all 8 data bits (LSB first), we shift in the new bit into bit 0, shifting existing bits left: `data_reg <= {in, data_reg[7:1]}` actually puts the new bit in the MSB, which reverses bit order. Instead, we should shift the existing bits right and insert the new bit into the MSB or better, shift right and insert at MSB to receive LSB first:

- Since the first received bit is LSB (bit 0), we can do: `data_reg <= {in, data_reg[7:1]}` and then, after 8 cycles, data_reg[0] contains first bit. Alternatively, shifting right by one and placing new bit in MSB actually means we get MSB first, so to receive LSB first, we can shift left and place new bit at bit 0:

`data_reg <= {data_reg[6:0], in};`

This way, first bit received goes to bit 0, next bit shifts left, etc.

Regarding bit_count, count from 0 to 7 as each data bit is sampled. When bit_count reaches 7 (meaning 8 bits received), go to STOP_WAIT.

Also, the FSM should assert 'done' for exactly one cycle synchronously after verifying the stop bit is '1'. If stop bit is incorrect, remain in STOP_WAIT until a '1' is detected.

In the sequential block, on reset, clear all signals.

All outputs and state transitions occur on posedge clk with synchronous reset.

In summary:

- Remove 'done' assignment from combinational block.
- Shift data bits correctly for LSB first.
- Increment bit_count on each data bit received.
- Assert done for one cycle when stop bit is correct.
- Keep FSM states as IDLE, RECEIVE, STOP_WAIT.
