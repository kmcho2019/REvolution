Fuse the two provided examples by combining the power-efficient data handling of Example 1 with the timing-friendly one-hot FSM encoding of Example 2.

Key points of the fusion:

1. Use one-hot encoding for FSM states (4 bits for IDLE, RECEIVE, CHECK_STOP, WAIT_STOP) to improve timing and simplify state decoding.

2. Adopt the LSB-first shift direction and reduced toggling approach from Example 1:
   - Shift left inserting the new bit at LSB (`shift_reg <= {shift_reg[6:0], in}`).
   - Update `shift_reg` and `bit_count` only in RECEIVE state.
   - Reset `shift_reg` and `bit_count` only on reset or state transitions into IDLE (not every cycle), reducing unnecessary toggling.

3. Implement synchronous reset and synchronous `done` pulse asserted only one cycle when a correct stop bit is detected in CHECK_STOP state.

4. Use a single synchronous always block for state, counters, shift_reg, and done, plus a combinational always block for next_state and done_next logic.

5. Maintain WAIT_STOP to handle framing errors by waiting for a proper stop bit (line idle).

This fusion yields a design with better timing (due to one-hot states), power (due to minimal toggling of registers), and clean code structure. The `done` signal is asserted only for one clock cycle right after a valid byte reception is detected.

The design is fully synchronous, robust, and ready for synthesis.
