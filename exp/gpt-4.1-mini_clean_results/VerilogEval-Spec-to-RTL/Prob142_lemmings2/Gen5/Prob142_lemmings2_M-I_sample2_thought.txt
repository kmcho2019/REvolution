To fix the direction mismatch issue, encode the walking direction entirely in the state variable, removing the separate `walking_dir` register to avoid synchronization problems.

Implement a three-state FSM:
- WALK_LEFT (walking left)
- WALK_RIGHT (walking right)
- FALLING (falling)

Transitions:
- On areset, go to WALK_LEFT.
- When ground is 1:
  - If in WALK_LEFT and bump occurs, switch to WALK_RIGHT.
  - If in WALK_RIGHT and bump occurs, switch to WALK_LEFT.
- When ground goes to 0 from walking states, transition to FALLING state, retaining the last walking direction in the state.
- In FALLING state, ignore bumps.
- When ground returns to 1, return to the walking state corresponding to the stored direction.

Outputs depend solely on state (Moore outputs):
- WALK_LEFT => walk_left=1
- WALK_RIGHT => walk_right=1
- FALLING => aaah=1

This removes redundant variables, fixes the timing mismatch, simplifies logic, and exactly follows the problem specification about bump and ground event precedence.
