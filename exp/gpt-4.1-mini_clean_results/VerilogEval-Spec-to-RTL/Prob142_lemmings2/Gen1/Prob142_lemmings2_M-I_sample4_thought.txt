The original code mostly works but has a critical functional bug in handling bumps. The problem states:

- If bumped on the left, the lemming walks right next.
- If bumped on the right, it walks left next.
- If bumped on both sides simultaneously, it still switches direction.

The current code blindly toggles walking direction on any bump. This is incorrect because it ignores which bump signal is active and always flips direction.

Improvement strategy:
- When in WALK_LEFT state:
  - If bump_left=1, walk right next.
  - Else if bump_right=1, walk left next (no change).
- When in WALK_RIGHT state:
  - If bump_right=1, walk left next.
  - Else if bump_left=1, walk right next (no change).

But the problem says if bump on left or bump on right (or both), the direction switches. So if bumped on left (regardless of walking state), direction should be right; if bumped on right, direction should be left. If both bumps are 1, direction switches anyway.

This suggests the new direction depends only on the bump signals, not current direction.

Hence, at bump:
- If bump_left and bump_right both are 1, direction switches from current.
- Else if bump_left=1, direction is right.
- Else if bump_right=1, direction is left.
- Else keep current direction.

This logic avoids ambiguous toggling and aligns exactly with problem statement.
