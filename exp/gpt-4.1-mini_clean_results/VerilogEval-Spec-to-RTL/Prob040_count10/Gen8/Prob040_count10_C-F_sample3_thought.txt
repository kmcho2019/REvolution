To fuse the best ideas from both examples, I will keep the straightforward synchronous active-high reset and simple decade counting logic since it already achieves minimal logic and clear functionality. The main opportunity for improvement lies in reducing switching power without adding complexity or impacting performance.

I will add a clock enable signal internally so that the counter only increments (and toggles bits) when the current count is not 9. When q is 9, the counter resets to 0 on the next cycle, but preventing unnecessary toggling right before reset helps reduce switching power slightly.

This clock enable is implemented combinationally as `enable = (q != 9)`. In the always block, if reset is asserted, reset q to zero; else if enable is asserted, increment q; else wrap q back to zero. This avoids multiple conditional branches and keeps critical path short.

This fusion approach merges the clean and minimal structure from both examples with a small optimization of counting only when enabled to help power without increasing complexity or area.

The code will remain synthesizable with minimal hardware cost and should slightly reduce bit toggling compared to continuous counting. The counter sequence and timing remain identical to prior implementations.
