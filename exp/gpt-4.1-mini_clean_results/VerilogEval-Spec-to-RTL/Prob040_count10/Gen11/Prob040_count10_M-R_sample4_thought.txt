I will refactor the decade counter into a two-process structure: a combinational block to determine the next count value and a sequential block to update the state. This separates next-state logic from state registers, making the design more modular and easier to extend if needed.

Specifically:
- Create a reg q to hold the current count.
- Create a wire next_q representing the next count, computed combinationally.
- Use an always block triggered on posedge clk for state update with synchronous reset.
  
This style is common in FSM and counter designs, improves readability by explicitly showing next state logic, and can sometimes assist synthesis tools in optimization.

The functionality remains identical: count from 0 to 9, reset synchronously to 0 on reset high, and wrap around from 9 back to 0.
