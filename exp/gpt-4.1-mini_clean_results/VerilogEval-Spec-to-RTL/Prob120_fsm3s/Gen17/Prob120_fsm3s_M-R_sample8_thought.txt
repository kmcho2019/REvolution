I will refactor the FSM implementation to use a combinational always block for next state logic and output logic, instead of continuous assignments with multiple boolean expressions. This approach uses a `case` statement for next state decoding, which improves readability and maintainability by explicitly enumerating each state's transitions. 

The output remains Moore type, driven only by the current state, but is assigned in the same combinational always block to keep related logic together. State encoding and synchronous reset logic in the sequential always block remain unchanged for synthesis compatibility.

This structure is common and clearly expresses FSM behavior, making it easier to modify or expand in the future. It may also help synthesis tools optimize combinational logic better and reduce gate duplication compared to multiple scattered assignments.
