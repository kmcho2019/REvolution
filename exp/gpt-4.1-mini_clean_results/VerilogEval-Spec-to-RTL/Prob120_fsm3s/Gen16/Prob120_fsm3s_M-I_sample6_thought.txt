To improve PPA, I will implement the next state logic using a combinational always block with a case statement instead of complex boolean expressions. This can reduce gate-level complexity and the critical path by avoiding multiple OR gates and duplicated state comparisons. Using a case statement synthesizes efficiently into a multiplexer tree and is easy for synthesis tools to optimize.

I will keep the same 2-bit encoding and synchronous active-high reset for clarity and compatibility. The output will remain a simple continuous assignment based on the current state for minimal logic and power.

This approach balances simplicity, better synthesis optimization, and likely improved timing and power due to reduced combinational logic fan-in and fewer logic levels.

In summary:
- Use a combinational always block with case on current state for next_state generation.
- Keep synchronous reset and registered state update.
- Retain simple continuous assignment for output.
