To optimize the FSM for better PPA (performance, power, area), I will:

- Reduce unnecessary toggling in the data shift register by updating it only during the SEARCH states. This reduces switching power outside pattern detection.
- Simplify pattern detection logic by removing the small data_sr shift register and using the existing FSM states for pattern progress; since each SEARCH state corresponds to a specific pattern bit received, we can rely on state + input rather than a separate register.
- Use non-blocking assignments for state and shift counter updates as before.
- Keep the binary state encoding as it is already compact and efficient for area.
- Maintain synchronous reset and all outputs driven from the state register.
- This reduces logic toggling, slightly simplifies logic, and should improve power and potentially timing by reducing unnecessary toggling in data sampling.

All functionality remains unchanged.
