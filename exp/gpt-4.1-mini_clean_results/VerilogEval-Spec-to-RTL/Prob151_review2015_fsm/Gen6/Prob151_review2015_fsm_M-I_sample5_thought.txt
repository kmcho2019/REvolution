The original FSM is mostly correct but has subtle timing issues due to pattern detection and state transition synchronization.

Improvement strategy:
- Since both `pattern_reg` and `state` update on the clock's rising edge, detecting the pattern (1101) from `pattern_reg` and acting on it in the same cycle isn't possible.
- To fix this, use a two-stage approach:
  1. Update the pattern register every clock cycle.
  2. On the next clock cycle, when pattern_reg holds the pattern 1101, transition from IDLE to SHIFT_0.

This means adding a "pattern_detected" signal registered from the comparison of the pattern_reg to 4'b1101. This registered signal will drive FSM transitions so the FSM can react properly on the next clock cycle.

Also:
- Use a single counter (2-bit) to count shift cycles instead of multiple SHIFT_n states, simplifying the FSM states and reducing logic.
- Keep FSM outputs combinational and based on the current state.
- This results in states: IDLE, SHIFT (with internal counter), WAIT_COUNT, WAIT_ACK.

This ensures:
- The pattern detection is synchronous and stable.
- Shift enable is asserted exactly for four cycles.
- Clear state transitions, outputs timed correctly.
- Reduced state space helps better PPA.

Finally, the pattern register and the pattern_detected signal reset synchronously.

This approach corrects timing mismatches and optimizes the FSM size and transitions.
