The main issue is the pattern detection and its synchronization with the FSM. The original solution used a `start_pattern_detected` flag set combinationally based on a newly shifted pattern. This can cause missed or repeated triggers due to race conditions between pattern detection and FSM transitions.

To fix this, we:

- Implement a dedicated pattern detection FSM (or logic) that detects the sequence `1101` bit-by-bit over multiple clock cycles, rather than detecting the pattern with a 4-bit shift register in one cycle. This approach is more robust, especially for overlapping patterns.

- Use a small pattern detect state machine that advances when correct bits arrive and resets on mismatches, recognizing the pattern precisely.

- When the pattern is detected (on the last bit of `1101`), raise a synchronous pulse (`pattern_detected`) one clock cycle to trigger the main FSM transition.

- The main FSM then uses this single-cycle `pattern_detected` pulse to transition from IDLE to SHIFT exactly once per pattern occurrence.

- This avoids the need for a latch like `start_pattern_detected` and eliminates timing issues between pattern detection and FSM.

- Outputs are still synchronous to FSM state.

- The SHIFT cycle counter is implemented as before, counting 4 cycles of `shift_ena`.

This approach ensures clean, glitch-free pattern detection and clean FSM state transitions matching the timing requirements.

The design remains synchronous, simple, and fully compliant with the problem specification.
