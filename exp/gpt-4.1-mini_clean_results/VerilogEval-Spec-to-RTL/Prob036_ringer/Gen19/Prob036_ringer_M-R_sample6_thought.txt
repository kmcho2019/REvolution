I will refactor the design to use an always_comb block instead of continuous assignments, assigning outputs inside a combinational procedural block. This approach explicitly shows the decision logic in a procedural style, which can sometimes improve readability and is easily extensible for more complex conditions. The logic remains the same: when ring is asserted, if vibrate_mode is set, turn on motor, else turn on ringer. If ring is low, both outputs are off. Using an always_comb block ensures outputs update correctly with any input change without requiring a clock.
