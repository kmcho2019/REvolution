I will implement the design using a combinational always block with an if-else construct for clear priority and mutual exclusion. The logic will first check if ring is asserted. If not, both outputs are 0. If ring is asserted, it will check vibrate_mode: if vibrate_mode is 1, motor is enabled; else, ringer is enabled. This ensures that when the phone rings, either ringer or motor is activated exclusively based on vibrate_mode, and when it does not ring, both outputs stay off. Using a procedural block also makes it explicit and easy to extend in future with more conditions if needed.
