To implement a gshare branch predictor with the given specifications, we need to:
1. Maintain a 7-bit global history register (GHR) that tracks branch history
2. Use a 128-entry PHT (2-bit saturating counters) indexed by XOR of PC and GHR
3. Handle prediction and training interfaces separately but with priority to training
4. Update GHR on predictions (unless overridden by training)
5. Update PHT and potentially recover GHR during training (especially on mispredictions)
6. Handle concurrent predict/train operations with proper precedence

Key points:
- Prediction uses current PHT state (before any training updates)
- Training updates PHT on next clock edge
- Mispredictions recover GHR to train_history
- Training has priority over prediction for GHR updates
- All updates are synchronous to clock edge
