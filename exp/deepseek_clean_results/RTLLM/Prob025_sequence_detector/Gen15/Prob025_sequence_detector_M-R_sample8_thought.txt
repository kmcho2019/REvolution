I'll refactor the code to use explicit state machine implementation instead of the shift register approach, while maintaining the same functionality. The key changes are:

1. Define named states for better readability and maintainability
2. Use a separate combinational block for next state logic and output
3. Keep the sequential block only for state transitions
4. Make the state encoding explicit (binary encoding)
5. Use assign statements for output logic

This approach makes the FSM behavior more explicit and easier to modify if the sequence changes. The trade-off is slightly more code but better maintainability and clearer state transitions.
