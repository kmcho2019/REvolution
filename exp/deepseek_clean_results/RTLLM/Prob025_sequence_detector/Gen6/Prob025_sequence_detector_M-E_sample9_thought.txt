Instead of a traditional FSM, I'll implement a shift-register based solution that:
1. Uses a 4-bit shift register to store the last 4 input bits
2. Performs parallel comparison against the target sequence (1001)
3. Eliminates state transitions entirely, reducing timing complexity
4. Uses register retiming for better timing closure
5. Implements glitch-free registered output
6. Adds input change detection to reduce power consumption
7. Uses Gray-coded counters for the shift register (though not strictly necessary here, demonstrates forward-thinking design)

This approach trades some area (for the shift register) for improved timing and simpler control logic. The parallel comparison is more scalable for longer sequences.
