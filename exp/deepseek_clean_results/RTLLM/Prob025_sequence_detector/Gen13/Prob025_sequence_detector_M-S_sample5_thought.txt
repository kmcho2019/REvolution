To simplify the sequence detector while maintaining functionality, I'll:

1. Remove the separate detection logic and combine it with the shift register update
2. Eliminate the intermediate detected_next signal since it's not necessary for this simple case
3. Directly compute the sequence detection in the sequential block
4. Maintain the same 3-bit shift register approach for efficiency
5. Keep the registered output for clean timing

This reduces:
- One always block (from 2 to 1)
- One intermediate signal
- Overall logic complexity
While maintaining:
- Same detection functionality
- Registered outputs
- Reset behavior
- Efficient shift register implementation
