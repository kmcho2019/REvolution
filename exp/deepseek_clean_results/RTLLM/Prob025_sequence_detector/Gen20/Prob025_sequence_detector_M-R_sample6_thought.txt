I'll refactor the sequence detector to use a Mealy-style finite state machine (FSM) implementation while maintaining the same functionality. This approach:

1. Explicitly defines all states (IDLE, S1, S2, S3) for better readability and maintainability
2. Uses a combinational next-state logic block with assign statements
3. Separates the sequential state register from the output logic
4. Maintains the same detection pattern (1001)
5. Keeps the registered output for clean timing

Benefits:
- More explicit state transitions that match the problem description
- Easier to modify for different patterns by changing state transitions
- Clear separation between combinational and sequential logic
- Still maintains good PPA characteristics
