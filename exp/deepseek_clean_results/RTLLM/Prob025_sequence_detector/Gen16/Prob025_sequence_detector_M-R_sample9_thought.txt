To refactor the sequence detector, I'll implement a Moore machine style FSM with explicit state encoding. The key changes are:

1. **Explicit State Encoding**:
   - Define named states (IDLE, S1, S2, S3, S4) for better readability
   - Use parameters for state values instead of bit positions

2. **Separate State Transition Logic**:
   - Split into combinational next-state logic and sequential state update
   - Makes the FSM behavior more explicit and easier to modify

3. **Registered Output**:
   - Keep sequence_detected as a registered output for better timing
   - Output depends only on current state (pure Moore machine)

4. **Simplified Reset Handling**:
   - Clear state to IDLE on reset
   - Output automatically clears since it's derived from state

Benefits:
- More readable and maintainable state machine
- Clear separation of combinational and sequential logic
- Easier to modify if sequence needs to change
- Still maintains good timing with registered output
