Here's a refactored version that maintains the same functionality but uses a different structural approach:

1. Replace the flag-based approach with an explicit state machine (IDLE and HAVE_FIRST_BYTE states)
2. Use separate always blocks for state transition and output generation (Mealy machine style)
3. Move combinational logic to continuous assignments where possible
4. Keep the same timing behavior: output appears exactly one cycle after second valid input

Advantages of this approach:
- More explicit state control flow
- Separation of combinational and sequential logic
- Easier to extend if more states are needed later
- Clear mapping between states and behavior
- Maintains same performance characteristics
