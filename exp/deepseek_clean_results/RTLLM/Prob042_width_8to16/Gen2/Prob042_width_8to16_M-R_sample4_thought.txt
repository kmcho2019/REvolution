Here's a refactored solution that maintains the shift register concept but fixes the data handling issues:

1. Instead of shifting both bytes through the register, we'll use a 16-bit register that stores the first byte in the upper bits when it arrives
2. When the second byte arrives, we'll combine it with the stored upper byte and output the complete 16-bit word
3. We'll use a simple flag (has_upper) to track whether we have the first byte stored
4. The output logic becomes straightforward: valid_out is only high when we have both bytes
5. Reset clears all registers and flags
6. This approach ensures proper byte ordering and meets all timing requirements
