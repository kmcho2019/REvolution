The main issue with the previous implementation is that it doesn't handle continuous data streaming properly. The state machine immediately returns to IDLE after OUTPUT state, which could cause missed data when new valid inputs arrive in quick succession.

Key fixes:
1. Modify the state machine to handle continuous data flow by:
   - Transitioning from OUTPUT back to FIRST_BYTE (not IDLE) when new valid data arrives
   - This allows immediate processing of the next data pair
2. Maintain all other functionality:
   - Still store first byte in FIRST_BYTE state
   - Still output concatenated data in OUTPUT state
   - Still assert valid_out only during OUTPUT state
3. Reset behavior remains unchanged

This ensures:
- No data loss during continuous operation
- Proper handling of back-to-back conversions
- Same correct behavior for single conversions
- Minimal additional hardware overhead
