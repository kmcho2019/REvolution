I'll implement the edge detector as a finite state machine (FSM) with 3 states:
1. IDLE: No edge detected
2. RISING: Rising edge detected (output rise=1)
3. FALLING: Falling edge detected (output down=1)

The FSM will:
- Transition to RISING when a changes from 0→1
- Transition to FALLING when a changes from 1→0
- Always return to IDLE on the next clock cycle
- Handle reset conditions properly

This approach provides:
1. Explicit state tracking for better debug visibility
2. Potential for easy extension to detect more complex patterns
3. Clear separation of edge detection logic
4. Synchronous outputs that are guaranteed to be one-cycle pulses
