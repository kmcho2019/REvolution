I'll implement the pulse detection using a Moore-type FSM with 4 distinct states:
1. IDLE: Waiting for the first '0' in the sequence
2. GOT_0: Received first '0', waiting for '1'
3. GOT_01: Received '0' then '1', waiting for final '0'
4. PULSE_DETECTED: Final state that outputs the pulse

Key advantages:
- Explicit state transitions make the design more readable and verifiable
- Easier to modify if pulse criteria changes (e.g., different patterns)
- Clear separation between state transitions and output logic
- More robust against glitches since it requires proper sequence
- Can be easily extended for more complex patterns if needed

The FSM will:
- Start in IDLE state
- Transition through states only when proper input sequence occurs
- Output '1' only in PULSE_DETECTED state
- Immediately return to IDLE after detection
