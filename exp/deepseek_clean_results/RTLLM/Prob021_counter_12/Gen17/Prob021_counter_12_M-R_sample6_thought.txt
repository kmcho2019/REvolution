I'll refactor the counter using a combinational always block for the next state logic and a sequential always block for the state register. This separates the combinational and sequential logic cleanly. The key changes are:

1. Split the logic into:
   - Combinational block to calculate next state
   - Sequential block for state transition
2. Use synchronous reset for better timing
3. Remove clock gating (use enable signal synchronously)
4. Simplify terminal count detection to direct comparison
5. Make the counter behavior more explicit with named states

This approach improves:
- Timing by removing clock gating
- Readability by separating combinational and sequential logic
- Maintainability with explicit state handling
- Synthesis predictability with standard synchronous design
