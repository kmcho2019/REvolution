Instead of using a conventional binary counter, I'll implement a shift-register based counter with parallel load. This approach offers:
1. Lower power consumption since only one bit flips per count (except during wrap-around)
2. Simpler comparison logic (just check MSB for wrap-around)
3. Built-in glitch-free clock gating by using the valid_count as a load enable
4. Reduced area by eliminating the need for a full comparator
5. Better timing as the critical path is just the shift operation

The design works by:
- Using a 4-bit shift register that rotates left
- Loading 4'b0001 when reset or wrapping around
- Shifting only when valid_count is active
- The current count is represented by the position of the '1' in the shift register
