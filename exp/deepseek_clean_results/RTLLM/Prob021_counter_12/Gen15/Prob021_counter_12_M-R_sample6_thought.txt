Refactoring the counter design using continuous assignments and combinational logic instead of procedural blocks:

1. Main Changes:
- Replace the always block with continuous assignments
- Use a combinational next_state logic driven by current state and control signals
- Separate the state update into a flip-flop process
- This makes the design more modular and potentially more synthesis-friendly

2. Benefits:
- Clear separation of combinational and sequential logic
- Easier to add additional features or modify behavior
- More explicit data flow
- Maintains same functionality while showing alternative implementation

3. Implementation Details:
- Create a next_count wire that calculates the next value
- Use simple D-flip-flops for state storage
- Keep the same reset and enable behavior
- Explicit comparison for wrap-around remains
