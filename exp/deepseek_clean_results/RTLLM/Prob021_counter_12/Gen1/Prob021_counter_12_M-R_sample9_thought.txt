I'll refactor the counter using a combination of combinational and sequential logic blocks. The key changes are:
1. Separate the next-state logic into a combinational block using assign statements
2. Use a dedicated register block for state storage
3. Move the wrap-around logic to the combinational part
4. Make the reset behavior more explicit

This approach separates concerns more clearly:
- Combinational logic handles the counting rules
- Sequential logic handles state storage
- The structure is more modular and potentially easier to optimize
