To refactor the counter while maintaining the same functionality, I'll implement it using:
1. Continuous assignment (assign) instead of always blocks
2. A combinational next-state logic block
3. A separate register for state storage
4. Explicit wrap-around logic at count=11

Key advantages:
- Separates combinational and sequential logic clearly
- Makes the wrap-around condition more explicit
- Maintains same functionality with different implementation style
- Uses minimal logic operations (just +1 and reset)
- Still automatically handles 4-bit overflow naturally
