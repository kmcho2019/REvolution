Refactoring Strategy:
1. State Machine: Convert the procedural always block state machine to a combinational/sequential split using assign statements for next-state logic
2. Counter Logic: Move counter decrement to a separate always block for clearer timing control
3. Pedestrian Logic: Implement the pass_request handling as a separate combinational block
4. Output Generation: Keep direct combinational assignments but make them more explicit
5. Reset Handling: Maintain synchronous reset but separate the reset logic for clarity
6. Parameterization: Keep timing parameters but make them more visible at module level

Key Improvements:
- Clear separation of combinational and sequential logic
- More modular design with distinct functional blocks
- Easier to modify individual components (state transitions, counter logic)
- Maintains same functionality while improving readability
- Better matches synchronous design best practices
