I'll refactor the traffic light controller with these key changes:

1. Replace the sequential always block with combinatorial logic for state transitions
2. Use a separate always block just for register updates
3. Implement the counter as a down-counter with synchronous load
4. Make pedestrian request handling more explicit with a separate condition check
5. Use parameterized timing constants for better maintainability
6. Keep the same state encoding but make transitions more visible

The benefits are:
- Clear separation of combinatorial and sequential logic
- More explicit state transition conditions
- Easier to modify timing parameters
- Maintains same functionality while being more readable
