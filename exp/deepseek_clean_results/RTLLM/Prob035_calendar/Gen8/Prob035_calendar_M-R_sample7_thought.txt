I'll refactor the calendar module using a more modular approach with these key changes:
1. Separate the time counters into individual always blocks with enable signals
2. Use hierarchical enable signals (sec_overflow enables min counter, min_overflow enables hour counter)
3. Implement the counters with clear rollover conditions
4. Use assign statements for overflow detection to simplify the always blocks
5. Maintain the same functionality but with better timing characteristics

The benefits are:
- More balanced timing paths since each counter has its own always block
- Clearer separation of concerns between different time units
- Reduced combinational path depth compared to nested if-else
- Enable signals reduce unnecessary switching activity
- Easier to modify or extend individual counters
