To optimize the perpetual calendar module, I'll implement a more efficient structure with these improvements:
1. Use a single always block for synchronous updates to minimize redundant logic
2. Implement a state machine approach for clearer time progression logic
3. Use hierarchical conditions to simplify the rollover logic
4. Right-size the hours counter to 5 bits since it only needs to count to 23
5. Use blocking assignments for intermediate calculations to improve timing

The new design will:
- Still maintain the same functionality (0-23 hours, 0-59 minutes/seconds)
- Handle reset the same way
- Be more power efficient by reducing unnecessary comparisons
- Have better timing characteristics by reducing logic depth
