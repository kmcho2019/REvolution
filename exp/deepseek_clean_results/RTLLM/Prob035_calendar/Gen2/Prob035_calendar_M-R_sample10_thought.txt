I'll refactor the calendar module using a single always block with a state machine approach. This offers several improvements:
1. Consolidates all timekeeping logic into one synchronous block for better timing control
2. Eliminates redundant comparison logic by calculating all time increments in sequence
3. Uses local variables to store intermediate values before final assignment
4. Maintains the same functionality while potentially improving PPA metrics
5. Simplifies reset handling with a single conditional block

The state machine approach processes time updates in this order:
1. First handles seconds increment/rollover
2. Then processes minutes based on seconds rollover
3. Finally handles hours based on minutes rollover
All updates happen in one clock cycle with clear dependency ordering.
