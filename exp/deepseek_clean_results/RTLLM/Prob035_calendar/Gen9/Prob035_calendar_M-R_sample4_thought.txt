I'll refactor the calendar module using a more dataflow-oriented approach with these key changes:
1. Replace the always block with continuous assignments for combinational logic
2. Use a single register update block for sequential elements
3. Implement rollover conditions as separate combinational logic
4. Maintain the same functionality but with clearer signal flow
5. Keep the same bit widths (5-bit Hours, 6-bit Mins/Secs)

The advantages of this approach are:
- Clear separation of combinational and sequential logic
- More explicit data flow through the design
- Easier to pipeline if needed for timing
- More straightforward timing analysis
- Maintains same power/area characteristics while improving readability
