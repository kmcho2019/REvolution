I'll refactor the frequency divider using a different approach that:
1. Separates the counter logic from the clock generation
2. Uses continuous assignment for the clock output
3. Implements the counter as a separate always block
4. Generates a toggle signal when counter reaches limit
5. Uses this toggle signal to drive the output clock

Key changes:
- Counter logic remains in sequential always block
- Toggle signal is generated combinatorially
- Output clock uses continuous assignment based on toggle
This maintains the same functionality but with clearer separation of concerns.
