Here's a novel approach using a handshake mechanism between clock domains:
1. Instead of directly synchronizing the enable signal, we implement a request-acknowledge handshake protocol
2. The clk_a domain sets a request flag when data_en is high
3. The request is synchronized to clk_b domain through two flip-flops
4. The clk_b domain responds with an acknowledge signal synchronized back to clk_a
5. Data is only transferred when both request and acknowledge are active
6. This provides better metastability protection and ensures data stability

Key advantages:
- More robust synchronization with explicit handshake
- Clear indication when data transfer is complete
- Better handling of clock domain crossing timing
- Still meets all original requirements
