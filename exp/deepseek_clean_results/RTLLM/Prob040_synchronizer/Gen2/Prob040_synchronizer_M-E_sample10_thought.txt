This solution implements a handshake protocol between clock domains for robust synchronization:

1. Architecture:
- Uses a request-acknowledge handshake to safely transfer data across clock domains
- Eliminates the need for traditional two-flop synchronizers for data path
- Implements a 4-phase handshake protocol for maximum reliability

2. Key Features:
- Request signal (req) is generated in clk_a domain when data_en is high
- req is synchronized to clk_b domain using two flip-flops
- Data is captured in clk_b domain when synchronized req is detected
- Acknowledge signal (ack) is sent back to clk_a domain to complete handshake
- Data is only updated when handshake completes

3. Advantages:
- Guarantees data stability during transfer
- Works well with the given constraints (data_en stable for 3 cycles)
- Naturally handles the infrequent data changes
- More robust against metastability than simple synchronizers
