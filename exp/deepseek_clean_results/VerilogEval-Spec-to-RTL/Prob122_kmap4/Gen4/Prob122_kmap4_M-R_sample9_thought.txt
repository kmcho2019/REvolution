The original solution uses a single continuous assignment with nested XOR operations. While this is perfectly valid and efficient, we can refactor it to:
1. Break down the XOR operations into intermediate signals for better readability and debugging
2. Maintain the same logical functionality and optimal PPA metrics
3. Show the step-by-step XOR computation explicitly

The refactored version will:
- Create two intermediate signals (ab_xor and cd_xor) for the first-level XOR operations
- Then combine them with a final XOR
- This makes the logic more modular and easier to trace in waveforms
- Still results in the same minimal gate count (3 XORs) when synthesized
