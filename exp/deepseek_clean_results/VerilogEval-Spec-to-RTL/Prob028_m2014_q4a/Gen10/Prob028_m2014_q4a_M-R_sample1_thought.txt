The original solution uses a continuous assignment with a ternary operator to implement the D latch. While this works, we can refactor it to use an `always_latch` block instead, which is the more modern and recommended way to explicitly describe latch behavior in SystemVerilog. This makes the design intent clearer to both synthesis tools and human readers while maintaining the same functionality.

Key changes:
1. Replace the continuous assignment with an `always_latch` block
2. Keep the same interface and functionality
3. Make the latch behavior more explicit in the code structure
