Here's a novel approach using a hierarchical state machine with explicit state encoding:

1. Use a 3-bit state encoding to represent all possible states:
   - [2]: Direction (0=right, 1=left)
   - [1:0]: Action state (00=walking, 01=digging, 10=falling)

2. Implement a priority-based state transition logic:
   - Falling has highest priority (ground=0)
   - Digging comes next (dig=1 when grounded)
   - Bump handling is last priority
   - Each condition is evaluated in parallel for better timing

3. Use a separate register to track the last walking direction during falls/digs
   - Preserves direction information during non-walking states
   - Simplifies recovery logic when returning to walking

4. Optimize output logic using the state bits directly
   - walk_left = state[2] & (state[1:0] == 2'b00)
   - walk_right = ~state[2] & (state[1:0] == 2'b00)
   - aaah = (state[1:0] == 2'b10)
   - digging = (state[1:0] == 2'b01)

This approach provides:
- Clear state separation with minimal encoding bits
- Parallel condition evaluation for better timing
- Direction preservation without extra logic
- Direct output generation from state bits
