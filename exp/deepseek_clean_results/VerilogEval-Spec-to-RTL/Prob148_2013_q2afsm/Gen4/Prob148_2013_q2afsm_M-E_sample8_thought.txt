Novel Architecture Idea: Priority Encoder with State Tracking
1. Instead of traditional FSM states, use a priority encoder to dynamically determine the highest priority request.
2. Maintain a "current_grant" register that tracks which device currently holds the grant.
3. Implement a "hold" mechanism where once a device is granted, it keeps the grant as long as its request is active.
4. Use combinational logic to evaluate new grants only when no device currently holds an active grant.
5. This approach reduces the number of explicit states needed and makes the priority logic more direct.

Key Advantages:
- Eliminates explicit state encoding by tracking grants directly
- Priority logic becomes more transparent in the code
- Easier to extend to more devices if needed
- More efficient when dealing with frequent request changes
