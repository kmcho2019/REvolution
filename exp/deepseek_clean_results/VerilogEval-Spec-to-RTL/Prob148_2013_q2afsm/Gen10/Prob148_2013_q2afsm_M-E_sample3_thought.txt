Here's a novel approach using a priority encoder with state tracking:

1. **Innovative Architecture**: Instead of a traditional FSM, I'll implement a priority encoder that continuously evaluates requests and maintains grant states. This combines combinational priority logic with state tracking for hold functionality.

2. **Key Features**:
   - Priority encoder handles initial grant decisions
   - State tracking maintains grants for active requests
   - Single always block for both state and output logic
   - Uses one-hot encoding for grants (natural for this application)

3. **Advantages**:
   - More direct mapping from spec to implementation
   - Easier to extend for more requesters
   - Clear separation between priority logic and hold logic
   - Reduced state space (only tracks which grant is active)

4. **Implementation**:
   - Current grant stored in a register
   - New grants determined by priority encoder
   - Outputs directly from grant register
   - Reset clears all grants
