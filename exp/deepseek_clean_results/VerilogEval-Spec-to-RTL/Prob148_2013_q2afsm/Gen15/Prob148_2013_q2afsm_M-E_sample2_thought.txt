Novel Architecture Idea: "Parallel Request Evaluation with State Masking"

Key Concepts:
1. Instead of sequential priority evaluation in state A, use parallel request evaluation with masking
2. Implement a "request valid" vector that gets masked based on priority
3. Use a one-hot state encoding for simpler output logic and better timing
4. Introduce a "grant_lock" mechanism to maintain grants until request drops
5. Separate the request processing logic from state transitions for clarity

Advantages:
- Parallel evaluation reduces critical path compared to nested if-else
- One-hot encoding simplifies output logic and improves timing
- Explicit priority masking makes the design more maintainable
- Clear separation between combinational and sequential logic
- Easier to extend for more requestors
