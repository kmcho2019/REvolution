The problem requires implementing a finite state machine (FSM) with 4 states (A, B, C, D) that acts as an arbiter for three requesting devices. The FSM has priority-based arbitration where device 0 has highest priority and device 2 has lowest. The FSM outputs grants (g) to devices based on their requests (r) and maintains the grant as long as the request is active.

Key points:
1. Use binary encoding for states (A=00, B=01, C=10, D=11)
2. Implement synchronous active-low reset (resetn)
3. State transitions follow the given state diagram with priority rules
4. Outputs g[2:0] are set based on current state (B sets g[0], C sets g[1], D sets g[2])
5. Use separate always blocks for state transitions and state storage

The FSM will:
- Stay in state A when no requests or only r2=1 (lowest priority)
- Transition to B when r0=1 (highest priority)
- Transition to C when r1=1 and r0=0
- Transition to D when only r2=1
- Maintain current grant state while request is active
- Return to A when request drops
