Here's a novel approach using a multiplexer-based design with explicit priority encoding:
1. Instead of nested if-else, use a continuous assignment with a ternary operator
2. Create an explicit priority encoder where Load (L) overrides Enable (E)
3. The multiplexer selects between:
   - Current value (hold) when neither L nor E is active
   - Input from previous stage (w) when E is active
   - Load value (R) when L is active
4. This approach makes the priority logic more visible in the code structure
5. The sequential element remains a simple D flip-flop
