Instead of using direct mux-based control, I'll implement this as a tiny state machine with 3 states:
1. HOLD - maintains current value (default)
2. SHIFT - loads value from previous stage (w)
3. LOAD - loads parallel input (R)

The state transitions are controlled by E and L inputs:
- When L=1: go to LOAD state (highest priority)
- When E=1 and L=0: go to SHIFT state
- Otherwise: stay in HOLD state

This approach makes the control logic more explicit and could potentially offer better power savings when in HOLD state since the state machine can be optimized to minimize switching activity.
