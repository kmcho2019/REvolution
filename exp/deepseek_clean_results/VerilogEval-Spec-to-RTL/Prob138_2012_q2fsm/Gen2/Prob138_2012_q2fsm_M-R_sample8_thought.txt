I'll refactor the FSM implementation with these key changes:
1. Use one-hot encoding for states (better for synthesis in many cases)
2. Separate state transition logic into a combinational always block
3. Keep state registers in a separate sequential always block
4. Use continuous assignment for output (z)
5. Make state names more readable with parameters

Benefits:
- One-hot encoding typically results in simpler decoding logic
- Separating combinational and sequential logic improves readability
- Named states make the code more maintainable
- Output remains purely combinational for minimal latency
