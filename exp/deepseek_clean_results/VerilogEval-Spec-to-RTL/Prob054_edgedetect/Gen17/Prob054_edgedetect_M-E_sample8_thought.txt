Instead of the conventional two-register approach, I'll implement a more flexible edge detection system using:
1. A shift register to maintain history of each input bit (4 cycles deep)
2. XOR operations to detect any changes between consecutive cycles
3. Additional logic to specifically identify 0->1 transitions
4. Parameterized depth for adjustable sensitivity

This approach offers:
- Ability to detect edges with configurable history depth
- Potential for detecting more complex patterns (like glitches)
- Clear separation between history storage and edge detection logic
- Easier extension to detect other edge types (negative, both)
