The original implementation uses a continuous assignment with logical OR and negation. We can refactor this to use a gate-level primitive (`nor`) instead. This approach:

1. Maintains identical functionality while using a different coding style
2. Makes the code more explicit about the intended gate-level implementation
3. May be preferred in some design flows where gate-level primitives are explicitly required
4. Still synthesizes to the same basic gate structure (NOR) in any modern synthesis tool

The refactored version will use the `nor` gate primitive, which is the most direct representation of the desired functionality.
