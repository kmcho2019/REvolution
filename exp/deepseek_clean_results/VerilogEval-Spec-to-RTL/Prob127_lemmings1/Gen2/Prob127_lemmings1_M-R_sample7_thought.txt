I'll refactor the solution by implementing the state machine using continuous assignments instead of procedural blocks. This approach:

1. Eliminates the always block by using:
   - A wire for next_state calculation
   - An assign statement for state register updates

2. Maintains identical functionality:
   - Same state encoding (LEFT=0, RIGHT=1)
   - Same asynchronous reset behavior
   - Same output logic

3. Benefits:
   - More dataflow-oriented style
   - Eliminates procedural blocks for those preferring pure structural/RTL
   - Makes state transitions more immediately visible in the code
   - Maintains same PPA characteristics since synthesis will produce identical hardware

The key insight is that we can express the state transitions as combinational logic and the state storage as a simple DFF with async reset, all using continuous assignments.
