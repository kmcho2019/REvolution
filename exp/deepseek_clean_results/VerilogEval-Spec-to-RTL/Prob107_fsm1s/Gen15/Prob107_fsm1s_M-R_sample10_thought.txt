I'll refactor the state machine implementation with these changes:
1. Use a single always block for both state transition and output logic (Mealy-Moore hybrid style)
2. Eliminate the separate next_state register by computing transitions directly
3. Keep the state encoding as parameters for clarity
4. Maintain synchronous reset functionality
5. Use a simple continuous assignment for the output

This approach reduces the number of always blocks while maintaining the same functionality. The state transitions and output logic are combined in one sequential block, which can sometimes lead to more compact code for simple FSMs.
