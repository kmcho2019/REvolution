Revised approach addressing the feedback issues:

1. **State Machine Implementation**: Properly implement a state machine that tracks both current and previous water levels based on sensor inputs. This requires encoding the water level into distinct states.

2. **Correct Flow Rate Mapping**: 
   - fr0: active when water is below s[2] (all states except above s[2])
   - fr1: active when water is between s[1]-s[0] or below s[0]
   - fr2: active only when water is below s[0]

3. **Supplemental Flow Logic (dfr)**: 
   - Activate when current level is higher than previous level (rising water)
   - Maintain supplemental flow when below s[0] (all outputs active)

4. **Reset Handling**: 
   - Synchronous reset sets all outputs to 1 (maximum flow)
   - Reset state assumes water was below s[0] (no sensors active)

5. **Level Encoding**: 
   - 00: Below s[0] (no sensors)
   - 01: Between s[0]-s[1] (only s[0])
   - 10: Between s[1]-s[2] (s[0] and s[1])
   - 11: Above s[2] (all sensors)
