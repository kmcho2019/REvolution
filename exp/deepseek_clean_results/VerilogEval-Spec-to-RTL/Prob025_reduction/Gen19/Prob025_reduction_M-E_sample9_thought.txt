Here's a novel approach using a hierarchical XOR tree structure:
1. Instead of using the reduction operator, we'll explicitly build a balanced XOR tree
2. First stage: XOR bits in pairs (4 parallel XORs)
3. Second stage: XOR the results in pairs (2 parallel XORs)
4. Final stage: XOR the last two results
5. This mimics how synthesis tools would implement the reduction operator, but gives us explicit control over the structure
6. Benefits:
   - Same functionality as reduction operator
   - More transparent data flow
   - Easier to modify for specific timing constraints
   - Can be extended to pipeline stages if needed
   - Shows the underlying hardware structure clearly
