The current solution uses a chain of ternary operators which is functionally correct but can be simplified. Since this is a pure combinational mapping with only 8 possible input cases (3-bit input), we can use a more straightforward case statement approach. This will:

1. Eliminate the unnecessary default case since all 3-bit combinations are covered
2. Make the code more readable and maintainable
3. Potentially improve synthesis results as case statements are well-optimized in most tools
4. Remove the redundant default case that can never be reached
5. Keep the same functionality with cleaner code structure
