The current implementation uses a chain of ternary operators which creates a long critical path. To optimize for better PPA (Power, Performance, Area), we can:

1. Use a case statement instead of ternary operators to:
   - Improve timing by creating a balanced multiplexer structure
   - Potentially reduce power by avoiding evaluation of all conditions
   - Allow synthesis tools to better optimize the implementation

2. Add a default case to handle undefined inputs (though not strictly needed here as input is 3-bit)

3. Use hexadecimal constants directly in the case statement for better readability

This approach should maintain the same functionality while potentially improving timing and power characteristics.
