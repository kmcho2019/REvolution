The original implementation uses a series of ternary operators for the lookup table. We can refactor this to use a case statement inside an always block, which:
1. Makes the mapping more readable and maintainable
2. Still maintains combinational logic by using always @(*)
3. Explicitly shows all possible cases for a 3-bit input
4. May result in slightly different synthesis patterns while being functionally equivalent

The mapping remains identical:
0 -> 1232 (hex)
1 -> aee0 (hex)
2 -> 27d4 (hex)
3 -> 5a0e (hex)
4 -> 2066 (hex)
5 -> 64ce (hex)
6 -> c526 (hex)
7 -> 2f19 (hex)
