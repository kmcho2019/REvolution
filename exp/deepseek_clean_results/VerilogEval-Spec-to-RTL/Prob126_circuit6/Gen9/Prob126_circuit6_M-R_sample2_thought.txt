The current implementation uses a chain of ternary operators which can lead to long critical paths. We can refactor this to use a case statement inside an always block, which:
1. Makes the mapping more explicit and readable
2. Typically synthesizes to more balanced logic trees
3. Still maintains combinational behavior
4. Potentially improves timing by avoiding long chains of conditional operators

The functionality remains identical - mapping each 3-bit input to a specific 16-bit output value.
