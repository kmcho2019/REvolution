The original solution uses a series of ternary operators for the lookup table. We can refactor this to use a case statement inside an always block, which:
1. Makes the mapping more explicit and easier to read
2. Potentially allows for better synthesis optimization
3. Still maintains the same combinational behavior
4. Groups all conditions together in a single construct
5. Provides a clear default case (though not strictly needed for 3-bit input)

The functionality remains identical:
0 -> 1232 (hex)
1 -> aee0 (hex)
2 -> 27d4 (hex)
3 -> 5a0e (hex)
4 -> 2066 (hex)
5 -> 64ce (hex)
6 -> c526 (hex)
7 -> 2f19 (hex)
