I'll refactor the code to use continuous assignments (assign statements) instead of an always block. This approach has several advantages:

1. More explicit combinational logic representation
2. Potentially clearer mapping to hardware
3. Avoids the need for procedural blocks for simple combinational logic
4. May lead to better synthesis results in some cases

The key changes will be:
1. Replace the always block with assign statements for next_state bits
2. Use bitwise OR operations to combine transitions from multiple active states
3. Keep the same state transition logic but express it as continuous assignments
4. Maintain the same output logic but implement it with assign statements

This approach should maintain the same functionality while potentially offering better synthesis results due to the more direct mapping to combinational logic.
