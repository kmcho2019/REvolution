The current implementation is already quite optimized, but we can simplify it further by leveraging the one-hot encoding properties more effectively:

1. For next_state[0]: Only states A and C can transition to A (when in=0), which are the first and third bits of state
2. For next_state[1]: Only states A, B, and D can transition to B (when in=1), which is all states except C
3. For next_state[2]: Only states B and D can transition to C (when in=0), which are the second and fourth bits
4. For next_state[3]: Only state C transitions to D (when in=1)
5. Output is simply the D state bit

The key simplification is recognizing that next_state[1] can be expressed as (in & ~state[2]) since in one-hot encoding, if state isn't C (state[2]), it must be one of the other states that can transition to B.
