The current implementation is already quite minimal, but we can simplify it further by leveraging the one-hot encoding properties more effectively:

1. For next_state[0]: Only states A (0001) and C (0100) can transition to A when in=0. This can be simplified to checking if either bit 0 or bit 2 is set when in=0.

2. For next_state[1]: States A (0001), B (0010), and D (1000) transition to B when in=1. Since these are all states where bit 2 is not set (except D which is handled by in=1), we can simplify to in=1 AND not state[2].

3. For next_state[2]: Only states B (0010) and D (1000) transition to C when in=0. This is simply checking if either bit 1 or bit 3 is set when in=0.

4. For next_state[3]: Only state C (0100) transitions to D when in=1. This is simply in=1 AND state[2].

5. Output remains unchanged as it's just state[3].

The key simplification is recognizing that with one-hot encoding, we only need to check individual state bits rather than combinations.
