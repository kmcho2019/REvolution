Instead of using direct logic equations, we can implement the state transitions using a multiplexer-based approach:
1. Each next state bit will be driven by a 4:1 mux selecting based on the current state
2. The mux inputs will be determined by the 'in' value for each state
3. This approach makes the state transitions more explicit and potentially more readable
4. The output remains simple as it's just state[3] (D state)

For each next state bit:
- next_state[0] (A): active when (current A and in=0) or (current C and in=0)
- next_state[1] (B): active when (current A and in=1) or (current B and in=1) or (current D and in=1)
- next_state[2] (C): active when (current B and in=0) or (current D and in=0)
- next_state[3] (D): active when (current C and in=1)
