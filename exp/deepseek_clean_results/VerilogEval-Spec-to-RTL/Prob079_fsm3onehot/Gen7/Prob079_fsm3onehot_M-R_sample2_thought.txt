I'll refactor the code by using a case statement inside an always block instead of separate assign statements. This approach:

1. Makes the state transitions more explicit and readable by listing each state case separately
2. Still maintains the one-hot encoding benefits
3. Keeps the combinational logic nature by using always @(*)
4. Groups all state transition logic in one block for better maintainability
5. Preserves the same functionality while presenting it differently

The output logic remains simple and separate since it's just state[3]. This refactoring doesn't change the underlying logic but presents it in a more structured way that might be preferable for some design styles.
