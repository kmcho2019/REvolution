Novel Architectural Idea: State Transition via Priority Encoder
1. Instead of computing each next_state bit separately, use a priority encoder approach:
   - First determine the current state using a priority encoder (since it's one-hot)
   - Then use a compact case statement to compute the next state based on current state and input
   - This reduces redundant logic by sharing the state decoding

2. Output Logic:
   - Keep the simple Moore output assignment (state[3])
   - Add a comment to clarify this is the output for state D

3. Advantages:
   - More readable and maintainable code with explicit state transitions
   - Potentially better for synthesis as it clearly expresses the state machine behavior
   - Easier to modify if state transitions change
   - Still maintains purely combinational implementation
   - Uses minimal operations through smart case statement
