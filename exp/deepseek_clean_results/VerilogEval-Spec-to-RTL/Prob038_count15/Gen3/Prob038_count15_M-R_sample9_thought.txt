To refactor the counter implementation while maintaining the same functionality, we can separate the combinational next-state logic from the sequential state storage. This approach uses:
1. A separate combinational block to calculate the next count value (current + 1, with wrap-around)
2. A sequential block (always @posedge clk) to update the state
3. The reset functionality remains synchronous and active-high
This separation makes the design more modular and can sometimes help with synthesis optimizations.
