I'll refactor the counter implementation while maintaining the same functionality. The key changes will be:

1. Move from procedural always block to continuous assignments using combinational logic
2. Create a next-state calculation block that determines the next count value
3. Use a register to store the current state
4. Maintain the synchronous reset functionality
5. Keep the efficient bitwise toggling logic but express it differently

This approach separates the state calculation from state storage, making the design more modular. The continuous assignments make the combinational logic explicit, while the single always block handles the sequential elements cleanly.
