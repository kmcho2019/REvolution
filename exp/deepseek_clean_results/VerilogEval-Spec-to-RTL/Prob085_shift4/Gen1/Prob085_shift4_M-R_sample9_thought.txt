I'll refactor the solution by separating the combinational and sequential logic:
1. Use an always block only for the flip-flop behavior (clock and reset)
2. Move the control logic to a combinational block using continuous assignments
3. Create a next_state signal that handles the load/enable priority
4. This approach makes the design more modular and potentially easier to optimize

The priority handling remains the same (reset > load > enable), but now the control logic is separated from the state storage.
