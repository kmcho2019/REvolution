To refactor this implementation while maintaining the same functionality, I'll switch from using an always block with case statement to using continuous assignments with conditional operators. This approach:

1. Replaces the procedural always block with combinational logic using assign statements
2. Uses nested conditional (?:) operators to implement the multiplexer
3. Maintains the same selection logic and default behavior
4. Results in more concise code while being functionally equivalent
5. May synthesize differently (potentially better for some tools) while maintaining the same PPA characteristics

The key advantages of this approach are:
- More compact representation
- Pure combinational logic without procedural blocks
- Easier to see the direct mapping from inputs to output
- Maintains all original functionality including default case
