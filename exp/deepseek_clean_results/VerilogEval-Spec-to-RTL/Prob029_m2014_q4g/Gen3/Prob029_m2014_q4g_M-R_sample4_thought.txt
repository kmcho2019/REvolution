The original solution uses a two-stage approach with an intermediate wire, which is clear but can be slightly optimized. I'll refactor it to:
1. Eliminate the intermediate wire by combining both operations in a single continuous assignment
2. Maintain the same logical functionality (XNOR of in1/in2 then XOR with in3)
3. Use the same efficient operators (~^ and ^)
4. Keep the purely combinational nature
5. Reduce the line count while preserving readability

This refactoring should maintain identical functionality while being slightly more compact. The PPA impact should be neutral or slightly positive since we're removing one wire declaration while keeping the same gate count.
