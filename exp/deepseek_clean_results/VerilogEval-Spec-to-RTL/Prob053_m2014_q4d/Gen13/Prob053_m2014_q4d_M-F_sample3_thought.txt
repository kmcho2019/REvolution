Since the problem explicitly states there is no reset, we need to handle this differently. In Verilog, we can initialize the register during declaration to ensure a known starting state (0 in this case). This will:

1. Provide a deterministic initial state (0) for simulation
2. Maintain the no-reset requirement from the problem statement
3. Ensure the XOR operation starts with a known value
4. Still work in hardware where initial values might be ignored (but gives consistent simulation)
