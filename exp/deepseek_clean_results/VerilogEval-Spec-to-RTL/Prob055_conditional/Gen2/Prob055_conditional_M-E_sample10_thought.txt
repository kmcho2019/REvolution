A novel approach is to use a tree-based comparator structure that reduces the critical path while maintaining parallel comparison capability. Instead of nested conditionals, we'll:
1. First compare all pairs of inputs in parallel (a vs b, c vs d)
2. Then compare the winners of these first-round comparisons
3. This creates a balanced comparison tree with only 2 levels of logic, improving timing
4. We'll use intermediate wires to store the first-round results for clarity
5. The structure naturally lends itself to pipelining if needed later
