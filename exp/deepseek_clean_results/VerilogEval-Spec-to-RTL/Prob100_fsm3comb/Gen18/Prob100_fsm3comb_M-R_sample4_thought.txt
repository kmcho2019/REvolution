Refactoring approach:
1. Replace the case statement with a more compact assign-based implementation using nested ternary operators
2. Maintain the same state encoding and transition logic
3. Keep the output logic identical since it's already optimal
4. Benefits:
   - Eliminates the always block, reducing simulation overhead
   - Makes the state transitions more explicit in a single expression
   - Potentially better for synthesis as it's a pure combinational expression
5. Trade-offs:
   - Slightly less readable than the case statement version
   - Still maintains all functionality exactly as specified
6. The nested ternary structure directly maps the state transition table into logic
