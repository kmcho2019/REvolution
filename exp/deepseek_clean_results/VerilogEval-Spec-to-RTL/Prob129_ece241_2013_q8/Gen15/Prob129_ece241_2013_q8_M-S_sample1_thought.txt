The existing solution is already quite minimal, but we can simplify it further by:
1. Recognizing that we don't need to store the full history - just the relevant state information
2. Using a state machine with only 3 states (as required) instead of tracking history bits
3. Implementing a classic Mealy FSM where output depends on both state and input
4. Still detecting overlapping sequences by proper state transitions
5. Maintaining the same asynchronous reset functionality

This approach reduces the implementation to just state transitions and output logic, while still meeting all requirements.
