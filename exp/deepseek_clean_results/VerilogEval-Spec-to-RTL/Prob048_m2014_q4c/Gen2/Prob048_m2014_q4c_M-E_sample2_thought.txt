Here's a novel approach using a clock-gated implementation with explicit reset control:
1. Instead of using a simple mux for reset, we'll implement a clock gating mechanism
2. The flip-flop will only update when either reset is active or new data is available
3. This reduces unnecessary toggling of internal nodes when neither reset nor new data is present
4. The reset still remains synchronous but now has more explicit control logic
5. This approach can potentially save power in scenarios where the data input doesn't change frequently
