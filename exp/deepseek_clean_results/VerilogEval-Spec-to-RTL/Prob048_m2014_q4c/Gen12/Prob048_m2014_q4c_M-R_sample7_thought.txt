To refactor while maintaining the same functionality, we can explore alternative implementations:

1. Using continuous assignment with a ternary operator for the output
2. Separating the reset logic into a separate always block (though this isn't typically better)
3. Using a function to encapsulate the flip-flop behavior
4. Implementing with a clock gating approach (though this adds complexity)

The most interesting refactor would be to use a continuous assignment with a registered value. We'll:
- Keep the register declaration
- Use an always block just for the clocked behavior
- Add an assign statement for the output
This separates the registered behavior from the output driver, which could be useful if we later need to add output buffering or other logic.

Note: This is more of a stylistic change than a functional improvement, as synthesis will likely produce the same hardware.
