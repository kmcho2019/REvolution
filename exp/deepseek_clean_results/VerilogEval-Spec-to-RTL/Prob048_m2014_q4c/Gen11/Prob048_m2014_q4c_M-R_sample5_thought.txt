To refactor while maintaining the same functionality, we can separate the synchronous reset logic from the flip-flop behavior. This can be done by:
1. Creating a combinational logic block that handles the reset condition
2. Using a continuous assignment to feed the flip-flop input
3. Keeping the flip-flop itself in a simple always block

This approach makes the reset logic more explicit and separates concerns, which could be beneficial for more complex designs where the reset logic might need to be shared or modified independently.
