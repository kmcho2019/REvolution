To refactor this solution while maintaining the same functionality, I'll make these key changes:

1. Simplify the state machine to just track the counter value instead of explicit states
2. Use a 2-bit counter (sufficient for counting 0-3) with synchronous reset
3. Generate shift_ena directly based on whether counter hasn't reached 3 yet
4. The counter will:
   - Reset to 0 on system reset
   - Increment each cycle until it reaches 3
   - Stay at 3 until next reset

This approach eliminates the explicit state machine while maintaining identical behavior - shift_ena is high for exactly 4 cycles (counter values 0-3) after reset.
