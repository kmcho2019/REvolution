Refactored solution approach:
1. Maintain the 2-bit counter concept but add a "done" flag to track completion
2. Use combinational logic for shift_ena:
   - Active when counter is counting (0-3) and not done
3. Sequential logic:
   - Reset sets counter to 0 and clears done flag
   - Count up to 3 (inclusive)
   - Set done flag after 4th cycle (counter == 3)
   - Once done, counter freezes and shift_ena stays low
4. Key improvements:
   - Explicit done state prevents periodic re-enabling
   - Still uses minimal state (2-bit counter + 1-bit flag)
   - Clear separation of combinational and sequential logic
   - Meets "4 cycles then 0 forever" requirement precisely
