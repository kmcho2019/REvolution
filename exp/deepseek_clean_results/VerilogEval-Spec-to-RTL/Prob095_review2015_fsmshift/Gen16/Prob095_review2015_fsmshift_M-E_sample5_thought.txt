Novel approach using a state machine:
1. Instead of using a counter, implement a finite state machine (FSM) with 5 states:
   - IDLE: Initial state, shift_ena = 0
   - S1-S4: Active states where shift_ena = 1
2. The FSM transitions through S1→S2→S3→S4 then back to IDLE
3. Reset forces the FSM into S1, starting the 4-cycle sequence
4. Each state represents one clock cycle of shift_ena assertion
5. After S4, the FSM stays in IDLE until next reset
6. This provides explicit control over each cycle and is more readable/maintainable
7. The state encoding is one-hot for clarity (though could be optimized)
