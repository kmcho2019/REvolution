My novel approach uses a counter-based design instead of a traditional FSM. The key insight is that we can track message progress by counting received bytes after finding a valid start byte. Here's the thought process:

1. Use a 2-bit counter to track which byte we're expecting next (0=waiting for start, 1=first byte, 2=second byte)
2. When in[3]=1 and counter is 0, we've found a start byte - increment counter
3. For subsequent bytes, just increment counter regardless of in[3] value
4. When counter reaches 3, we've received a complete message:
   - Assert 'done' in this cycle
   - Reset counter to 0 to look for next message
5. Reset synchronously clears the counter

This approach is simpler than an FSM because:
- Eliminates explicit state definitions
- Uses arithmetic progression instead of state transitions
- Naturally handles the 3-byte sequence with counter wrap-around
- Still meets all timing requirements
