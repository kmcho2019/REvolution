The key issues in the original implementation stem from improper state transitions and done signal timing. Here's a refactored approach:

1. Maintain the same 3-state FSM (IDLE, BYTE2, BYTE3) but with clearer transition logic
2. Use continuous assignments for outputs to separate combinational logic from state transitions
3. Simplify the state transition logic:
   - Only move to BYTE2 when we see in[3]=1 in IDLE state
   - Always move to next state on each byte (BYTE2->BYTE3, BYTE3->IDLE)
   - Assert done when leaving BYTE3 state
4. Use a counter to track bytes within a message instead of complex conditional transitions

This approach ensures proper message boundary detection and correct done signal timing.
