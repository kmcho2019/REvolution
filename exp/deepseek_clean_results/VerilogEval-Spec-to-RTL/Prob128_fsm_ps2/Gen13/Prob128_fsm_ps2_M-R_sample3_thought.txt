Refactoring Strategy:
1. State Machine Restructuring: Use explicit state names (IDLE, BYTE1, BYTE2, BYTE3) instead of a counter for better readability and maintainability.
2. Combinational Output: Move 'done' to a continuous assignment based on current state for clearer timing.
3. Next State Logic: Separate state transitions into a combinational block for better FSM structure.
4. Synchronous Elements: Keep only the state register in the sequential block.
5. Reset Handling: Maintain synchronous reset but make state transitions more explicit.

Key Benefits:
- Clearer state machine structure with named states
- Separated combinational and sequential logic
- More maintainable and debuggable code
- Same functionality with improved readability
