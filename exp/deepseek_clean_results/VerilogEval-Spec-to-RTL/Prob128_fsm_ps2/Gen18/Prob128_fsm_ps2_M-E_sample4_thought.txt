Instead of using a counter-based FSM, we can implement a shift register that stores the last 3 bytes received. The solution works by:
1. Continuously shifting in new bytes into a 24-bit shift register
2. Checking if the oldest byte in the window (bits[23:16]) has in[3]=1
3. When this condition is met, we know we have a complete 3-byte message
4. We then output 'done' and clear the shift register to start fresh

Advantages:
- No explicit state tracking needed - the shift register inherently maintains message boundaries
- Simple pattern matching logic
- Naturally handles back-to-back messages without resetting counters
- Easily extensible if message format changes
