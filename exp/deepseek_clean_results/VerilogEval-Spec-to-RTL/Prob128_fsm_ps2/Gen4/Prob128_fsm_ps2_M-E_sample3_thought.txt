Here's a novel approach using a counter-based design instead of a traditional state machine. The key ideas are:
1. Use a 2-bit counter to track the byte position (0=waiting, 1=first byte, 2=second byte, 3=third byte)
2. Reset the counter when we're in state 0 and don't see in[3]=1
3. Advance the counter when we're in states 1-3 or when we find a valid start byte
4. Generate 'done' when the counter rolls over from 3 to 0 (or to 1 if next byte is valid)

This approach eliminates explicit state transitions and instead uses arithmetic progression, which might be more area-efficient in some implementations. The counter naturally handles the 3-byte sequence and reset conditions.
