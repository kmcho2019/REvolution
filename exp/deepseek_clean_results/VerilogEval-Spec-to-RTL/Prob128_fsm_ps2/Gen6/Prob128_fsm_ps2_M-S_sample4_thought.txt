The current solution can be simplified by:
1. Removing the explicit state checking for byte_counter == 0 since we can handle all cases with a single if-else structure
2. Combining the increment and done logic into a single condition
3. Using simpler reset logic that doesn't require separate assignments
4. Making the counter increment unconditional when in a message (simpler logic)
The key insight is that we only need to track whether we're at byte 1, 2, or 3, and the in[3] check naturally resets this tracking.
