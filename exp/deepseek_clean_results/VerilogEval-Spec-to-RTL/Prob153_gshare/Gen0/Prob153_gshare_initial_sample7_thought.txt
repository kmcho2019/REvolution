To implement a gshare branch predictor with the given specifications, we need to:
1. Maintain a 7-bit global history register (GHR) that tracks branch outcomes
2. Use a 128-entry PHT (2-bit saturating counters) indexed by XOR of PC and GHR
3. Handle prediction and training interfaces separately but with precedence rules
4. Update GHR on predictions (unless overridden by training)
5. Update PHT and potentially recover GHR during training
6. Handle concurrent prediction/training with proper precedence

Key points:
- Prediction uses current PHT state and outputs current GHR
- Training updates PHT on next clock edge
- On misprediction, GHR is recovered to train_history
- Training has priority over prediction updates
- All updates happen on clock edges with async reset
