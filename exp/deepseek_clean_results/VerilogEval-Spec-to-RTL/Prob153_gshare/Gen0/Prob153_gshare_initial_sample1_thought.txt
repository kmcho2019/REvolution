To implement a gshare branch predictor with the given specifications, we need to:
1. Maintain a 7-bit global history register (GHR) that tracks branch outcomes
2. Use a 128-entry pattern history table (PHT) of 2-bit saturating counters
3. For predictions: XOR the PC with GHR to index into PHT, output prediction based on MSB of counter
4. For training: Update PHT counters based on actual branch outcomes (increment for taken, decrement for not taken)
5. Handle concurrent predict/train operations with proper priority (train takes precedence)
6. Manage GHR updates - update on predictions unless there's a misprediction training
7. Handle reset condition to initialize all state

Key points:
- PHT updates happen at next clock edge
- Prediction uses current PHT state
- Misprediction recovery restores GHR to train_history
- XOR of PC and GHR gives PHT index
- 2-bit counters: 11/10 -> predict taken, 01/00 -> predict not taken
