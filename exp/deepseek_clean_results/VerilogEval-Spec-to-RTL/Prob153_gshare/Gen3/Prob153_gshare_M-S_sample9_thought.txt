To simplify the gshare branch predictor implementation while maintaining functionality:

1. **Single GHR Update Path**: Instead of multiple update paths, use a single always block with clear priority logic (misprediction > training > prediction).

2. **Direct PHT Access**: Keep the PHT access simple - predictions use current state, training updates take effect next cycle.

3. **Simplified Counter Update**: Move the counter update logic inline rather than using a function.

4. **Clear Priority Handling**: Explicitly handle the priority of operations in the GHR update logic.

Key simplifications:
- Remove separate function for counter update
- Consolidate GHR update logic into a single always block
- Maintain clear timing separation between prediction and training
- Keep the same core functionality with fewer intermediate signals
