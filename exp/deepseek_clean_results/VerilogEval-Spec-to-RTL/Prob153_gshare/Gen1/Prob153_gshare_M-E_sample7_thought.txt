Here's a novel approach to implement the gshare branch predictor with improved timing and priority handling:

1. **Separate Prediction and Update Paths**: Use distinct combinational paths for prediction and training to avoid timing conflicts.

2. **Shadow GHR for Mispredictions**: Maintain a shadow copy of GHR that gets updated immediately during mispredictions, while the main GHR updates normally. This allows for faster recovery without disrupting the prediction pipeline.

3. **Three-Phase Update Logic**:
   - Phase 1: Calculate predictions using current state
   - Phase 2: Process training updates (with priority)
   - Phase 3: Update state registers at clock edge

4. **Early Misprediction Resolution**: When a misprediction occurs, immediately override any pending prediction updates with the correct history.

5. **Optimized PHT Access**: Use the current GHR for predictions and training GHR for updates, with proper muxing to handle concurrent operations.

Key innovations:
- Shadow GHR enables single-cycle misprediction recovery
- Strict separation of combinational and sequential logic
- Explicit priority handling through structured state updates
- Clean separation of prediction and training paths
