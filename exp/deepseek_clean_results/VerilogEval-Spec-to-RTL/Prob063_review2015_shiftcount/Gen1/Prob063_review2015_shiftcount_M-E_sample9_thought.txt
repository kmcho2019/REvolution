Instead of using separate shift and count logic, we can leverage the fact that both operations can be viewed as specific forms of bit manipulation. The key insight is:
1. For shifting: We're effectively doing a rotate-left with new data inserted at LSB
2. For counting: We can implement decrement using bitwise operations that might share some logic with shifting

The novel aspect is using a unified operation selector that combines both functions into a single expression, potentially reducing the critical path. We'll also use a more efficient decrement implementation by exploiting the fact that decrement is equivalent to adding all 1's (2's complement of 1).
