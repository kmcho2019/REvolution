Refactoring Approach: Flattened Combinational Logic
1. Instead of using sub-modules, we'll implement all operations directly in the TopModule using continuous assignments
2. This approach:
   - Eliminates hierarchical overhead
   - Makes all operations immediately visible in one place
   - Still maintains clear separation of concerns through distinct assign statements
3. The logical OR implementation is simplified to a single OR reduction of the bitwise OR result
4. The NOT operation remains clearly expressed through concatenation
5. Benefits:
   - Slightly reduced area (no module instantiation overhead)
   - All operations remain purely combinational
   - Clear visibility of all transformations in one module
