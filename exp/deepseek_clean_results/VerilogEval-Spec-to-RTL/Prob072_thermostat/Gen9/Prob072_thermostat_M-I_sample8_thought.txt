The current implementation is already quite efficient, but we can make a few minor optimizations:

1. **Fan Logic Optimization**: Since heater and aircon are mutually exclusive (mode selects between them), their OR operation can be simplified to a XOR operation when combined with fan_on. However, standard OR is actually more efficient in this case.

2. **Signal Sharing**: We can create a single intermediate signal for the temperature control output (heater or aircon) which could slightly reduce fan logic complexity.

3. **Power Gating Consideration**: While not implemented here, in a real design we might add enable signals to gate the outputs when not in use to save power.

The optimized version maintains the same functionality but with slightly clearer signal relationships:
- temp_ctrl = (mode & too_cold) | (~mode & too_hot)
- heater = mode & too_cold
- aircon = ~mode & too_hot
- fan = temp_ctrl | fan_on
