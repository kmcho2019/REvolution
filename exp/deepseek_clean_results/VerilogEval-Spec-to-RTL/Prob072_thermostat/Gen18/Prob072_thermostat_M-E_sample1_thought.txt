I'll implement a state machine with 4 distinct states:
1. IDLE: No heating/cooling needed
2. HEATING: Heater is active
3. COOLING: Aircon is active
4. FAN_ONLY: Only fan is active by user request

This approach:
1. Provides clear separation of operating modes
2. Makes it easier to add hysteresis or timing controls in future
3. Explicitly handles the fan request as a separate state
4. Uses next-state logic that's easy to understand and modify
5. Could be extended with more states for complex control sequences

The state transitions are:
- IDLE → HEATING when mode=1 and too_cold=1
- IDLE → COOLING when mode=0 and too_hot=1
- Any state → FAN_ONLY when fan_on=1
- Returns to IDLE when conditions no longer met
