Instead of pure combinational logic, we can model this as a simple state machine with 4 states:
1. IDLE: Neither heating nor cooling
2. HEATING: Heater is on
3. COOLING: Aircon is on
4. FAN_ONLY: Only fan is on by request

The state transitions are:
- From IDLE: 
  - to HEATING when mode=1 and too_cold=1
  - to COOLING when mode=0 and too_hot=1
  - to FAN_ONLY when fan_on=1
- From HEATING/COOLING:
  - Return to IDLE when temperature is normal
  - Can also go to FAN_ONLY if fan_on=1 while active
- From FAN_ONLY:
  - Return to IDLE when fan_on=0
  - Can transition to HEATING/COOLING if conditions met

This approach makes the behavior more explicit and could be easier to modify/extend later.
