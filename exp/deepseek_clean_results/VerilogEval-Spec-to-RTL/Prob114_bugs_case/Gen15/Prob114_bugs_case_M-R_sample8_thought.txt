To refactor the solution while maintaining the same functionality, I'll implement it using continuous assignments (assign statements) instead of an always block. This approach:

1. Eliminates the need for procedural blocks, making it purely combinational
2. Uses parallel ternary operators for each valid case
3. Combines the outputs into single expressions
4. Maintains the same default behavior (0 outputs when invalid)
5. Results in cleaner code with direct mapping of inputs to outputs

The valid signal will be OR of all valid cases, and the output will be a weighted sum of all valid cases. This approach is more declarative and may be more efficient for synthesis as it clearly expresses the combinatorial nature of the logic.
