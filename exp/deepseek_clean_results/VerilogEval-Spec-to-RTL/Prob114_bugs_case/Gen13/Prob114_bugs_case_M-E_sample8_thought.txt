Instead of using a case statement or sequential comparisons, we can implement:
1. A compact ROM-based lookup table that stores both the digit value and validity
2. The ROM is indexed directly by the input code
3. Invalid codes map to zero outputs by default ROM initialization
4. Valid codes are stored at their specific addresses
5. The ROM output is split into the digit value and valid signal

Advantages:
- Single-cycle lookup with no complex logic
- Naturally handles sparse code space efficiently
- Easy to modify/expand by just changing the ROM contents
- Clean separation of data (ROM) from logic
- Potentially better PPA as ROMs are highly optimized in FPGAs/ASICs
