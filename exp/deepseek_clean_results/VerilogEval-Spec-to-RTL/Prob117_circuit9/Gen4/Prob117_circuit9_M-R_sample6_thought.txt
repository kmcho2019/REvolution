I'll refactor the solution using a continuous assignment approach combined with a register. The key changes are:

1. Separate the storage and logic into distinct parts
2. Use an always block just for the register (q_reg)
3. Use a continuous assignment for the combinational next-state logic
4. The increment/wrap logic remains the same but is now in the combinational part
5. The muxing between hold/increment is handled by the ternary operator in the assignment

This approach makes the design more modular by separating the sequential and combinational logic, which can be beneficial for synthesis and verification.
