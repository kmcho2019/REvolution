Refactoring approach:
1. Instead of using an always block with synchronous logic, we'll implement the same behavior using combinational logic with assign statements and a register
2. The counter logic will be separated into:
   - A combinational next_state calculation
   - A synchronous register update
3. This makes the design more modular and explicit about the separation between combinational and sequential logic
4. The functionality remains identical: reset to 4 when a=1, increment and wrap when a=0
