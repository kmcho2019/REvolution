The original implementation uses an always block for sequential logic and a separate assign for combinational logic. We can refactor this to:
1. Use continuous assignments for both the counter update and tc generation
2. Eliminate the explicit if-else structure by using ternary operators
3. Maintain the same functionality while potentially reducing area by simplifying the control logic

The key insight is that the counter behavior can be expressed as a single multiplexer operation that selects between:
- data input when load is high
- counter-1 when load is low and counter isn't zero
- counter (no change) otherwise
