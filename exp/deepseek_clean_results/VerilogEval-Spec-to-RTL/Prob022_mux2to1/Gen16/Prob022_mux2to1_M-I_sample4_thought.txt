Improved Strategy: Ternary Operator for Cleaner RTL
1. While the bitwise implementation is correct, we can achieve the same functionality with cleaner, more readable code using a ternary operator
2. The ternary operator (?:) directly represents the multiplexer behavior in a single line
3. Benefits:
   - More intuitive and readable code (direct mapping to mux concept)
   - Same gate-level implementation as bitwise version (identical PPA)
   - Easier to modify and maintain
   - More scalable when extending to wider buses
4. Maintains identical functionality while improving code clarity
5. Expected PPA:
   - Same power/area as previous implementation (4.65e-05 power, 2.0 area)
   - Identical timing characteristics
   - Better readability score for RTL quality metrics
