Fusion strategy combining the best aspects of both examples:
1. Maintain the parameterized delay flexibility from Example 1 for the sequential path
2. Adopt the shared XOR computation from Example 2 to reduce redundant logic
3. Simplify the sequential implementation when DELAY_CYCLES=1 (common case)
4. Keep clean separation between combinational and sequential logic
5. Add explicit reset capability for robustness (though not required in spec)
6. Use blocking assignments for combinational logic, non-blocking for sequential
7. Optimize area by only instantiating the delay chain when needed

Key improvements:
- Shared XOR computation reduces power and area
- Parameterized delay maintains flexibility
- Simplified default case for better PPA
- Clear code structure for maintainability
