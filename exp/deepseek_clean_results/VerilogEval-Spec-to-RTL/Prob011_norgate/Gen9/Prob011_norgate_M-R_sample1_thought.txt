The original implementation uses a continuous assignment with `assign`, which is already optimal for this simple combinatorial logic. However, we can demonstrate alternative implementations that achieve the same functionality while showing different Verilog coding styles:

1. Using an always block with blocking assignment (behavioral style)
2. Using a ternary conditional operator
3. Using a case statement (though overkill for this simple function)

The most meaningful refactor would be to use an always block, which:
- Shows an alternative coding style
- Maintains identical functionality
- Demonstrates procedural assignment
- Could be more readable for some designers
- Would be necessary if we needed to add sequential logic later
