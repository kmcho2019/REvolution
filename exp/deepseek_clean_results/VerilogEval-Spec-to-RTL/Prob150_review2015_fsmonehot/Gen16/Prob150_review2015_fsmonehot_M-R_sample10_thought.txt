Refactoring Strategy:
1. Structural Change:
   - Replace the wire-based combinational logic with an always_comb block for better readability and maintainability
   - Use casez statement for state transitions to make the state machine more explicit and easier to modify
   - Keep the one-hot encoding benefits while making the code more self-documenting

2. Output Logic:
   - Move output logic into the same always_comb block for consistency
   - Use direct state bit checks for outputs to maintain clarity
   - Keep the same functional behavior but with cleaner organization

Key Benefits:
- More readable state machine implementation
- Easier to modify state transitions or add new states
- Maintains same PPA characteristics while improving code structure
- Clear separation between state transition logic and output logic
