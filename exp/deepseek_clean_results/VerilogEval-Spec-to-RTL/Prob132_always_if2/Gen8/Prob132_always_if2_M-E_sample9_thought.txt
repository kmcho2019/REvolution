I'll implement this using a finite state machine (FSM) approach, even though the problem is purely combinational. This unconventional approach demonstrates how even simple logic can be modeled as a state machine, which could be beneficial if:
1. Future requirements need state tracking
2. The design needs to integrate with other FSMs
3. We want to add diagnostic or debug states later

The FSM will have:
- 2 states: NORMAL and SHUTDOWN
- Transitions based on cpu_overheated
- Output logic that combines both requirements
This provides a structured way to handle the logic while maintaining the same functionality.
