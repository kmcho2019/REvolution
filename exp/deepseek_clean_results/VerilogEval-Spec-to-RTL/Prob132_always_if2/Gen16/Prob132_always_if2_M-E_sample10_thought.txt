Here's a novel approach that implements the same functionality but with a different architectural perspective:

1. Instead of using combinational logic, we'll implement this as a simple state machine with two states (normal and emergency)
2. The emergency state handles CPU overheating, while the normal state handles the driving logic
3. This approach provides better scalability if more conditions need to be added later
4. We'll use a parameterized state encoding for better readability
5. The outputs are registered to prevent glitches (though not strictly necessary here, it's good practice)

Benefits:
- More structured approach that's easier to extend
- Registered outputs provide cleaner signals
- Clear separation of concerns between emergency and normal operations
- Better for timing closure in larger designs
