The original solution uses a direct Boolean expression implementation. Let's refactor this to use a case statement approach, which provides:
1. More explicit mapping to the truth table
2. Easier readability and maintainability
3. Potential for better synthesis optimization in some tools
4. Clear correspondence between code and specification

The case statement will directly implement each row of the truth table, making the design intent extremely clear. While functionally identical to the original solution, this approach may be preferred when:
- The truth table might need future modifications
- Code readability is prioritized
- The design needs to be more self-documenting
