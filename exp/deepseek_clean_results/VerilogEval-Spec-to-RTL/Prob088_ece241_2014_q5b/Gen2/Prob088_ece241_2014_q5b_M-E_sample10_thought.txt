I'll implement a novel "transition-triggered" Mealy FSM that:
1. Uses a single flip-flop to track transitions rather than states
2. Encodes the state implicitly in the transition history
3. Generates outputs based on both current input and transition history
4. Maintains one-hot properties by tracking only relevant transitions

Key innovations:
- State is represented by whether we've seen the first '1' (transition from A to B)
- Output logic becomes purely combinatorial based on current state and input
- Reduced state transitions since we only need to track the critical first transition
- Asynchronous reset properly initializes to starting state
- More efficient than traditional one-hot for this specific FSM pattern
