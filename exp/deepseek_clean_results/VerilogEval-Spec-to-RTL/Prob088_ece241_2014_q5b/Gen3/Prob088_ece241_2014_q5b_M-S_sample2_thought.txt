The FSM can be simplified by recognizing that:
1. State B is absorbing (once entered, never left)
2. The output z is simply x when in state A, and ~x when in state B
3. We only need to track whether we're in state B (since state A is just !state_B)

This allows us to:
- Use a single bit state register (state_B) instead of one-hot
- Simplify next state logic to just state_B | (x & !state_B)
- Output logic remains simple: x ^ state_B
- Maintain asynchronous reset to state A (!state_B)
