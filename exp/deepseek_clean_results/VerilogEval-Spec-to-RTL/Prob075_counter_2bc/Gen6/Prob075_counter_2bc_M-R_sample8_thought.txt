I'll refactor the implementation to use continuous assignments (assign statements) instead of procedural blocks for the combinational logic. This approach:
1. Eliminates the need for a separate next_state register
2. Uses ternary operators to directly compute the next state
3. Makes the saturation behavior explicit through conditional expressions
4. May result in more optimized synthesis as it exposes the logic directly to the synthesizer
5. Reduces the number of always blocks while maintaining the same functionality
