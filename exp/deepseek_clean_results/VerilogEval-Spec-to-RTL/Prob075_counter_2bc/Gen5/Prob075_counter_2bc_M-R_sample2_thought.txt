Here's a refactored version using a more arithmetic approach with explicit saturation checks instead of a state machine. The key changes are:

1. Replace the FSM with direct arithmetic operations on the counter value
2. Use ternary operators for saturation checks (preventing overflow/underflow)
3. Maintain the same reset behavior (01 when areset)
4. Simplify the logic by combining increment/decrement conditions into a single expression
5. Use continuous assignments for the state update, making the code more concise

This approach reduces the logic depth by:
- Eliminating the case statement
- Using simple arithmetic with saturation bounds
- Combining the train_valid and train_taken conditions into a single update expression
The behavior remains identical but the implementation is more compact.
