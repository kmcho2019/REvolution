Novel Architecture Idea:
1. Use binary encoding for states (00,01,10,11) to enable arithmetic operations
2. Implement increment/decrement using simple +1/-1 operations with saturation
3. Use a single always_ff block for more compact implementation
4. Explicit saturation checks prevent overflow/underflow
5. Reset to '01' (weakly not-taken) as specified
6. Arithmetic operations are more synthesis-friendly than case statements

Key Advantages:
- More compact implementation using arithmetic
- Easier to extend to wider counters if needed
- Clear saturation boundaries
- Single always block reduces potential synthesis overhead
- Maintains all original functionality
