Instead of using arithmetic operations, we can implement the counter as a 4-state FSM where each state explicitly represents a counter value. The transitions between states are controlled by the train_valid and train_taken inputs. This approach:
1. Eliminates arithmetic operations entirely
2. Uses direct state transitions with clear saturation boundaries
3. Maintains the same functionality but with potentially simpler logic
4. Could offer better timing characteristics as it avoids carry propagation
5. Makes the saturation limits explicit in the state transitions
