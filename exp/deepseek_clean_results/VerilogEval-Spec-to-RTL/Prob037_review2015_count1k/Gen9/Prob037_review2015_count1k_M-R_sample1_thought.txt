I'll refactor the counter using a different approach that:
1. Uses a single always block for both reset and counting logic
2. Eliminates the separate combinational next-state logic
3. Maintains the same functionality (0-999 counter with synchronous reset)
4. Simplifies the design by combining all sequential logic in one block

This approach reduces the number of always blocks and wires while maintaining the same behavior. The synchronous reset and counting logic are combined into a single sequential block, which might be more intuitive for some designers.
