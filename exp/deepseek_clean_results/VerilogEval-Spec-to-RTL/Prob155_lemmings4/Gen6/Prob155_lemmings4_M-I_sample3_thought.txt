   - Explicit priority handling in state transitions (fall > dig > bump)
   - Proper fall counter management with clear reset conditions
   - Correct splat condition checking only when landing

2. State machine structure:
   - Separate direction tracking (left/right) from actions (walk/fall/dig/splat)
   - Only 4 main states with direction as a separate register
   - Clear state transition conditions with proper priorities

3. Priority handling:
   - Fall condition checked first (ground=0)
   - Dig condition checked only if not falling (ground=1)
   - Bump conditions checked only if walking normally (not falling/digging)

4. Fall counter:
   - Reset when not falling
   - Only check splat when landing (ground transition 0->1)
   - Counter increments only during falling

5. Output logic:
   - Pure combinatorial based on current state
   - Clear mapping from states to outputs
   - No complex saved direction logic needed
