I'll implement a hierarchical FSM with two main state categories:
1. Movement states (left/right) - handles walking direction and bump responses
2. Action states (fall/dig/splatter) - handles special behaviors

Key innovations:
- Separate movement and action state machines that operate in parallel
- Movement state persists during actions (stored in a register)
- Fall timer is implemented with saturation to prevent overflow
- Outputs are generated combinatorially based on current states
- Strict priority is enforced by checking action conditions first

This architecture provides cleaner separation of concerns and makes the state transitions more explicit.
