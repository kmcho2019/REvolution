Refactored Lemming State Machine Design:

1. State Encoding:
   - Use one-hot encoding for clearer state representation
   - Separate states for left/right walking to simplify direction logic

2. Output Logic:
   - Move all outputs to continuous assignments
   - Simplify output conditions by directly mapping states

3. Fall Counter:
   - Keep as separate always block for clarity
   - Reset when not in FALL state

4. Transition Logic:
   - Use priority-encoded if-else structure
   - Explicitly handle all transition cases in order of priority

Key Improvements:
- Clearer state representation with one-hot
- More explicit priority handling
- Separated counter logic
- Direct output mapping from states
- Maintains same functionality but with cleaner structure
