Refactored Lemming State Machine Design:

1. Simplified State Encoding:
   - Use one-hot encoding for clearer state representation
   - Combine direction with action in state names (e.g., WALK_L, DIG_R)

2. Combinational Output Logic:
   - Move all outputs to continuous assignments for clarity
   - Explicitly define each output based on current state

3. Optimized State Transitions:
   - Use nested ternary operators for priority handling
   - Clearly implement fall > dig > bump priority chain
   - Separate falling logic from walking/digging logic

4. Improved Fall Counter:
   - Maintain counter as separate register
   - Clear when not falling, increment when falling
   - Splat condition only checked when ground reappears

Key Refactoring Benefits:
- More readable state machine structure
- Clearer priority implementation
- Explicit output definitions
- Maintains identical functionality while being more maintainable
