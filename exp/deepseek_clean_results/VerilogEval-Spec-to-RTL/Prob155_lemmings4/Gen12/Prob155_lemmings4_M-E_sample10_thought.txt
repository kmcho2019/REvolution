I'll implement a hierarchical FSM with these key features:
1. Main state machine tracks walking/falling/digging/splatter states
2. Separate direction register maintains walking direction independently
3. Fall timer is managed by a dedicated counter module
4. Output logic combines state and direction information
5. Priority logic is centralized in a combinational block

The innovation here is:
- Direction is maintained separately from states, only updated when walking
- Fall timer is encapsulated in its own logic block
- Clear separation between state transitions and direction changes
- Outputs are driven from a single source to avoid multiple drivers
