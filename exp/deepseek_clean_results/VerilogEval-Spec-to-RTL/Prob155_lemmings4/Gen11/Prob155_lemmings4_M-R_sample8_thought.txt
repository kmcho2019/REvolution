The refactored solution will:
1. Use a one-hot encoded state machine for better readability and potentially simpler logic
2. Separate the state transition logic into combinational always blocks
3. Move the fall timer to a separate always block for clarity
4. Use continuous assignments for outputs to make them more explicit
5. Maintain the same priority order (fall > dig > bump)

Key improvements:
- One-hot encoding makes state conditions clearer
- Separated timer logic is easier to verify
- Combinational next-state logic is more straightforward
- Output assignments are more explicit
