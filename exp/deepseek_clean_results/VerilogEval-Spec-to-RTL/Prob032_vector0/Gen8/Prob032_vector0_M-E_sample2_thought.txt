This implementation takes a behavioral approach with a focus on potential future extensibility:
1. Uses an intermediate register to store the input vector, making it easier to add synchronous behavior later
2. Implements the outputs through procedural assignments in an always block
3. While functionally equivalent, this approach better supports future modifications like:
   - Adding clocked behavior
   - Implementing output enables
   - Incorporating reset functionality
4. The design emphasizes modularity and maintainability over raw efficiency
5. The always block provides a clear separation between input capture and output generation
