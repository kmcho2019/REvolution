The original solution is efficient but can be refactored for better readability and maintainability while preserving the same functionality. Here's the refactoring approach:

1. **Structural Changes**:
   - Replace the conditional inversion with explicit add/sub paths
   - Use separate continuous assignments for clarity
   - Move zero detection to its own logical expression

2. **Benefits**:
   - More explicit data flow showing both add and sub paths
   - Clear separation of arithmetic and zero detection logic
   - Maintains single-cycle operation
   - Same PPA characteristics as original

3. **Key Differences**:
   - Uses explicit add and subtract operations
   - Muxes between results instead of conditional inversion
   - Zero flag logic remains identical
   - All assignments are continuous for combinational logic
