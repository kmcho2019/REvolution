Here's a novel approach using a hierarchical XOR tree with intermediate result checking. Instead of directly computing the parity, we'll:
1. First compute pairwise XORs (a^b and c^d)
2. Then XOR these intermediate results
3. The final XOR result indicates odd parity (1 when odd number of 1s)
4. Invert this to get even parity (q = 1 when even number of 1s)

This approach:
- Uses the mathematical property that XOR is associative and commutative
- Naturally forms a balanced tree structure for better timing
- Requires only 3 XOR gates and 1 inverter
- Provides better scalability for larger input widths
- Has more regular structure than the case-enumeration approach
