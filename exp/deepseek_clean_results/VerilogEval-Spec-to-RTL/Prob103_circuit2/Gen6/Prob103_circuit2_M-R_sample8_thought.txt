The original implementation uses a single XOR chain with inversion for even parity checking. While efficient, we can refactor this to:

1. Use intermediate signals to make the parity calculation more explicit and potentially more readable
2. Break down the parity calculation into pairwise XOR operations first, then combine results
3. Still maintain the same functionality (even parity check) but with a different structural approach
4. This approach might be more maintainable and could potentially help with debugging in more complex designs

The refactored version will:
- First compute XOR of input pairs (a,b) and (c,d)
- Then XOR those intermediate results
- Finally invert to get even parity
- Use only assign statements (no always blocks)
