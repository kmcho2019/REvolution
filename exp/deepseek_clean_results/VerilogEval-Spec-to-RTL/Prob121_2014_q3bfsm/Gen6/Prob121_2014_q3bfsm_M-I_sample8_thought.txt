To optimize the FSM for better PPA (Power, Performance, Area) metrics, I'll implement the following improvements:

1. State Encoding:
   - Switch to one-hot encoding (5 bits for 5 states) to improve timing by reducing combinational logic depth
   - One-hot typically has better timing at the cost of slightly more area

2. Output Logic:
   - Register the output to reduce glitches and dynamic power
   - This adds one cycle latency but improves power and timing

3. Power Optimization:
   - Use one-hot encoding to minimize state transition power (only 2 bits change per transition)
   - Keep output registered to prevent unnecessary combinational switching

4. Area Consideration:
   - Accept slightly larger area (5 flip-flops vs 3) for better timing
   - The case statement remains simple and synthesis-friendly

5. Performance:
   - One-hot encoding reduces next-state logic complexity
   - Registered output improves timing path

The trade-off is slightly more area for better timing and power characteristics, which is often desirable in modern designs.
