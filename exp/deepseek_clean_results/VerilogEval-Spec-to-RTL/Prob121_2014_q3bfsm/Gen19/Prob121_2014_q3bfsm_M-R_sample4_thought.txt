I'll refactor the FSM implementation to use a single always block for both state transitions and output logic, while maintaining the same functionality. This approach:

1. Combines the state register and output logic into one sequential block
2. Uses a case statement for state transitions based on current state and input
3. Still maintains synchronous reset to state 000
4. Keeps the same state encoding and output conditions
5. Eliminates the separate combinational next_state logic

This style is more compact and can be beneficial when:
- The FSM is relatively simple
- Outputs are registered (though in this case z remains combinational)
- You want to minimize the number of always blocks
- The timing between state and output doesn't need to be separated
