I'll refactor the FSM implementation using a more explicit two-process style (separate sequential and combinational blocks) which is often considered a cleaner FSM implementation pattern. The key changes are:

1. Separate the state register (sequential) from next-state logic (combinational)
2. Use parameters for state encoding to improve readability
3. Move all combinational logic (next-state and output) to separate always blocks
4. Keep synchronous reset behavior
5. Use named states instead of numeric values for better maintainability

This approach makes the state machine more explicit and easier to modify, though it uses slightly more code. The functionality remains identical to the original.
