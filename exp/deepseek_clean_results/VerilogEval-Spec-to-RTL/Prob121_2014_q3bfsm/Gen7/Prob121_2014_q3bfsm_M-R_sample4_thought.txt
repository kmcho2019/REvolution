I'll refactor the FSM implementation using a more data-driven approach with a lookup table (LUT) for the next state logic. This approach:

1. Uses a combinational always block for next state logic with a case statement
2. Maintains the same state encoding for consistency
3. Separates the state register into its own always block
4. Keeps the output logic as a simple combinational assign
5. Benefits:
   - Clear separation of combinational and sequential logic
   - Easier to modify state transitions (all in one case statement)
   - More scalable for larger FSMs
   - Maintains same functionality while being more modular
