To refactor this FSM implementation while maintaining the same functionality, I'll make these key changes:

1. State Representation:
   - Keep the same parameterized states for readability
   - Use one-hot encoding instead of binary for potentially better timing

2. State Transitions:
   - Split into combinational next-state logic and sequential state update
   - Use assign statements for next-state logic instead of case in always block

3. Output Logic:
   - Maintain the same simple OR-based output
   - Keep it combinational as before

4. Key Improvements:
   - Explicit separation of combinational and sequential logic
   - One-hot encoding may improve timing (though area may increase)
   - More modular structure with clearly defined next-state logic
   - Still maintains synchronous reset functionality

The refactored version moves the state transition logic to continuous assignments while keeping the state register update in an always block. This provides clearer separation of combinational and sequential elements.
