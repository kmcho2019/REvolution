I'll refactor the FSM implementation using a more combinational approach while maintaining the same functionality. The key changes will be:

1. Separate the next state logic into a combinational always block
2. Keep the state register update in a sequential always block
3. Use continuous assignments for both next state and output logic
4. Maintain the same state encoding for readability

This approach provides:
- Clear separation between combinational and sequential logic
- Easier timing analysis as next state logic is isolated
- Potential for better synthesis optimization
- Same state machine behavior as original
- Maintains synchronous reset functionality
