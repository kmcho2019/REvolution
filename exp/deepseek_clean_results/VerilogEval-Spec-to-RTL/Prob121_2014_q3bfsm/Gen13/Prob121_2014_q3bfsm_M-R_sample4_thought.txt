To refactor the FSM implementation while maintaining the same functionality:
1. Use a combinational always block for next state logic
2. Separate the state register into its own sequential always block
3. Keep output logic as continuous assignment
4. Use localparam for state definitions to improve readability
5. Maintain synchronous reset behavior

This approach:
- Separates combinational and sequential logic clearly
- Makes state transitions more explicit and readable
- Still maintains the same timing characteristics
- Potentially easier to modify or debug
