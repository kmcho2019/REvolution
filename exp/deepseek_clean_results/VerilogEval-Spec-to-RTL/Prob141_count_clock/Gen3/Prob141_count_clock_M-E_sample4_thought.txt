Instead of nested if-else structures, we'll use:
1. A state machine to track which counter needs incrementing
2. Separate BCD increment modules for each digit pair
3. Pre-computed next values for all counters
4. Parallel evaluation of all possible next states
5. Special handling for the 12-hour wrap and AM/PM toggle

This approach:
- Reduces combinatorial path depth by parallel evaluation
- Simplifies the hour counter logic by treating it as a special case
- Uses modular BCD increment blocks for code reuse
- Minimizes power by only computing necessary transitions
