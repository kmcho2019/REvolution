Here's a novel approach that leverages the observation that each mux_in bit corresponds to a column in the K-map, and each column can be treated as a separate 2-input function of c and d:

1. mux_in[0] (ab=00): Output is 1 when cd=01,11,10 → This is equivalent to ~(c & ~d)
2. mux_in[1] (ab=01): Always 0 → Direct assignment
3. mux_in[2] (ab=10): Output is 1 only when cd=00 → This is ~c & ~d
4. mux_in[3] (ab=11): Output is 1 when cd=00,10,11 → This is ~d | (c & d)

To implement these functions using only 2-to-1 muxes:
- For mux_in[0]: Use c as selector, choose between ~d (when c=0) and d (when c=1)
- For mux_in[2]: Use c as selector, choose between ~d (when c=0) and 0 (when c=1)
- For mux_in[3]: Use d as selector, choose between 1 (when d=0) and c (when d=1)
- mux_in[1] remains hardwired to 0

This implementation uses exactly three 2-to-1 muxes (one for each non-constant output) and maintains the correct K-map relationships.
