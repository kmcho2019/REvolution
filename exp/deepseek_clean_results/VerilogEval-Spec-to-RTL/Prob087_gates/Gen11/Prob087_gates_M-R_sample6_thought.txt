I'll refactor the solution to use continuous assignments (assign statements) instead of an always block. This approach is more straightforward for simple combinational logic like this, as it:
1. Eliminates the need for output registers (output reg)
2. Makes the code more concise and easier to read
3. Typically results in slightly better PPA (Power, Performance, Area) since it directly represents the combinational logic without any procedural overhead
4. Clearly shows the direct relationship between inputs and outputs
