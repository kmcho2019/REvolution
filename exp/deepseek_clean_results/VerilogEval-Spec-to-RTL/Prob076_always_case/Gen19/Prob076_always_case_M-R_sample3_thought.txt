To refactor the code while maintaining the same functionality, I'll switch from using an always block with case statement to using continuous assignments with conditional operators. This approach:

1. Eliminates the need for a procedural block (always)
2. Uses ternary conditional operators to create the same multiplexing logic
3. Maintains the same selection behavior (output 0 for sel values 6 and 7)
4. Results in combinational logic that should synthesize similarly
5. May offer slightly better readability for simple multiplexers

The refactored version will use nested conditional operators to select between the data inputs based on the sel value, with the same default-to-zero behavior for invalid selections.
