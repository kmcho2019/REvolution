I'll refactor the solution using a combinational always block for next state logic instead of a function, and move the state encoding to parameters. This approach:

1. Eliminates the function call overhead (though synthesis would optimize it)
2. Makes the state transitions more immediately visible in the code
3. Uses parameters instead of localparam for slightly better tool compatibility
4. Maintains the same Gray coding for power efficiency
5. Keeps the efficient output assignment (MSB check)
6. Uses explicit case items for all states (no default) for clarity

The key changes are:
- Replace function with direct combinational always
- Change localparam to parameter
- Keep all other optimizations (Gray code, output logic)
- Structure follows classic two-process FSM style (combinational next state + sequential state update)
