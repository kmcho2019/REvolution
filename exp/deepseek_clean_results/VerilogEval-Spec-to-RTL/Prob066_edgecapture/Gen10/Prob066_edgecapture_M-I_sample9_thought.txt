2. Permanent latching: The OR operation (out <= out | ...) ensures bits stay set once detected
3. Reset properly clears all state synchronously

However, we can make one optimization:
1. Remove the separate prev_in register by using non-blocking assignment
2. This saves 32 flip-flops while maintaining correct functionality
3. The optimization works because:
   - We can use the already registered 'in' value from previous cycle
   - The order of evaluation ensures correct edge detection
   - Maintains same behavior with fewer registers

This improves PPA by reducing area (fewer flip-flops) while keeping identical functionality.
