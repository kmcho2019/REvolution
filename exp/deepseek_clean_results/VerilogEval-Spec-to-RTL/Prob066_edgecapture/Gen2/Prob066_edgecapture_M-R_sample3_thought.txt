Here's a refactored approach that maintains the same core idea but simplifies the implementation:
1. Use a single register to store the previous input value (prev_in) instead of two pipeline stages
2. Detect transitions by comparing current input with previous input directly
3. Use a separate register (captured) to maintain the captured state
4. Update the captured state only when 1->0 transitions are detected
5. Use continuous assignments for cleaner combinational logic
6. Keep all sequential elements in a single always block for clarity
