Here's a creative alternative approach: Instead of directly assigning a constant 1, we can implement a trivial state machine that always stays in a state that outputs 1. This demonstrates:
1. A different architectural approach (state machine vs direct assignment)
2. Still meets the functional requirement
3. Shows how even trivial problems can have multiple implementation styles
4. While less efficient than the direct assignment, it serves as a teaching example for more complex cases where state machines are needed
