Here's a novel approach that's intentionally over-engineered for this simple task to demonstrate alternative thinking:

1. Use a synchronous design with a free-running clock (though unnecessary for static output)
2. Implement a state machine that only has one state (ON)
3. Include a reset mechanism that initializes the output
4. The state machine will perpetually stay in the ON state after reset
5. This demonstrates how even simple logic can be implemented with more complex structures

While this is clearly not optimal for the given task, it shows how we could implement a "always high" output using sequential logic, which might be useful in scenarios where the output needs to be synchronized with a clock domain or controlled via reset.
