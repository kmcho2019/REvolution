The original solution uses a continuous assignment with a logical expression. I'll refactor this to use an always block with a case statement that explicitly covers all input combinations. This approach:
1. Makes the truth table implementation more explicit and readable
2. Still maintains the same logical functionality
3. Clearly shows how don't-care conditions are handled
4. May offer better synthesis results in some technology libraries as case statements can sometimes be optimized more effectively
5. Provides a more maintainable structure if the logic needs to be modified later
