To refactor this D flip-flop implementation while maintaining the same functionality, I'll use a different approach that:
1. Separates the combinational and sequential logic explicitly
2. Uses an intermediate wire for the next state logic
3. Implements the flip-flop behavior through a separate always block

This approach makes the design more modular and could potentially help with synthesis optimizations in some tools. The key differences are:
- Explicit next state logic calculation
- Clear separation of asynchronous reset handling
- Same timing characteristics (positive edge-triggered with async reset)
- Functionally equivalent behavior
