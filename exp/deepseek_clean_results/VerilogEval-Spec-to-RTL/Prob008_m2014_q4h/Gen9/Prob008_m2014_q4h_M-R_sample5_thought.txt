The original implementation uses a direct continuous assignment, which is perfectly suitable for this simple combinational logic. For refactoring, I'll demonstrate an alternative implementation that:

1. Uses an always block with sensitivity to all inputs (though overkill for this simple case)
2. Explicitly declares reg type for the output (though functionally equivalent)
3. Shows how this would look if we were to extend this to more complex combinational logic in the future

This maintains identical functionality while showing a different coding style that might be more familiar to some designers or more extensible for future modifications.
