The original solution is already optimal for basic functionality, but we can consider two potential improvements for better PPA in a larger system context:

1. **Power Optimization:** Add an enable signal to gate the output when not needed, reducing unnecessary switching activity. This is particularly valuable if this module is instantiated multiple times in a design.

2. **Timing Robustness:** While not necessary for this simple case, we could add a buffer to ensure clean signal propagation if this module is part of a long signal chain. However, this would trade off area for timing.

Since the original metrics show excellent PPA already, we'll implement the power optimization approach while maintaining the simplicity of the design. The enable signal will be optional (default enabled) to maintain backward compatibility.
