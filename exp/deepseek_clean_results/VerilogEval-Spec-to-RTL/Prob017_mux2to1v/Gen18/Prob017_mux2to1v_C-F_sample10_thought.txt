The optimal solution combines the strengths of both examples while addressing their minor limitations:

1. From Example 1: The case statement approach provides explicit selection logic which is more readable and maintainable, especially if the mux needs to be extended to more inputs later.

2. From Example 2: The ternary operator approach is more concise and directly maps to hardware muxes, but lacks the explicit default case handling.

Fusion Strategy:
- Use the always block approach for better readability and maintainability
- Keep the output as a wire (not reg) by using continuous assignment
- Include default case for robustness
- Use simple bitwise operations that directly map to hardware

The resulting implementation:
1. Maintains excellent timing characteristics (identical to both examples)
2. Provides clear, maintainable code structure
3. Includes proper default handling
4. Uses minimal and efficient hardware mapping
