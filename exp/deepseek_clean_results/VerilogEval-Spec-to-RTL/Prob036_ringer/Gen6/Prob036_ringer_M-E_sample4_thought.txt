Instead of using simple combinational logic, we can implement this as a state machine with two states: IDLE and ACTIVE. In the IDLE state, both outputs are off. When 'ring' is detected, we transition to ACTIVE state where we check 'vibrate_mode' to determine which output to activate. This approach provides more flexibility for future enhancements (like adding timing control or different ring patterns) while maintaining the same functionality. The state machine ensures glitch-free transitions between states.
