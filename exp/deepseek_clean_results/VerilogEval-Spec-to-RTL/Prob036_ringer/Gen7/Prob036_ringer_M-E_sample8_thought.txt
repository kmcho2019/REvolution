Instead of pure combinational logic, implement a simple state machine that:
1. Has two states: IDLE and ALERT
2. Transitions to ALERT when ring is detected
3. In ALERT state, activates either ringer or motor based on vibrate_mode
4. Returns to IDLE when ring goes low

This approach provides:
- Clear separation of control logic
- Easier debugging with observable states
- Better extensibility for future features (like alert patterns)
- Potential for power gating in IDLE state
- More explicit timing control if needed
