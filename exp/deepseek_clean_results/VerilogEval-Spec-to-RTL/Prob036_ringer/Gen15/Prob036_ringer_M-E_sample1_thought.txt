Here's a novel approach using a priority encoder style implementation with a different architectural perspective:

1. **State Encoding**: Treat the input combination as a 2-bit state (ring + vibrate_mode)
2. **Lookup Table**: Use a case statement to map input states to output patterns
3. **Output Encoding**: Represent outputs as a 2-bit vector for compactness
4. **Explicit Default**: Handle all possible input combinations explicitly

This approach is interesting because:
- It clearly enumerates all possible input states
- The case statement makes the state-to-output mapping very explicit
- It could easily be extended to handle more complex modes or states
- The output vector representation could be useful for further processing
