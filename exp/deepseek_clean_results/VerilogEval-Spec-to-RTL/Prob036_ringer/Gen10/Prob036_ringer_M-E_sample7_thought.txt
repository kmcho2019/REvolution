A novel approach would be to implement the control logic using a small state machine that explicitly represents the four possible states of the system (idle, ring-only, vibrate-only, and error state). While this might seem overkill for such a simple function, it offers several advantages:
1. Explicit state representation makes the design more maintainable and extensible
2. Easier to add new features (like different vibration patterns)
3. Clear separation of control logic
4. Better error handling capabilities (though not required here)
5. More scalable for future modifications

The state machine will have:
- IDLE state when ring=0
- RINGER state when ring=1 and vibrate_mode=0
- VIBRATE state when ring=1 and vibrate_mode=1
- ERROR state (unreachable in normal operation)

The outputs are purely combinatorial functions of the current state.
