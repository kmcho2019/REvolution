Let's implement a state machine approach that adds some additional features while maintaining the core functionality. The new design will:
1. Use a simple FSM to handle the control logic
2. Add a small delay (2 cycles) when switching between modes to prevent mechanical wear
3. Include a "silent mode" override where both outputs stay off regardless of ring input
4. Maintain the original functionality when not in silent mode

The FSM will have 3 states:
- IDLE: Default state when no ring signal
- RING: Active when ring=1 and not in vibrate mode
- VIBRATE: Active when ring=1 and in vibrate mode

This approach provides better debouncing and mode switching protection compared to pure combinational logic.
