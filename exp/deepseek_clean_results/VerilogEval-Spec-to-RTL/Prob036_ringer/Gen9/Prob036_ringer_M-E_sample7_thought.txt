This solution implements a tiny state machine that explicitly encodes the priority rules:
1. When ring=0, both outputs are 0 (IDLE state)
2. When ring=1, we enter either RING or VIBRATE state based on vibrate_mode
3. The state transitions are immediate (combinational) but the explicit state encoding makes the design intent clearer
4. This approach could be easily extended to add more complex behaviors (like ring patterns) by expanding the state machine

Benefits:
- More explicit representation of the control flow
- Easier to modify/expand with additional states
- Clear separation of conditions and actions
- Could be made sequential with minimal changes if timing requirements change
