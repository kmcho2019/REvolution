I'll implement a solution using a hierarchical decision-making approach that:
1. First checks if there's an incoming call (ring signal)
2. Then makes a secondary decision based on vibrate_mode
3. Uses explicit enable signals for each output
4. Implements the outputs as gated signals where the ring signal acts as the global enable
5. This structure clearly separates the decision logic from output gating
6. The design is easily extensible for additional modes or features
