Here's a novel approach using a multiplexer-based design with explicit priority encoding:

1. Instead of separate logic for each output, we'll use a 2:1 multiplexer to select between the two output modes
2. The multiplexer will choose between two configurations:
   - Configuration 0 (normal mode): ringer=ring, motor=0
   - Configuration 1 (vibrate mode): ringer=0, motor=ring
3. The vibrate_mode signal acts as the mux select line
4. This approach makes the mode switching more explicit and could be easier to extend if more modes are added later
5. The implementation uses a case statement for clear mode selection
