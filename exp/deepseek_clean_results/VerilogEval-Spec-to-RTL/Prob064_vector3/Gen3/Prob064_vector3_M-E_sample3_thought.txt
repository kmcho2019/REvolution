Here's a novel approach that avoids using a large intermediate concatenation wire:

1. Instead of concatenating all inputs into a 32-bit wire, we'll compute each output byte directly from the relevant input bits
2. For each output byte, we'll:
   - Select the appropriate 8 bits from the inputs
   - Pad with 1's only for the LSBs when needed
3. This approach:
   - Eliminates the need for a 32-bit intermediate wire
   - Potentially reduces routing congestion
   - Makes each output calculation independent and parallel
   - May improve timing for individual outputs
4. The mapping is:
   - w: bits 29-22 of inputs (a[4:2], b, c[4:6])
   - x: bits 21-14 of inputs (c[1:0], d, e[4:3])
   - y: bits 13-6 of inputs (e[2:0], f)
   - z: bits 5-0 of inputs (f[4:0]) + 2'b11 padding
