Instead of directly implementing the next-state logic with simple combinational assignments, I'll take a more structured approach by:
1. First decoding the current state from the one-hot encoded input
2. Then implementing the state transition logic using a case statement for clarity
3. Finally encoding the next state outputs Y1 and Y3 based on the transitions

This approach makes the state machine behavior more explicit and easier to verify against the given transition table. The key advantages are:
- Clear mapping between states and transitions
- Explicit handling of all state transitions
- Easier to modify if the state machine changes
- Still maintains the one-hot encoding requirement
