The original implementation had a width mismatch and potential logical operation issues. Let's try a completely different approach using a case statement inside an always block, which is more explicit and easier to verify. This approach:

1. Uses procedural assignment for clearer selection logic
2. Explicitly handles all cases (though only 2 here)
3. Makes the selection mechanism more readable
4. Avoids potential bitwise operation pitfalls
5. Still maintains combinational behavior through always @(*)

This method is more robust because:
- The case statement clearly shows the selection paths
- No need to worry about bitwise operation precedence
- Easier to modify if selection logic becomes more complex
- More maintainable code structure
