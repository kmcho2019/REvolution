To implement the TopModule, we first need to define the internal components, 
including the global branch history register, the pattern history table (PHT), 
and the logic for updating these components. 

The global branch history register is a 7-bit register that stores the history 
of branch predictions. 

The PHT is a 128-entry table of two-bit saturating counters, where each entry 
is accessed by a 7-bit index calculated by hashing the 7-bit pc and 7-bit 
global history using xor.

When a branch prediction is requested, the module produces the predicted 
branch direction and state of the branch history register used to make the 
prediction, and then updates the branch history register for the predicted 
branch at the next positive clock edge.

When training for a branch is requested, the module updates the PHT to train 
the branch predictor to predict this branch more accurately next time, and 
also recovers the branch history register to the state immediately after the 
mispredicting branch completes execution if the branch was a misprediction.

The module must handle the case where training and prediction of the same PHT 
entry happen at the same time, in which case the prediction sees the PHT state 
before training.

The module also needs to handle the asynchronous active-high reset.
