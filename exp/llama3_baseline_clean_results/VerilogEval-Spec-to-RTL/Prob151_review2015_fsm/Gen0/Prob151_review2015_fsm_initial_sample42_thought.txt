To implement the finite-state machine that controls the timer, we need to design a state machine with the following states:
- IDLE: initial state, searching for the pattern 1101
- PATTERN_DETECTED: pattern 1101 detected, waiting for the next clock cycle
- SHIFTING: shifting in 4 bits to determine the duration
- COUNTING: waiting for the counters to finish counting
- DONE: notifying the user and waiting for acknowledgement
We use a counter to count the number of bits shifted during the SHIFTING state.

We use a FSM (Finite State Machine) to implement the state machine. The FSM has 5 states: IDLE, PATTERN_DETECTED, SHIFTING, COUNTING, and DONE.

The state machine transitions from one state to another based on the current state and the inputs. The outputs are also determined by the current state.

The state machine starts in the IDLE state. It stays in this state until the pattern 1101 is detected. When the pattern 1101 is detected, it transitions to the PATTERN_DETECTED state.

In the PATTERN_DETECTED state, it asserts shift_ena and starts shifting in the bits to determine the duration. After shifting 4 bits, it transitions to the COUNTING state.

In the COUNTING state, it asserts counting and waits for the counters to finish counting. When the counters finish counting, it transitions to the DONE state.

In the DONE state, it asserts done and waits for the user to acknowledge. When the user acknowledges, it transitions back to the IDLE state.

The state machine also has a synchronous reset. When the reset is asserted, the state machine is reset to the IDLE state.
