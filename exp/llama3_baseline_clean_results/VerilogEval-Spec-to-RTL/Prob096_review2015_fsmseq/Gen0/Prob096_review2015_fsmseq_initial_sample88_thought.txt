To implement the finite-state machine that searches for the sequence 1101 in an input bit stream, we can define four states: Idle, Seen1, Seen11, and Seen110. The Idle state is the initial state. When in the Idle state, if the input data is 1, we transition to the Seen1 state. From the Seen1 state, if the input data is 1, we stay in the Seen1 state. If the input data is 0, we transition to the Seen10 state, but since our target sequence does not start with 10, we actually need a Seen10 state to handle this scenario, which then transitions to Seen101 if the next input is 1. However, the requirement does not explicitly mention handling '110' as part of '1101', so we'll directly aim for '1101'. Thus, correcting our approach: From Idle, we move to Seen1 if data is 1. Then, to Seen11 if we see another 1, to Seen110 if we then see a 0, and to Seen1101 if we see a 1. When we reach the Seen1101 state, we set start_shifting to 1. Reset must return the FSM to the Idle state and set start_shifting to 0.
