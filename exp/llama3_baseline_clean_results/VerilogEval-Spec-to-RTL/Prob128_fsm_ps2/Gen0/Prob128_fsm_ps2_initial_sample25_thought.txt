To solve this problem, we will implement a finite state machine (FSM) in the TopModule. The FSM will have four states: 
- Idle: This is the initial state where the module waits for a byte with in[3] = 1 to start a new message.
- Byte1: After receiving a byte with in[3] = 1, the module moves to this state, assuming the received byte is the first byte of a message.
- Byte2: After receiving the first byte, the module moves to this state, waiting for the second byte of the message.
- Byte3: After receiving the second byte, the module moves to this state, waiting for the third byte of the message. 
Once the third byte is received, the module signals 'done' in the next cycle and then returns to the Idle state, waiting for the next message.

The reset input will be used to asynchronously reset the FSM to the Idle state.
