The design will involve a finite state machine (FSM) with several states: 
1) an idle state where it continuously checks the input byte stream for 
a byte with in[3]=1, 
2) a state where it receives the first byte of the message (byte 1), 
3) a state where it receives the second byte of the message (byte 2), 
4) a state where it receives the third byte of the message (byte 3), and 
5) a state where it asserts the done signal for one clock cycle after 
receiving the third byte.

The FSM will be implemented using a parameterized enum to define the 
states. The FSM will use a combination of conditional statements and case 
statements to handle the transitions between states.

The FSM will also need a mechanism to track the number of bytes received, 
which can be implemented using a counter or a finite state machine with 
a limited number of states.

To ensure that the FSM behaves correctly in the presence of the reset 
signal, we will need to reset the FSM to the idle state whenever the 
reset signal is asserted.
