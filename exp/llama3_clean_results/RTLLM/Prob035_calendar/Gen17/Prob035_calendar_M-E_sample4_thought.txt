To create a novel solution, let's rethink the perpetual calendar's architecture. Instead of using separate always blocks for each time unit or nested if-else statements, we can utilize a state machine approach. This approach involves defining states for each time unit (seconds, minutes, hours) and using a finite state machine (FSM) to transition between these states based on the current state and the clock signal.

The state machine will have three main states: reset, increment_seconds, and wrap_around. The reset state is entered when the reset signal is active, setting all time units to zero. The increment_seconds state is the default state where the seconds value is incremented every clock cycle. The wrap_around state handles the cases where seconds, minutes, or hours need to be reset to zero and the next higher time unit incremented.

This approach simplifies the logic and potentially reduces the area and power consumption by minimizing the number of transitions and using a more systematic method to handle the time unit increments and wrap-arounds.
