To tackle the Lemmings state machine problem from a fresh perspective, let's introduce a novel architectural idea: a hierarchical, behavior-oriented design. This approach involves breaking down the Lemmings' behavior into smaller, manageable modules, each responsible for a specific aspect of its behavior, such as walking, falling, and digging. We will use a top-down design methodology, starting with the overall state machine and then decomposing it into smaller, interacting modules.

The key components of this design will include:

1. **State Controller**: A central module responsible for managing the overall state of the Lemming (walking, falling, digging). It will receive inputs from various sensors (bump_left, bump_right, ground, dig) and determine the next state based on the current state and these inputs.
2. **Walking Controller**: A module dedicated to handling the walking behavior, including direction changes based on bumps and the decision to start digging.
3. **Falling Controller**: A module that manages the falling state, ensuring the Lemming transitions back to walking when ground is detected.
4. **Digging Controller**: A module responsible for the digging behavior, transitioning from walking to digging and back to falling when ground is lost.

By decomposing the problem into these smaller, focused modules, we can create a more modular, maintainable, and scalable design. Each module can be designed and tested independently, simplifying the development process and reducing the complexity of the overall system.

This hierarchical approach also allows for easier extension or modification of the Lemming's behavior, as new behaviors can be added by introducing new modules without significantly altering the existing architecture.
