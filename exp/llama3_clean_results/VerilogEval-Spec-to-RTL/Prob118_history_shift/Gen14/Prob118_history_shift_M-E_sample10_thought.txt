The FSM can have three main states: idle, predict, and train. In the idle state, the history register remains unchanged. If a misprediction occurs (train_mispredicted = 1), the FSM transitions to the train state, where it loads the history register with the provided train history concatenated with the actual branch result.

By using an FSM, we can explicitly manage the flow of the history update process, making the design more modular and easier to understand. Additionally, this approach allows for easier extension or modification of the logic if new requirements arise.
