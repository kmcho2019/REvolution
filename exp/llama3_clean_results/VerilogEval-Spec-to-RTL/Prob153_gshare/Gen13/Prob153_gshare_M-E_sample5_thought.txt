A novel architectural idea for the gshare branch predictor is to use a self-reconfiguring table that adapts to the branch behavior of the program. The predictor uses a single table with 128 entries, each containing a 2-bit saturating counter and a 1-bit flag indicating whether the counter is stable or not. The table is indexed using a 7-bit index calculated by XORing the 7-bit PC with the 7-bit global branch history.

The predictor works as follows:

- When a branch prediction is requested, the predictor checks the stability flag of the corresponding table entry. If the flag is set, the predictor uses the value of the saturating counter to make the prediction. If the flag is not set, the predictor uses a default prediction (e.g., taken or not taken).

- When training is requested, the predictor updates the table entry corresponding to the branch being trained. If the branch was taken, the saturating counter is incremented. If the branch was not taken, the saturating counter is decremented.

- The stability flag is updated based on the number of consecutive times the saturating counter has been incremented or decremented without changing direction. If the counter has been incremented or decremented consecutively for a certain number of times (e.g., 4), the stability flag is set. If the counter changes direction, the stability flag is reset.

- The global branch history register is updated based on the prediction. If the prediction is correct, the global branch history register is updated with the actual outcome of the branch. If the prediction is incorrect, the global branch history register is recovered to the state after the mispredicting branch completes execution.

This architectural idea allows the predictor to adapt to the branch behavior of the program and make more accurate predictions over time.
