We will model the Lemming with a Moore FSM with these states:
- WALK_LEFT
- WALK_RIGHT
- FALL_LEFT
- FALL_RIGHT
- DIG_LEFT
- DIG_RIGHT
- SPLAT

The Lemming starts in WALK_LEFT on reset.

Outputs are determined by state:
- WALK_LEFT: walk_left=1
- WALK_RIGHT: walk_right=1
- FALL_LEFT or FALL_RIGHT: aaah=1
- DIG_LEFT: walk_left=1 and digging=1
- DIG_RIGHT: walk_right=1 and digging=1
- SPLAT: all outputs 0

Direction (left or right) is encoded in the state name for clarity.

Transitions are priority-based:
1. If ground=0 and not already falling or splatted, go to fall state corresponding to current direction.
2. If currently falling, increment fall counter. If ground becomes 1:
   - If fall time >20 cycles, go to SPLAT.
   - Else return to walk state in original direction.
3. If walking on ground and dig=1, enter dig state in current direction.
4. If digging and ground=0, transition to fall state.
5. If walking and bumped (left or right), switch walk directions.
6. Bumps during falling or digging do not affect direction.
7. Once splatted, stay splatted forever.

The fall counter resets on ground or reset, increments every clk cycle while falling.

The FSM is updated on rising clock edge, asynchronously reset with areset.

Outputs set combinationally from current state.
