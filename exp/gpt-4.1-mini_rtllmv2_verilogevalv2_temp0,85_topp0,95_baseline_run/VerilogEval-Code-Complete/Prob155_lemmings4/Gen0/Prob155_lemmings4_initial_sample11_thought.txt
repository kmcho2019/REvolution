Model the Lemming as a Moore FSM with distinct states representing its current activity and direction. The states will include walking left, walking right, falling left, falling right, digging left, digging right, and splattered. 

Key points:
- Walking states: respond to bumps to switch direction, can start digging if dig=1 and ground=1 and not falling.
- Falling states: triggered when ground=0 while walking or digging; bumps and dig input ignored; count falling cycles; if fall duration > 20 and ground returns, go to splattered.
- Digging states: can only start digging if walking on ground; continue digging until ground=0, then fall.
- Splattered state: outputs all zeros, no transitions except reset.
- On reset, go to walk_left.

We'll use an enum for states and a fall counter register for counting falling duration. Moore outputs depend only on the current state.

State encoding (example):
0: WALK_LEFT
1: WALK_RIGHT
2: FALL_LEFT
3: FALL_RIGHT
4: DIG_LEFT
5: DIG_RIGHT
6: SPLATTERED

Transitions prioritized as:
If splattered: stay splattered
Else if falling (ground=0): continue falling and count
Else if falling and ground=1: if fall > 20 splatter else resume walking same direction
Else if digging and ground=0: switch to falling same direction
Else if walking and ground=0: switch to falling same direction
Else if walking and dig=1: start digging same direction
Else if walking and bumped: switch direction
Else remain in current walking/digging state

Outputs:
walk_left: in WALK_LEFT or DIG_LEFT
walk_right: in WALK_RIGHT or DIG_RIGHT
aaah: in FALL_LEFT or FALL_RIGHT
digging: in DIG_LEFT or DIG_RIGHT
All outputs 0 in SPLATTERED

Implement synchronous state and counter updates on posedge clk or areset async posedge.
