We design a Moore FSM with four states representing the Lemming's behavior: WALK_LEFT, WALK_RIGHT, FALLING, and DIGGING. On reset, the Lemming starts in WALK_LEFT.

- WALK_LEFT and WALK_RIGHT represent walking states with the direction encoded.
- FALLING represents the Lemming falling ("aaah!").
- DIGGING represents the Lemming digging.

Transitions:

1. From WALK_LEFT or WALK_RIGHT:
   - If ground == 0 -> FALLING (falling overrides other actions).
   - Else if dig == 1 -> DIGGING (only if on ground and not falling).
   - Else if bumped (bump_left or bump_right) -> switch walking direction.
   - Else stay in current walking state.

2. From DIGGING:
   - If ground == 0 -> FALLING.
   - Else remain in DIGGING.

3. From FALLING:
   - If ground == 1 -> return to the previous walking direction (stored as walking direction state).
   - Else remain in FALLING.

Other rules:

- Bumping has no effect in DIGGING or FALLING.
- Direction remembers walking direction before fall or dig.
- Outputs are encoded based on the state.

Implementation details:

- Use a reg to store current state and next state.
- Use a reg to store walking direction for returning from FALLING.
- Outputs are derived solely from the current state.
- Asynchronous positive-edge reset sets the state to WALK_LEFT.

States encoding:

- WALK_LEFT = 2'b00
- WALK_RIGHT = 2'b01
- FALLING = 2'b10
- DIGGING = 2'b11
