We need to implement a 4-digit BCD counter with digits stored in q[3:0] (ones), q[7:4] (tens), q[11:8] (hundreds), and q[15:12] (thousands). On each clock cycle, the ones digit increments. When it reaches 9 and rolls over to 0, the tens digit should increment, and so on for hundreds and thousands digits.

The ena signals for digits [3:1] correspond to enabling increment for tens, hundreds, and thousands digits, respectively. These should be asserted when the lower digit rolls over from 9 to 0, indicating the next digit should increment.

The reset is synchronous and active-high, which means on reset, all digits reset to zero.

The approach is to check the carry (rollover) of each digit and use that to generate the enable signals and to increment the next digit on the next clock edge.

Implementation detail:
- On each clock:
  - If reset, q <= 0.
  - Else:
    - Increment ones digit.
    - If ones rolls over 9->0, enable tens increment (ena[1]).
    - If tens rolls over, enable hundreds (ena[2]).
    - If hundreds rolls over, enable thousands (ena[3]).
- The ena output signals should be combinational, reflecting whether the next digit increments on this cycle.

We'll implement this with a synchronous process, updating the digits, and combinational logic for ena signals.

Note: ena is 3 bits: ena[1] = tens enable, ena[2] = hundreds enable, ena[3] = thousands enable.
