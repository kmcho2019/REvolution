This implies the counter resets after the light turns off, which is counterintuitive and may cause the counter to be out of sync with the actual state duration.

3. **Inadequate Pedestrian Button Handling**:  
   The shortening of green time upon `pass_request` depends on checking `p_green` (next green signal) and `cnt`. Moreover, the counter decrements inside the if-statement for the pedestrian request only if `cnt <= 10`, but this decrement is performed asynchronously within a conditional branch, which may cause inconsistent count behavior.
