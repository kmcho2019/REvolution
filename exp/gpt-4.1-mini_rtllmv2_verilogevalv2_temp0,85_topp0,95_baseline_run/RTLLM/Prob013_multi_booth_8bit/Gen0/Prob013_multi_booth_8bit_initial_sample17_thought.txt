The design implements an 8-bit multiplier using a Radix-4 Booth algorithm style approach but follows the instructions which seem more like a bit-by-bit multiplication with a 16-bit counter (though Radix-4 usually processes two bits per cycle). According to the problem statement:

- On reset, extend inputs a and b to 16-bit signed values (with sign extension) and store them in multiplier and multiplicand registers, respectively.
- On each clock cycle, if counter < 16:
  - Shift multiplicand left by 1 (multiplicand <<= 1).
  - If multiplier[ctr] == 1, add multiplicand to product.
  - Increment counter.
- When counter reaches 16, set rdy.

However, this description has some inconsistencies with Radix-4 Booth (which typically handles 2 bits per cycle), and also the roles of multiplicand and multiplier seem swapped compared to typical multiplication (usually multiplicand remains constant, multiplier bits scanned). But we will implement as per the problem statement.

Implementation detail:
- Use synchronous logic with positive edge clk or reset.
- Registers: multiplicand (16-bit), multiplier (16-bit), product (16-bit), counter (5-bit), rdy (1-bit).
- On reset: multiplicand <= sign-extended b, multiplier <= sign-extended a, product <= 0, counter <= 0, rdy <= 0.
- On operation: if counter < 16:
  - multiplicand <<= 1 (shift left by 1)
  - if multiplier[ctr] == 1, product += multiplicand
  - counter++
- if counter == 16: rdy <= 1.

The product output is the register 'product'.

This matches the user request exactly.
