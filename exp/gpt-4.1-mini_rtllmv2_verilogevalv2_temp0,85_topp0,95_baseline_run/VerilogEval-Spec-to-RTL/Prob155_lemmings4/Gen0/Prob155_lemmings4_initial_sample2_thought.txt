We will implement a Moore FSM with states encoding the Lemming's current mode and walking direction:
- WALK_LEFT
- WALK_RIGHT
- FALL_LEFT
- FALL_RIGHT
- DIG_LEFT
- DIG_RIGHT
- SPLAT (dead state)

The outputs walk_left, walk_right, aaah, digging depend only on the state.

Transition rules:
1. If areset, go to WALK_LEFT.
2. If in SPLAT, stay in SPLAT.
3. Otherwise:
   - If currently FALLING and ground=1:
       - If fall_counter > 20, go to SPLAT
       - else return to WALK in the previous direction
   - Else if ground=0 and not digging and not falling, start falling (FALL_LEFT or FALL_RIGHT based on current walking dir)
   - Else if digging and ground=0, transition to falling (falling direction is digging direction)
   - Else if digging and ground=1, continue digging
   - Else if ground=1 and not falling and not digging:
       - If dig=1 start digging in current walking direction
       - Else if bumped, switch walking direction accordingly
       - Else stay walking in same direction

Fall counter increments when in FALL states; resets in other states or on reset.

Outputs:
- walk_left=1 only in WALK_LEFT state
- walk_right=1 only in WALK_RIGHT state
- aaah=1 only in FALL states
- digging=1 only in DIG states

The FSM is Moore: outputs depend only on state.

We will implement the state encoding with enums, synchronous state and fall_counter updates, asynchronous posedge reset, and combinational next-state logic.
