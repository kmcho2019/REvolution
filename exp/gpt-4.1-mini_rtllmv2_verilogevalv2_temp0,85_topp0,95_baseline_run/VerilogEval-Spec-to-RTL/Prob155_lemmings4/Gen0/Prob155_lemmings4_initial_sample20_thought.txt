Design a Moore FSM with the following states:

- WALK_LEFT: walking left on ground
- WALK_RIGHT: walking right on ground
- FALL_LEFT: falling, original direction left
- FALL_RIGHT: falling, original direction right
- DIG_LEFT: digging, original direction left
- DIG_RIGHT: digging, original direction right
- SPLATTER: dead state, all outputs 0

State transitions on posedge clk or async posedge areset:

- On areset: state = WALK_LEFT, fall counter = 0.

- While walking (WALK_LEFT, WALK_RIGHT):
  - If ground=0 => fall in that direction (FALL_LEFT or FALL_RIGHT), reset fall counter.
  - Else if dig=1 => start digging (DIG_LEFT or DIG_RIGHT).
  - Else if bump_left or bump_right => switch direction accordingly.

- While digging (DIG_LEFT, DIG_RIGHT):
  - If ground=0 => start falling in original direction (FALL_LEFT or FALL_RIGHT), reset fall counter.
  - Else continue digging.
  - Ignore bumps and dig command during digging.

- While falling (FALL_LEFT, FALL_RIGHT):
  - Increment fall counter.
  - If ground=1 => check fall counter:
    - If fall counter > 20 => splatter.
    - Else resume walking in original direction.
  - Else continue falling.
  - Ignore bumps and dig commands while falling.

- SPLATTER is terminal until reset.

Outputs:
- walk_left = 1 for WALK_LEFT
- walk_right = 1 for WALK_RIGHT
- aaah = 1 for FALL_LEFT or FALL_RIGHT
- digging = 1 for DIG_LEFT or DIG_RIGHT
- all 0 for SPLATTER

Because it's a Moore FSM, outputs depend on state only.

Implement async posedge areset, synchronous posedge clk for state and fall counter.

Use parameter encoding for states.

Handle bumps carefully: if bumped on left, walk right, if bumped on right, walk left, if bumped on both, still switch directions.

When multiple conditions apply during walking, prioritize fall > dig > bump.

Ignore bumps and dig while falling or digging.

Fall counter only increments while falling, reset on other states or reset.
