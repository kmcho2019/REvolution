We implement a Moore FSM with these states: WALK_LEFT, WALK_RIGHT, FALL_LEFT, FALL_RIGHT, DIG_LEFT, DIG_RIGHT, SPLAT. The FSM stores direction in the state names. On reset, state is WALK_LEFT.

- Transitions:
  - If areset: go to WALK_LEFT.
  - If in SPLAT: remain in SPLAT.
  - Else, if ground=0:
    - If currently walking or digging, go to FALL (preserving direction).
    - If already falling, increment fall counter.
  - If ground=1:
    - If falling and fall_counter > 20, splatter.
    - Else if falling, return to previous walking direction.
    - If digging and ground=1, continue digging.
    - If walking and dig=1, start digging.
    - If walking and bumped, switch directions.
  - While falling or digging, bump signals are ignored.
  
We keep a fall counter to count how long the Lemming falls. If it exceeds 20 and then ground=1, transition to SPLAT.

Outputs are driven by the current state:
- walk_left: 1 in WALK_LEFT only
- walk_right: 1 in WALK_RIGHT only
- aaah: 1 in FALL_LEFT or FALL_RIGHT
- digging: 1 in DIG_LEFT or DIG_RIGHT
- all zero in SPLAT

The design uses a synchronous process for state transitions and counters, and asynchronous posedge areset to reset. Moore output logic depends only on current state.
