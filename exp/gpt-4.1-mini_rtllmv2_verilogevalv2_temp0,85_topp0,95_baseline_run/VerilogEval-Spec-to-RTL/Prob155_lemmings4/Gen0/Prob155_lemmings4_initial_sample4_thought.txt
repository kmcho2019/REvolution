We will implement a Moore FSM with three main states: WALK_LEFT, WALK_RIGHT, FALLING, and DIGGING, plus an additional SPLATTERED terminal state. The outputs depend solely on the current state. The walking states indicate direction; falling and digging have their own outputs.

State transitions:
- From WALK_LEFT or WALK_RIGHT:
  - If ground=0, transition to FALLING, start fall counter at 1
  - Else if dig=1, transition to DIGGING, keep walking direction remembered
  - Else if bump_left or bump_right, change walking direction accordingly
- From FALLING:
  - If ground=0, stay in FALLING, increment fall counter
  - Else if ground=1, check fall duration:
    - If fall counter > 20, transition to SPLATTERED
    - Else return to previous walking direction
- From DIGGING:
  - If ground=0, transition to FALLING, start fall counter at 1
  - Else if dig=0 or ground=1, continue digging
- From SPLATTERED:
  - Remain in SPLATTERED forever until reset

On reset, we set to WALK_LEFT, zero fall counter, not splattered.

The fall counter counts cycles spent falling, reset on other states.

Outputs:
- walk_left = 1 in WALK_LEFT state only
- walk_right = 1 in WALK_RIGHT state only
- aaah = 1 in FALLING state only
- digging = 1 in DIGGING state only

Bumping does not affect FALLING or DIGGING states.

The walking direction is remembered during FALLING and DIGGING to resume later.

Implement asynchronous active-high reset.

Follow the precedence: fall > dig > bump.

Implement as a Moore FSM with registered state and next_state logic.
