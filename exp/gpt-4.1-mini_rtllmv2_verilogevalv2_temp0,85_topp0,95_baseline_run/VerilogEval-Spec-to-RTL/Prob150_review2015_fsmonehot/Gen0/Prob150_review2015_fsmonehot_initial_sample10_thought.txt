The module implements the next-state and output logic for a Moore FSM with 10 one-hot encoded states, based on inputs d, done_counting, and ack. Each next-state signal corresponds to the next state's one-hot bit being set.

From the state diagram and given one-hot encoding (bit0 = S, bit1 = S1, ..., bit9 = Wait), next-state equations are derived by inspection:

- S_next is asserted when next state is S (bit0): 
  From states:
  - S on d=0 stays S
  - S1 on d=0 goes to S
  - S110 on d=0 goes to S
  - Wait on ack=1 goes to S

- S1_next (bit1) next state when:
  - S on d=1 goes to S1

- S11_next (bit2) next state when:
  - S1 on d=1 goes to S11

- S110_next (bit3) next state when:
  - S11 on d=0 goes to S110

- B0_next (bit4):
  - S110 on d=1 goes to B0

- B1_next (bit5):
  - B0 always goes to B1

- B2_next (bit6):
  - B1 always goes to B2

- B3_next (bit7):
  - B2 always goes to B3

- Count_next (bit8):
  - B3 always goes to Count

- Wait_next (bit9):
  - Count on done_counting=1 goes to Wait

Outputs (Moore):

- shift_ena = 1 when state is B0, B1, B2, or B3 (bits 4-7)
- counting = 1 when state is Count (bit8)
- done = 1 when state is Wait (bit9)

Because the problem asks only for combinational logic, we produce next-state signals based on current state and inputs only. We take input state[9:0] and output next state one-hot signals and the outputs.

Note: The problem asks only for B3_next, S_next, S1_next, Count_next, Wait_next, and outputs done, counting, shift_ena.

We implement combinational logic for next states by ORing all conditions that lead to that next state.

For "always go to next cycle" transitions (B0->B1, B1->B2, B2->B3, B3->Count), these occur unconditionally if current state is B0, B1, B2, or B3.

We do not implement state registers or sequential logic here, only combinational next-state and output signals.
