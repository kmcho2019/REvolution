Implement a three-state FSM with states A, B, and C, representing no grant, grant to device 0, and grant to device 1, respectively. Although the description mentions device 2 and a state D, the state diagram's transitions do not clearly define a separate state D; device 2's grant is implied to be state D when r2=1 and r0=0, r1=0.

But since the problem states the FSM has states A, B, C, and D, and the transitions mention moving to D from A when only r2=1, we will implement four states: A, B, C, D.

- State A: no grants, waiting for requests.
- State B: grant to device 0 (g[0]=1).
- State C: grant to device 1 (g[1]=1).
- State D: grant to device 2 (g[2]=1).

On reset, go to state A.

The priority is device 0 > device 1 > device 2.

From state A:
- If r0=1, go to B.
- Else if r1=1, go to C.
- Else if r2=1, go to D.
- Else remain in A.

From state B:
- If r0=1, stay in B.
- Else go to A.

From state C:
- If r1=1, stay in C.
- Else go to A.

From state D:
- If r2=1, stay in D.
- Else go to A.

Assign output g based on the current state.

Use synchronous active-low reset, positive edge clock.

Use separate always blocks for state register and next state combinational logic.

Outputs g assigned with continuous assignment or always block.

Assign state encoding with localparams.

Use a 2-bit or 3-bit reg for state encoding.
