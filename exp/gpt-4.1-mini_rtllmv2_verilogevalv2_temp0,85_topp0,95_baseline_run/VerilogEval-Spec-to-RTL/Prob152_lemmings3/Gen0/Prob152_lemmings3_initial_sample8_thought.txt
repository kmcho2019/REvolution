We model the Lemming behavior as a Moore FSM with four states:
- WALK_LEFT: walking left on ground
- WALK_RIGHT: walking right on ground
- FALLING: falling (aaah!)
- DIGGING: digging while walking on ground

On reset, the state is WALK_LEFT.

Transitions:
1. FALLING state has highest priority: If ground=0 at any time (except already falling), go to FALLING.
2. From FALLING, when ground=1, go back to last walking direction state (WALK_LEFT or WALK_RIGHT).
3. DIGGING has second priority: If dig=1 and ground=1 and not falling, go to DIGGING.
4. From DIGGING, if ground=0, transition to FALLING.
5. WALK_LEFT and WALK_RIGHT states:
   - If bumped left or right, switch walking direction.
   - If dig=1 and ground=1, start DIGGING.
   - If ground=0, start FALLING (already highest priority).

No bump effect while falling or digging.

Outputs depend only on current state:
- WALK_LEFT: walk_left=1, walk_right=0, aaah=0, digging=0
- WALK_RIGHT: walk_left=0, walk_right=1, aaah=0, digging=0
- FALLING: aaah=1, all others 0
- DIGGING: digging=1, walk_left or walk_right as per walking direction

We store the current walking direction state (left or right) so we can resume walking after falling.

The async reset areset sets state to WALK_LEFT.
