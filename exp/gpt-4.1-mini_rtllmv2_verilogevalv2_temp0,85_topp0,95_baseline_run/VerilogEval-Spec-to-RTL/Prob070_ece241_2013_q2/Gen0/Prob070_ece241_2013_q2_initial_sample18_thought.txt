First, encode the inputs (a,b,c,d) as a 4-bit number where a is the MSB and d the LSB.
The numbers that produce logic-1 output are 2, 7, and 15.
The numbers that produce logic-0 output are 0, 1, 4, 5, 6, 9, 10, 13, 14.
Numbers 3, 8, 11, and 12 never occur, so they can be considered as don't care for minimization.

We will write the truth table for out_sop and derive the minimal sum-of-products expression using Karnaugh map or Boolean algebra, then do the same for out_pos (minimal product-of-sums).

Using Karnaugh maps or Boolean algebra with don't cares, we find minimal expressions.

Minimal SOP for out (out_sop):

1) The minterms for output 1 are for decimal 2, 7, 15.
- 2 = 0010 (a=0,b=0,c=1,d=0)
- 7 = 0111 (a=0,b=1,c=1,d=1)
- 15=1111 (a=1,b=1,c=1,d=1)

Including don't cares for 3,8,11,12 allows grouping:

Group 1: Covers 7 (0111) and 15 (1111) along with don't care 11(1011) and 3(0011) in c=1,d=1 column:
- This simplifies to c d

Group 2: Covers 2 (0010) and 10 (1010) don't care 10(1010) is 0, so no, we cannot use 10 as don't care here because it is 0 output, so we only have 2 as 1 without adjacent don't cares on d=0,c=1,b=0.

So minimal SOP is:

out_sop = c d + (not a) (not b) c (not d)

Minimal POS for out (out_pos):

By similar reasoning and using the list of zeros and don't cares to get the minimal POS expression.

out_pos = (a + b + d)(a + c + d)(b + c + d)

We can verify and implement these expressions.

Therefore:

out_sop = (c & d) | (~a & ~b & c & ~d)

out_pos = (a | b | d) & (a | c | d) & (b | c | d)
