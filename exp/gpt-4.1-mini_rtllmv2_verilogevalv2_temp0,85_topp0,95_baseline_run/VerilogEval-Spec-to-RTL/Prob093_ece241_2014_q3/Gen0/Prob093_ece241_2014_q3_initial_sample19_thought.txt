The 4-to-1 MUX uses {a,b} as selector, so each mux_in bit corresponds to a different ab combination:
mux_in[0] for ab=00
mux_in[1] for ab=01
mux_in[2] for ab=11
mux_in[3] for ab=10

We must generate mux_in[3:0] as functions of inputs c and d only.

Given the K-map (cd as rows, ab as cols):

        ab
    cd  00  01  11  10
    00 | 0 | 0 | 0 | 1 |
    01 | 1 | 0 | 0 | 0 |
    11 | 1 | 0 | 1 | 1 |
    10 | 1 | 0 | 0 | 1 |

For each ab value, mux_in[ab] is a function of cd:

- ab=00 (mux_in[0]): outputs at cd=00(0), 01(1), 11(1), 10(1)
    So mux_in[0] = 0 1 1 1 for cd=00,01,11,10
- ab=01 (mux_in[1]): outputs: 0 0 0 0
- ab=11 (mux_in[2]): outputs: 0 0 1 0
- ab=10 (mux_in[3]): outputs: 1 0 1 1

We implement each mux_in bit with 2-to-1 muxes only, using c and d as inputs.

We can use the expression of each mux_in bit as c and d select lines with 2-to-1 muxes:
We can implement any function of two variables using a 2-level 2-to-1 MUX tree.

For example, implement mux_in[0]:
cd=00=0, 01=1, 11=1, 10=1
First level select on c:
if c=0 (cd=00 or 01): outputs = 0 and 1
if c=1 (cd=10 or 11): outputs = 1 and 1
So mux_in[0] = MUX c (output if c=1, output if c=0) = MUX c (1, MUX d(1,0))

Similarly for others.

We'll define helper 2-to-1 MUX modules to build mux_in[3:0].

No other logic gates allowed.

Finally, output mux_in[3:0].
