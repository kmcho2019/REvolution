pedge <= transition_detected;

Both assignments occur in the same clocked `always @(posedge clk)` block. The key issue lies in the ordering and timing of these non-blocking assignments. Because all the assignments inside the block update simultaneously at the clock edge, `transition_detected` is assigned the value computed from the old `prev_in` and current `in`, but `pedge` is assigned the current value of `transition_detected`, which has not yet updated and still holds the previous cycle's value.
