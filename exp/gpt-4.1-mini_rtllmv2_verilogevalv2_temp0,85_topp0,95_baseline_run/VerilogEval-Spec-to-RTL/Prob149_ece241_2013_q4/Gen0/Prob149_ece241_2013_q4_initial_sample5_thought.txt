The module monitors the three sensor inputs s[2:0] indicating water level. Based on the current sensor pattern, the module sets nominal flow valve outputs fr0, fr1, fr2 according to the table:

- All sensors asserted (s=3'b111): Above s[2], no flow outputs (all zero).
- s=3'b110 (s[0], s[1] asserted, s[2] not): between s[2] and s[1], fr0 asserted.
- s=3'b100 (only s[0]): between s[1] and s[0], fr0 and fr1 asserted.
- s=3'b000 (none asserted): below s[0], fr0, fr1, fr2 all asserted.

Other cases (e.g., s=3'b010, 3'b001, etc.) are not explicitly defined; we treat those as above the highest sensor (all sensors asserted) with no outputs asserted.

The previous water level state (previous sensor pattern) is stored. If the level has risen compared to the last sensor change (the new sensor reading is "higher" than previous), then dfr (supplemental flow valve) is asserted.

"Level rising" means the water level goes up to a sensor pattern with more bits asserted or a higher sensor index asserted. To implement this, I will use a numeric encoding of the sensor level: the number of sensors asserted from highest to lowest. Since the sensors are placed vertically with s[2] highest, s[0] lowest, we can convert the sensor reading to a numeric level:

- 3'b111 => level 3 (above highest)
- 3'b110 => level 2
- 3'b100 => level 1
- 3'b000 => level 0 (below lowest)

Any other pattern will be treated as level 3 (above highest).

On reset, the state is as if water level had been low for a long time, meaning all outputs asserted: fr0=fr1=fr2=dfr=1, and previous level = 0.

On each clock cycle, update outputs and previous level accordingly.

The module is synchronous with active-high reset.
