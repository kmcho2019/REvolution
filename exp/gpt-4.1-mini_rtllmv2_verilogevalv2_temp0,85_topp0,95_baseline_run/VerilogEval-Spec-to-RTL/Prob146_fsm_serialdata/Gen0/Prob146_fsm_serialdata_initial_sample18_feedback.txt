However, the problem specifies that the protocol sends the least significant bit first. Therefore, the shift register is not reconstructing the byte in the correct bit order, causing the output data to be incorrect. This is consistent with the large number of 'out_byte' mismatches in simulation.

   The done signal is asserted in the STOP state's sequential block only if the stop bit is valid (`if (in == 1'b1)`). However, done is set to 0 at the start of the clock cycle, and 'out_byte' is updated in the same clock cycle. The done pulse and valid data may not align correctly or be visible to downstream logic as expected. This can cause the simulation to observe mismatches in 'done' timing or data validity.

   The data bit counter increments each clock while in DATA. The next state transitions to STOP when `bit_cnt == 7`. However, since the counter increments after sampling the bit in the current cycle, the count and timing of state transitions might cause off-by-one errors in data capture or premature transition to STOP. This can cause partial or incorrect data reception.

4. **WAIT_STOP State Logic:**  
   The FSM waits in WAIT_STOP until a valid stop bit (1) is seen to resynchronize. This is correct according to specification, but the simulation mismatches on 'done' suggest that the FSM may not assert done properly after recovering from this state.
