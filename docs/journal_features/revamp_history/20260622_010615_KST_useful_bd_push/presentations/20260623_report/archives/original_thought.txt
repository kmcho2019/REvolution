  # RTLLM QD Milestone Presentation And Run Plan

  ## Summary

  Create docs/journal_features/revamp_history/20260622_010615_KST_useful_bd_push/presentations/20260623_report/ as the milestone
  package that answers:

  1. Does diversity matter for RTL/Verilog PPA evolution?
  2. Which diversity actually matters?

  The package will combine prior evidence with a new matched RTLLM experiment comparing classic REvolution against the best QD/MAP-
  Elites method selected by a small pre-screen. Use the selected defaults: Markdown deck, matched 1-seed 12x3 budget, and “screen then
  choose” before the full RTLLM launch.

  - Add a presentation/report directory with:
      - README.md: navigation and artifact index.

      - experiment_plan.md: pre-registered RTLLM protocol.
      - adversarial_validation.md: review rubric and recorded feedback.
      - tables/, figures/, data/, commands/, reviews/.

  - Update the current useful-BD goal docs to make this a priority milestone:

        the RTLLM comparison supports the claim.

  ## Experiment Plan

  - Freeze the RTLLM suite from benchmark files, not scripts/RTLLM.csv, because the CSV omits Prob006_adder_pipe_64bit and
    Prob013_multi_booth_8bit; the run manifest must list all 50 problems explicitly.

  - Preflight http://20.0.0.103:8000/v1/models and require openai/gpt-oss-120b with max_model_len >= 128000.
  - Run a small screening ladder before the expensive full RTLLM run:
      - baseline: exact T26 settings.
      - T26.1: T26 with qd_two_parent_probability=0.10.
      - T26.1-gated: T26 with low two-parent fusion gated by valid, near-front, descriptor-compatible parents.

  - Keep screening matched to classic on the existing hard RTLLM screen plus a small stress slice:
      - Prob045_alu, Prob041_traffic_light, Prob015_multi_pipe_8bit.
      - Add Prob006_adder_pipe_64bit, Prob013_multi_booth_8bit, Prob043_RAM if smoke cost is acceptable.

  - Choose the full-run QD arm before seeing full RTLLM results using:
      - preserves every classic-covered design;
      - no catastrophic validity drop where classic has at least 10 passing samples;
      - best paired HV/HV-AUC and front-family evidence on the screen;
      - no duplicate-collapse or invalid-diversity claim.

  - Full run:
      - classic arm: classic_revolution, eoh_strategies.
      - QD arm: selected T26-family variant.
      - benchmark: RTLLM 50-problem manifest.
      - seed: 1001.
      - budget: population_size=12, num_generations=3.
      - tokens: max_tokens=128000, diff_max_tokens=128000.
      - workers: start with total_worker_slots=48, max_active_problems=12, max_workers_per_problem=4.
      - record all commands under presentations/20260623_report/commands/.

  ## T26.1 Implementation

  - Keep exact T26 behavior as the control.
  - For simple T26.1, no code change is needed if only qd_two_parent_probability=0.10 changes.
  - For gated T26.1, add one narrow QD parent-selection option:
      - new CLI/config field: --qd_two_parent_gate.
      - allowed values: none, near_front_descriptor.
      - default: none.
      - near_front_descriptor only permits two-parent fusion when both parents are valid archive members, both are rank-1 or near-front
        under existing NSGA-II rank, and descriptor distance is below a fixed pre-registered threshold.

  - Do not add broad fallbacks or optional loose behavior. If the gate cannot find a valid pair, use the existing one-parent fallback
    and count it in the summary.

  - Extend summaries to report:
      - success-parent requests;
      - two-parent attempts;
      - gated accept count;
      - gated reject count;
      - fallback count;
      - PPA/front contribution from two-parent descendants.
