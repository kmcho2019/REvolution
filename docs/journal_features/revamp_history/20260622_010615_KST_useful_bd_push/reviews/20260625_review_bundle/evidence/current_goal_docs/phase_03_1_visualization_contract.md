# Phase 03.1 Visualization Contract

This contract applies to every new live QD technique in this push. The
reader-facing direct PPA view and the full linked archive/PPA viewer answer
different questions, so a completed live QD package needs both.

## Required Layout

Live QD techniques with archive artifacts must include:

```text
visualizations/qd_ppa_viewer/
  index.html
  manifest.json
  datasets/*.json
  validation.json
  screenshot.png
  README.md

visualizations/direct_ppa_pareto/
  index.html
  metrics.json
  screenshot.png
  README.md
```

`visualizations/qd_ppa_viewer/` is the Phase 03.1 viewer. It is generated by
`scripts/export_qd_ppa_visualization.py` and uses
`src/revolution/qd/ppa_visualization_export.py` plus
`src/revolution/qd/ppa_visualization_viewer.py`. It must expose timeline,
compare mode, archive projection, raw/improvement/normalized coordinates,
native and raw area-power PPA panes, 2D/3D-style rendering, validation schema,
and debug hooks.

`visualizations/direct_ppa_pareto/` is a paper-readable raw area-power
supplement. It is useful for direct front inspection, but it is not a
substitute for the Phase 03.1 viewer.

Replay-only or archive-missing techniques may omit `qd_ppa_viewer/` only when
`results_report.md` and `artifacts_manifest.md` state the reason.

## Required Inputs

Every full viewer export needs:

- `final_analysis/ppa_distribution/data/ppa_candidates.csv`;
- `final_analysis/ppa_distribution/data/reference_ppa_metrics.csv`;
- `final_analysis/design_space_analysis/successful_candidates.csv` when
  classic candidates need descriptor recovery;
- the classic backend run directory;
- the QD backend run directory;
- QD archive artifacts such as `archive_space.json`, `archive_cells.csv`, and
  preferably `archive_history.jsonl`;
- descriptor values, or enough source data to recover descriptor values and
  project classic candidates into the QD archive posthoc.

Keep generated run artifacts under `exp/useful_bd_push/`. Do not place new
experiment outputs under `/aux`; `/aux` is read-only prior-run context.

## Standard Export

Alias the baseline as `classic` so compare mode and validation stay
consistent:

```bash
uv run python scripts/export_qd_ppa_visualization.py \
  --run-root docs/.../techniques/T##_slug/visualizations/qd_ppa_viewer_source \
  --backend_run classic=exp/.../classic_revolution/seed_1001 \
  --backend_run METHOD=exp/.../METHOD/seed_1001 \
  --archive_source_backend METHOD \
  --subset-config docs/.../techniques/T##_slug/tables/live_screen_v0_subset.yaml \
  --output-dir docs/.../techniques/T##_slug/visualizations/qd_ppa_viewer \
  --strict
```

Then validate:

```bash
uv run python scripts/validate_qd_ppa_visualization.py \
  --viewer-root docs/.../techniques/T##_slug/visualizations/qd_ppa_viewer \
  --subset-config docs/.../techniques/T##_slug/tables/live_screen_v0_subset.yaml \
  --strict \
  --playwright
```

The validator checks the full control surface, including compare mode,
timeline, coordinate modes, archive perspective controls, raw area-power front
mode, and debug hooks. Keep `validation.json`, inspect the Playwright
screenshots, and copy one compact inspected screenshot to
`visualizations/qd_ppa_viewer/screenshot.png`.

## Report Checklist

Every completed `results_report.md` must state:

- whether the full Phase 03.1 viewer exists;
- the exact `visualizations/qd_ppa_viewer/` path;
- whether classic candidates were honestly projected into QD archive cells;
- why projection failed, if it failed;
- the exact `visualizations/direct_ppa_pareto/` path;
- where the raw point table and direct PPA-front PNG live;
- what the screenshots showed during visual inspection.

Do not call a technique complete when only `direct_ppa_pareto/index.html`
exists. That file is a supplement, not the linked archive/PPA viewer.
