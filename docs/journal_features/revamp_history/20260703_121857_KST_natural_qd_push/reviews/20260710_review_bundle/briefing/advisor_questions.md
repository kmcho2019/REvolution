# Advisor Questions

## Direction

1. Is the current QD evidence strong enough for a TCAD characterization paper,
   or should submission wait for a positive primary method result?
2. Does descriptor-free Pareto REvolution have enough methodological novelty
   when the algorithmic primitive is standard NSGA-II?
3. Is reference-seeded optimization a natural journal extension of the
   conference generation framework, or should it be a separate paper?
4. Should QD remain a central analysis section, a supporting ablation, or an
   appendix after a pivot?

## Method

1. Should Pareto rank and crowding replace both Success-pool survivor selection
   and parent selection, or only survivor selection?
2. Should the external Pareto archive affect search, or remain a reporting-only
   deliverable to preserve attribution?
3. Is the Fail population best left exactly as in classic REvolution for the
   first experiment?
4. Is removing C-F a meaningful simplification, or only a configuration
   observation because the final-HV confidence interval crosses zero?
5. Is a UCB-versus-fixed operator-policy ablation necessary for the journal?

## Validation

1. What minimum improvement over classic would be compelling for TCAD: mean
   final-HV equality, the existing +5% log-ratio gate, or another
   preregistered effect threshold?
2. Must any new positive method run the untouched held-out reference set before
   manuscript drafting resumes?
3. What is the right baseline for seeded optimization: scalar REvolution,
   iterative single-lineage refinement, or both?
4. What fraction of large-design improvements must be formally equivalent for
   a credible claim?
5. Which 6-10 e203 modules provide enough scale and timing diversity without
   creating a capability-only experiment?

## Reviewer Resistance

1. How should the paper answer "NSGA-II is textbook" without overstating
   algorithmic novelty?
2. Does reporting the full failed QD portfolio adequately answer the
   survivor-selection or multiple-comparisons objection?
3. Can synthesis-stage PPA proxies support a large-design TCAD claim, or does
   the seeded track require a deeper physical-design stage?
4. Does the RealBench two-state and no-gate-level-resimulation policy require
   a stronger verification gate before any PPA result is publishable?
5. Which current claim should be dropped first if manuscript space or compute
   is limited?
